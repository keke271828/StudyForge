# 讲解质量与效率验收

这是逐项改进的第七项，源码已更新并自检，未重新打包。本项改进重复读取、长文组织和可核查的来源记录；没有把模型自检或引句匹配包装成事实正确性保证。

## 打开与验收

退出旧窗口，双击项目根目录 **验收最新版.vbs**，确认窗口标题带“源码验收版”。原有本机资料和设置保留；进入学习对话选择资料，继续使用当前导师及你的解析要求。

1. 先用一份有明确标题、概念和限制条件的资料生成讲解，不勾选同步出题。成果仍只导出所选格式，末尾保留系统性总结，不另生成审查或 Markdown 成果。
2. 到成果卡片展开 **来源定位核对**：查看匹配的位置、原文引句、解析复用数和核对范围。定位与引句不匹配时显示“待核对”，文档正文在最终总结前也会注明。没有警告不代表讲解已经正确。
3. 在软件仍运行时，用同一原文件再生成不同概括性档位或提出新要求。符合缓存条件时显示解析复用；完整原文仍交给模型，不改为读取资料库的预览或旧讲解。重复生成仍有正常的模型用量。
4. 用长资料检查章节衔接：前后概念、方法动机、推导条件及最后一部分是否解释到位，是否避免每章重复全文导言。只有一个最终系统性总结，各部分保留自己的小结。
5. 修改原文件后再生成，确认不沿用旧解析。原文件或抽取画面在生成期间发生变更时，本次不发布旧版本讲解，需重新通读并生成。
6. 用哲学、社会科学等资料确认讲解仍从原学科语境出发，不强行类比物理；检查人物归属、论证前提和不同观点。数学与科学资料另检查等式、单位、边界条件及方法选择理由。
7. 多个章节的总结输入过长时，只节选用于总结的辅助输入，不删减已经生成的讲解正文。成果卡片和总结开头注明范围；极多章节会注明未列入此次总结输入的部分。此时应人工检查总结，不能把它视为完整的细节覆盖证明。

已有通读、知识结构、问卷、同一导师和暂停恢复继续使用原流程；这项核对不修改画像分数，也不自动出题。需要短时间了解材料时可选择“概览”及“极速 · 生成时自检”；这会减少原有审查请求，不能证明内容因此更可靠。

## 改进内容和边界

### 完整解析复用

- 原文件内容以 SHA-256 核对，缓存保存完整解析而非概括文本；副本隔离，AI 画面说明不会改写原文索引。即使大小和修改时间相同，内容变更也会使缓存失效。
- 本次增加的是内存缓存：最多8份文件、合计200万文本字符。超限、退出后或被淘汰时重新解析；每次仍需读取文件计算指纹，并非所有磁盘读取都省掉。
- 抽取图片缺失或内容变更时重新解析；同一文件的并发解析合并为一次。原文件已删除时，不能从缓存继续冒充原文件读取。
- 成功的画面理解按图片内容、资料位置、服务、模型、推理参数和视觉模型配置复用，最多64条，每条不超过32000字符。失败不作为成功缓存，后续可重试。这减少重复视觉请求，不保证模型画面解释正确。
- 视频与音频仍使用导入时取得的完整字幕／转录和抽取画面，不等于重新观看每一帧。新的内容指纹能识别转录和画面变更；早期只有原文件指纹的通读记录兼容保留。重新抽取和复杂媒体完整性另属后续审计。

### 长文组织与效率

- 各部分收到本部分全部原文，以及确定性的全文标题／开头导航、上一部分原文末尾和有限的已写章节线索。导航和旧讲解都注明只是辅助，不能替代原文证据；知识结构仍独立传给导师。
- 导航、阅读笔记和已写内容限制长度，避免每章反复发送全部辅助笔记。导航不全列时明示未列项数；当前各部分的原文输入不因这些限制而减少。
- 总结辅助输入上限为48000字符。超限明确节选，保留各部分首尾线索；章节数量极大时均匀选取并保留首末部分，明示遗漏数。输入限制不保证所有模型的上下文容量都足够。
- 不增加规划或来源核对的模型请求。通常完整的单篇讲解仍一次生成；长文仍各部分生成后再请求一次全文总结。原有审查、资料通读、图片理解、代码输出和同步习题的用量另算，不能将“额外请求为0”理解成整次任务免费。
- 已验证解析复用和请求数量，没有用真实服务测得生成速度提升比例。模型推理、服务排队、网络、导出及资料长度仍影响耗时；缓存不会让长资料瞬间生成。

### 来源核对

只机械核对 `[来源名｜位置]` 格式的定位及 Markdown 引用块。忽略空白差异；显式 `[…]` 或 `[...]` 按原文顺序匹配，代码围栏不当作引用。无法唯一定位的同名资料会提示，不能随意匹配其中一个。

这不是事实、推导或覆盖评估：准确引用可能仍被错误解释，模型也可能漏讲整段内容。标点、公式转写和格式差异可能提示人工核对；其他引用格式也可能尚未识别。文档显示前10项，卡片展开显示保存的前50项，超出时明确说明尚未逐一列出的数量。AI 补充背景应保留实际外部来源，不能伪装成所选原文。

画面分析只用于辅助模型理解，不能凭 AI 自己的解释证明引句来自原文。来源检查出现问题时不会再自动烧一轮模型用量，而是在所选成果内和成果卡片展示；疑点仍需核查，不静默删除真实原文或编造定位。

## 多学科人工验收

增加 `scripts/lesson_quality_eval.py`，包含哲学、社会科学、数学、物理、化学、生物六份自编短材料，隔离数据目录，默认不联网、不调用模型，也不使用真实保存的密钥。离线输出明确注明是原文复现的流程样例。

报告提供以下人工验收项，不由脚本假装自动通过：

| 项目 | 人工检查内容 |
| --- | --- |
| 覆盖 | 是否遗漏主旨、论证环节、重要细节和限制；逐条对照原文 |
| 方法动机 | 是否讲清为何选择方法、怎样想到构造，而非只复述计算 |
| 条件与错误 | 等式、单位、适用条件、历史归属和不确定处是否准确 |
| 合适迁移 | 关联是否有依据，是否说明差异，是否把类比当成证明 |
| 可读性 | 术语首次解释、章节衔接、读者能力匹配和最终总结是否清楚 |

本次六学科各两次，共12次离线流程完成，第二次均复用完整解析，原文引句匹配。报告的语义验收和人工质量评分仍为空，**不能将12次流程成功当作12篇真实模型讲解通过质量验收**。短材料也不代表真实教材、视频、扫描文档或大型跨资料任务的覆盖。

需要实际模型验收时，可显式加 `--live --provider … --model …`，会产生正常用量；DeepSeek 要求进程环境 `DEEPSEEK_API_KEY`，不复制用户保存的设置。`--repeat` 在真实模式下会再生成一次，也增加费用。本次没有运行真实模式。后续应使用你的多学科材料人工填写验收项，而非再用模型自评一遍就宣布合格。
