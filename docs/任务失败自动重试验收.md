# 任务失败自动重试验收

日期：2026-10-11。源码更新，未打包。

## 如何使用

双击根目录 `验收最新版.vbs` 打开当前源码。到「设置与联动 → 生成偏好 → 任务调度」，可选择「任务失败自动重试」和次数。默认开启、失败后重试 5 次，可调 5–20 次；次数不包括首次执行。默认最多执行 6 轮，成功后立即停止。保存的设置影响新任务，已有任务保留其重试额度。

讲解、配套习题、只出题、批改、编程作业、费曼/修复/进阶任务、通读、知识结构、资料解析、另存格式，以及书库阅读/目录/范围任务均接入任务重试管理。实时聊天流与低 token 后台画像整理保留原有恢复/调用额度，不重新发送学生消息或给后台画像另加五倍调用。

任务卡显示重试次数、等待时间、是否已耗尽及停止原因；电脑与手机共用记录。网络恢复后沿用原任务 ID，不创建一排重复任务。

## 如何处理失败

| 情况 | 行为 |
| --- | --- |
| 网络连接中断、超时、HTTP 408/425/429/5xx、模型空回复、不完整 JSON | 自动重试，成功即停 |
| HTTP 400/401/402/403/404/422、密钥/余额问题、网页访问限制 | 停止，显示需要处理的原因 |
| 原文件缺失或已变更、权限未授予、确定的习题实质错误、修订后仍为空泛的补讲 | 停止，不以重试绕过输入和教学质量要求 |
| 等待审批、填写错因问卷、阅读时段或预算 | 继续等待条件，不当作失败、不消耗重试次数 |
| 未完成的 Agent 步骤可能已经修改、删除或生成用户文件 | 停止自动重放，避免重复操作；已成功并保存的步骤可复用 |

默认等待约 3、6、12、24、48 秒；服务返回 Retry-After 时按其建议适当延长。等待不占模型/本地处理名额，其他独立任务仍能推进。

这里的次数是任务重试轮次，不是 HTTP 请求总数；一个任务可以包含多个章节、格式修复及模型请求内部的恢复。部分兼容服务将明确的额度耗尽也返回为 429，此时按账户问题停止，不误当作暂时限流。

暂停会阻止后续重试；取消或删除任务会终止等待。完整退出后，普通生成任务保留已完成步骤和重试计数，重开后可继续；书库等待任务由原有阅读调度恢复，手动暂停仍保持暂停。只有明确点击失败书库任务的重试或作业的重新批改，才开始一轮新的重试额度；普通暂停、继续不会清零计数。

## 避免重复与无效缓存

只保留有效的模型回复。无效 JSON、空书库笔记及未满足结构要求的回复，不留作下一轮必用的答案。成功章节、题单、已提交评分和已交付成果保留。已交付讲解之后题单临时失败，重试不会重复发布讲解；习题答案继续私有保存，完整提交前不公开。

本功能恢复临时故障，不降低审查强度或更改原任务的教学要求。重复的确定性程序错误需要修复代码，重复请求不能替代修复。
