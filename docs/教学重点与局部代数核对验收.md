# 教学重点、局部代数核对与定位补讲验收

日期：2026-10-13。用户要求把学习效果放在首位，本轮以实际回答中的缺陷为依据改进。源码已更新；本轮没有重新打包，安装版 0.4.2 不会自动获得这些改动。内置指南同步更新，手机壳缓存版本为 v36。

## 改了什么，为什么

### 1. 精学回到当前问题，不默认套数学证明结构

旧精学路径强调“目标—构造—推导”，在数学证明上有用途，但会把简单社会科学概念问题推向不必要的自建数学模型。真实同题实验出现了这个现象，新增模型还引入了原问题没有的错误。

现在按任务区分重点：

- 概念问题先用完整例子、对照和原概念解释当前疑问。
- 证明、解题或实现任务再详细讲构造动机、每步依据及条件。
- 经验研究解释证据与替代解释；哲学论证解释前提、推理及反对意见。
- 明确要求的模型、深入推导和相关延伸仍可展开；新增模型说明用途、前提、被省去的项和退化情况，不能把相近条件当成同一条件。

导师对话、讲解生成、修订以及批改后的补讲共享这些教学原则。概览、精学、研究的任务重点仍各不相同。没有提高全部模式的字数下限，也没有用一套固定章节模板覆盖所有学科。

实际规则版本为 `2026-10-13-teaching-focus-and-model-conditions`，可查看 [实际导出的导师规则](AI导师提示词.md)、[共同政策](../studyforge/teaching_policy.py)、[学习模式](../studyforge/learning_modes.py)。

### 2. 加入不增加模型轮次的有限算术核对

真实数学样例的主证明基本正确，但新增区间右端点写成了：

$$b+\frac{b-a}{2}=\frac{a+3b}{2}.$$

正确展开应是：

$$b+\frac{b-a}{2}=\frac{3b-a}{2}.$$

取 $a=2,b=5$，原式左边是 $13/2$，错误右边是 $17/2$。同一模型的快速审查曾两次返回 `passed=true, issues=[]`；主证明正确并不使额外例子自动正确。

程序现在用封闭的有理数与线性表达式解析器检查部分等式链和显式区间端点改写。不执行表达式代码、不调用符号软件、不新开 AI 审查。候选差异连同代入值进入现有审查请求；模型仍要检查正文条件。确定的小错误沿用精确定位的局部替换；未解决的候选差异在最终正文总结前保留可见提示。

实现：[局部算术提示](../studyforge/algebra_hints.py)、[现有审查流程](../studyforge/review.py)、[末尾总结检查](../studyforge/teaching.py)。

**边界明确：**当前只覆盖有限线性算术语法，跳过原文引用块、代码、不支持的非线性表达式及单个标量定义。只有部分可以计算的改写得到检查；没有提示不代表公式正确。代入差异可能依赖正文附加条件，不能直接判定整题或学生答案错误。此项用于讲解与总结，不是对所有聊天答案、批改公式或数学证明的通用验证器。

### 3. 问卷可以直接选择“卡在哪一节”

电脑和手机的理解问卷新增可选的章节选择。标题从这份已交付讲解中提取，不请求模型，不重传文件或解析资料。父章节包含自己的小节，重名小节按父标题及内容版本区分；显示前 300 个标题，超出部分明确说明，可改用自己的选段补充。

选择后保存提交时的片段与内容哈希。超过 7000 字符的章节明确标成开头节选，不能假装已核对其余内容。标题选择仍不能证明学生在全节都存在同一种困难；补讲先定位具体问题，并核对 AI 旧讲解是否有错。

同时修复了三处实际使用问题：

- Codex 补讲旧问卷时对应原讲解，不再优先把最新生成的另一文档作为问卷目标。同对话公开历史仍保留供理解；跨对话历史不引入。
- 问卷打开时主动定位到阅读区中的问卷，避免布局恢复的旧滚动锚点把它跳回另一文档；实际视口检查及截图已确认。
- 电脑端新增“仅保存反馈”，不需要等待当前聊天结束就能先保存；需要补讲时再发起。电脑和手机的草稿、所选位置可以在设备内切换和刷新后恢复。

画像只保存六类自报困难及符合知识学习条件的补充，带着本讲解／章节范围；AI 片段不是学生原话，不进入理解证据，也不直接扣分或创建题单。提交相同内容可幂等恢复；过时、外部讲解或被篡改的位置 ID 会被拒绝，填写内容留在本机可修改。

“定义”“证明”“系统性总结”这类通用标题不单独成为知识标签，避免在别的学科讨论定义时误召回本节困难。具体知识标题与原讲解／资料范围继续可用于匹配。

旧数据库自动补充空定位字段，不清除旧问卷或反馈。删除对话后不可继续补讲，且不会把不可用任务留在“导师正在补讲”状态。

实现：[章节定位](../studyforge/lesson_focus.py)、[问卷与画像](../studyforge/lesson_feedback.py)、[电脑界面](../web/lesson_feedback.js)、[手机界面](../web/mobile/lesson-feedback.js)。

## 实际模型实验：有改善，也保留失败

使用 `deepseek-flash`、推理 `high`、精学、直观与专业并重，数学极限与相关／因果两题。资料为合成短材料，无私人聊天；对比各臂均关闭工具。这是原生 API 的提示词对照，本轮没有重新连接或比较官网网页。

共 **11 次讲解实验，7 次成功、4 次连接失败**。结果保留在 [离线盲评对照页](../build/learning-quality-20261013-final/学习讲解质量实际对照.html)，可切换原始回答和人工评阅、揭示试验臂；原始样例没有被改写成“全部通过”。

主要观察：

1. 简短指令在某些题上也能讲清；旧规则的数学回答也有好的部分。不能得出“提示词越长越好”或“旧版本全都差”。
2. 单独加入一般性提醒未解决概念问题过度形式化。修正精学路径后，社会科学样例改用热天／冷天的完整例子，未再引入错误的协方差模型；仍发现随机促销与实际消费的因果条件混淆。
3. 数学主要构造解释较完整，但附加区间算式有错误。快速模型审查曾漏检，本机核对器最初也漏掉了实际回答的 LaTeX 空格和句末标点；没有把简化测试通过当作原样验证。
4. 修复实际语法后，再用同一份原回答运行生产快速审查，模型识别并精确改正了右端点：只改该段公式，一次现有审查，没有重写全文或再开独立复核。本次约 **31.84 秒**。这是单个错误的修复证据，不是整体速度或教学质量的提升比例。

## 打开和验收

1. 从托盘彻底退出旧运行版，双击根目录 [验收最新版.vbs](../验收最新版.vbs)。源码入口保留原数据；本轮测试没有修改用户数据库或原文件。
2. 选择自己真正卡住的一小段材料，使用“精学 + 直观与专业并重 + 快速”生成。重点检查是否先解决当前问题、完整例子是否有作用、附加模型条件是否明确；不要用篇幅长短代替理解质量。
3. 生成后打开理解问卷，展开“卡在哪一节”，选出对应章节与六类困难，先点“仅保存反馈”；确认没有开始模型回复。再点“请导师补讲”，检查是否围绕该节与具体困难，是否先更正自己的误导。
4. 在同一对话先后生成两篇文章，再打开第一篇的问卷。补讲应对应第一篇，不拿后来文章替代；查看画像，所选困难应保留“自评（未验证）”与范围。
5. 手机刷新页面后进行同样操作；未提交草稿保存在各自设备，提交后通过电脑服务同步。内置“使用指南”已补充操作与核对提示说明。

下一项更有价值的验收是：对具体知识点用简短的解释／迁移任务和间隔后的独立作答，比较是否真正理解与保持。现有路线和理解检查可以承接这些证据；不能仅凭“文章看起来专业”认定学会，也不应自动给只想了解概览的人强加测验。
