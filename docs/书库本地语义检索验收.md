# 书库本地语义检索：使用与验收

2026-10-10。接续[书库检索与原文回查改进验收](书库检索与原文回查改进验收.md)。本轮增加可主动开启的本地语义检索，用来补充完全改写术语或换一种问法时的相关章节线索。当前交付是源码；0.4.1 安装包没有更新，正式学习数据库没有用于写入试验。

后续已完成聊天框 `@` 目录选择与引用标签，见 [聊天框书库引用验收](聊天框书库引用验收.md)。下文保留本地语义检索交付时的测试结果和待办状态。

## 一、直接打开和使用

1. 从 Windows 托盘完全退出旧版 StudyForge；关闭窗口会让旧程序继续运行。
2. 双击根目录的[验收最新版.vbs](../验收最新版.vbs)，无需保留 CMD 窗口。
3. 电脑进入“全局书库”，展开书架上的“智能检索”。默认是“仅关键词”；改为“关键词＋本地语义”才开启增强。
4. 这份源码的检索模型已下载并校验，可以直接开启。其他电脑或未来安装包缺少模型时，在电脑端点击“下载本地模型（约 136 MB）”。下载能取消、续传；只有长度与固定 SHA256 校验通过的文件才会投入使用。
5. 软件只对已经完成阅读、仍符合当前原文件版本和所选页内范围的页建立索引。未读书籍不会因为开启检索而自动解析，索引本身也不会重新 OCR、通读或调用云端生成模型。
6. 输入问题或术语，结果显示关键词、混合匹配或语义候选以及来源页。点击结果定位目录；需要引用时，由你选择节点，或沿用该对话的自动参考方式。
7. 手机使用电脑的同一模型、索引和开关，无需在手机下载模型。已打开的手机页面请刷新；本轮更新了网页缓存版本。

“检索方式（全局）”控制书库如何找候选；工作台每个对话的“自动找相关已读节点／只用手动引用／关闭书库引用”仍独立生效。手动模式先限定节点再排名，关闭引用不会因为另一个项目开启语义增强而重新添加书库正文。

## 二、数据、范围与原文回查

- 全局共享书籍和已经授权的阅读结果，索引不保存其他项目的聊天内容。
- 每批最多处理四个短片段，记录页码、原文或 AI 图像核对记录的类型、连续字符位置与文本哈希；只有完成页才参与语义检索。
- 相关片段会回查现有原页文本，保留省略边界、相邻条件、视觉核对记录和未解决疑点。图像核对记录明确标为 AI 记录，不能冒充原文。
- 原文件、节点范围或缓存文字改变时，旧索引不继续作为有效证据；删除书籍或阅读记录时清理相关索引。
- 未读节点仍只提供目录提示；将节点设为“重点讲解对象”时仍处理全部所选范围，不能用搜索摘录代替整章正文。

另修复了两个实际暴露的问题：长页尾部的语义命中会被换行调整挤出摘录，以及英文短词 `eat` 错误匹配 `repeatedly`。前者现在保留相关尾部片段，后者按英文单词边界判断，避免无关日常问题自动带入教材。

## 三、内存与调度

索引工作器在前台繁忙时不启动新的批次，后台阅读任务进行时也让位。全软件共享一个本地检索引擎，限制 CPU 推理线程和单批片段数，不为每个项目、对话复制模型。

默认关闭语义增强，保护日常使用的内存与响应速度。开启后按需加载；切回“仅关键词”会释放模型，正在执行的小批次结束后释放。空闲约 30 秒也会释放；持久化索引保留，之后可以继续处理或重新检索。

| 一个隔离 Python 进程的实测 | 内存 |
| --- | --- |
| 加载检索模型前 | 31.4 MB |
| 初始实现，保留两份分词器 | 732.5 MB |
| 最终实现，共用一份分词器 | 462.7 MB |
| 最终实现的测试峰值 | 482.2 MB |
| 关闭语义增强并释放后 | 79.2 MB |

同一实测流程中，加载状态的内存下降约 36.8%。这仍有明显的内存成本，不能因为权重只有约 136 MB 就称它低占用。以上包含该进程的原生模块、分词器和检索模型，不是整个 StudyForge 的峰值，也没有重新测量视频解析或成果生成的总体内存。

## 四、真实本地模型结果

### 五个受控检索样例

实际运行量化 ONNX 模型，没有模拟向量，也没有云端生成请求。

| 查询 | 目标节点 | 关键词排名 | 混合检索排名 |
| --- | --- | --- | --- |
| Where can I learn about one-to-one functions? | 映射的性质 | 未命中 | 2 |
| Testing myself from memory instead of going over the text again | 学习与记忆 | 未命中 | 1 |
| 两个现象一起出现就能说谁导致谁吗 | 社会科学方法 | 1 | 1 |
| 一个变化被系统的反向响应抵消是什么机制 | 开放系统的调节 | 1 | 1 |
| Why can a sequence not settle on two separate destinations? | 证明中的邻域 | 1 | 1 |

五次目标都进入前三，四次排第一。两条词面检索漏掉的改写被补回，但“one-to-one functions”的目标仍排第二，因此不能承诺同义数学术语总能排第一。两个无关问题“城市天气”和“昨天早餐吃了什么”没有触发自动书库正文引用；手动节点限制、未读排除和关闭后回到关键词也实际检查。

这是五段受控文字的检索检查，不能当成复杂证明、多本完整教材或教学正确率的测评。试验中较早的模型漏检结果保留，没有混入通过记录。

## 六、模型选择与能力边界

使用 [multilingual-e5-small 的量化 ONNX 导出](https://huggingface.co/Xenova/multilingual-e5-small)，固定修订 `761b726dd34fb83930e26aab4e9ac3899aa1fa78` 与文件哈希；按照[原模型说明](https://huggingface.co/intfloat/multilingual-e5-small)区分 `query:` 和 `passage:` 输入、进行掩码均值池化和向量归一化。

语义排名是候选发现能力，不能视为事实正确率。当前融合关键词与语义排名；自动引用采用较严格的启发式门槛，手动搜索保留更多候选，但该门槛没有经过大规模数理教材标定。不相关结果、公式 OCR 错误和跨章依赖仍可能出现，导师需要回查原文，用户应核对关键条件。
