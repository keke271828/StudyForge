# 大型书库查询与导师原文回查优化

2026-10-10，源码更新，未打包。先从 Windows 托盘彻底退出旧 StudyForge，再双击 [验收最新版.vbs](../验收最新版.vbs)。手机连接这个版本后刷新页面；0.4.1 安装包没有自动包含本轮代码。

## 发现的问题与改动

此前已减少流式排版、图片副本和重复轮询，见 [流畅度与内存优化验收](流畅度与内存优化验收.md)。这次继续检查大书库的实际查询路径，发现仍有不必要的读取：

1. 搜索、索引进度检查和每一小批语义索引，会先载入所有已完成版本的完整阅读笔记，然后才挑选当前有效版本。
2. 书架刷新会按每个节点单独打开数据库查询阅读记录；几十个章节、多次刷新会重复付出连接和查询开销。
3. 导师请求一个已读页或一小段文字时，会先读取整章全部页面、拼接整章字符串，再按页或字符截取。阅读笔记也一并载入，虽然这个工具并不使用笔记。

现在的执行方式：

- **先用元数据选有效版本。** 只比较节点范围、原书指纹、模型、推理配置与已完成状态；保留时间和 rowid 的原排序规则。失效范围、未确认范围、未完成记录不参与原文检索。
- **目录状态批量查询。** 每本书一次查询全部节点的有效阅读元数据，并增加可自动迁移的数据库索引。列表仍显示原来的阅读状态和疑点，不加载笔记正文。
- **完整笔记逐条评分。** 需要检索笔记时逐条读取并计算原来的相关分数，只保留分数。没有只检索开头、降低检索页数或改变混合排名规则。
- **显式笔记阅读只加载当前有效正文。** 历史版本仍保留；不会为了查看一份有效笔记先把其他大版本带入内存。
- **导师原文按页、分段读取。** 指定页只查询该已读页；整节点分页逐页处理，只保留所需的输出片段，保留真实的继续位置。读取转到有归属记录的本地线程，取消和项目删除继续使用原有任务跟踪。
- **完整节点生成仍读取所选范围的全部原文。** 没有用搜索片段替代用户明确要求讲解的完整节点，也没有改模型、图片质量、推理强度或增加模型请求。

上述变化不需要新开关，电脑、手机和导师的书库工具自动使用。

## 十本规模的本地查询对照

隔离数据库包含 10 本、每本 350 页的规模，500 个目录节点、1,500 份 12,000 字符左右的保存笔记和 3,500 份页面记录。每个节点具有两个历史/当前可校验版本和一个范围失效版本；每本最后一个节点的范围未确认，必须排除。有效阅读记录为 490 份。

**这是合成的已保存文本和目录负载，不是 AI 实际通读十本扫描教材。** 原文、笔记和目录来自自编夹具，没有使用用户的正式数据库或密钥。对照调用改造前保存的真实 Python 查询函数，不以人为延时模拟基线。

两个模式分别运行在独立 Python 进程。每项计时两次；额外使用 tracemalloc 测量查询期间 Python 分配峰值，计时结果不包含这次追踪的开销。基线与优化共用同一数据库及索引，局部语义模型关闭，不在测量中运行 OCR 或模型推理。

| 工作量 | 原实现平均耗时 | 优化后平均耗时 | 该样例减少 |
|---|---:|---:|---:|
| 连续查询十本书的目录状态 | 3.897 秒 | 0.167 秒 | 95.7% |
| 一次全库语义索引状态检查 | 0.562 秒 | 0.125 秒 | 77.8% |
| 五个全库关键词问题的查询合计 | 3.252 秒 | 1.218 秒 | 62.6% |

| 查询的 Python 分配峰值 | 原实现 | 优化后 |
|---|---:|---:|
| 索引状态检查 | 35.99 MiB | 0.96 MiB |
| 五个关键词查询 | 36.05 MiB | 1.33 MiB |

十本目录结果本身仍需要同样大小的列表，目录查询的分配峰值约 0.74–0.76 MiB，没有降低；它改善的是重复连接和查询耗时。整个隔离查询进程的 Windows 工作集峰值由 73.75 MiB 降到 34.30 MiB，**不等于整个 StudyForge 或加载语义模型后的内存**。

目录 JSON、索引状态 JSON 和所有查询结果 JSON 的 SHA-256 分别完全一致，包括排序、命中页和未读提示；这一点验证本样例的结果等价，不能证明任意教材的检索质量。

证据：[汇总](../build/library-scale-20261010-1/report.json)、[原实现](../build/library-scale-20261010-1/baseline.json)、[优化后](../build/library-scale-20261010-1/optimized.json)。复现脚本为 `scripts/benchmark_library_scale.py`；源码基线保存在同一隔离目录。

相关回归 **337 项通过，0 失败、0 错误**；电脑与手机 **39 组交互检查通过，控制台错误为 0**。补充内置指南内容后，两项指南路由回归也通过；原页图像核对另有一项专项通过。测试有一条既有 Starlette/httpx 弃用提示。

- [本轮相关回归](../build/pytest-library-query-memory-final-20261010-1/report.xml)：覆盖旧/新版本选择、同时间戳排序、完整笔记末尾命中、手动范围、改写后实时更新、删除后失效、元数据路径禁止笔记正文、完整原文生成，以及模型服务、审批、调度、暂停、项目隔离和手机接口。
- [桌面与手机交互](../build/library-query-memory-ui-20261010-2/ui-report.json)：真实 Electron、TLS 配对、关键词与真实本地语义索引、章节串行/并行、暂停/等待续接、跨项目引用隔离、DOCX 生成和实际下载。云端响应使用模拟传输，没有花费用户的模型额度。重复刷新检查测量持有响应期间的请求数与实际在途峰值，允许先前响应完成后的正常新周期刷新。
- [内置指南回归](../build/pytest-library-query-guide-20261010-1/report.xml)：指南页面和资源路由仍可打开，补充了已读内容复用与按页回查的方法。
- [原页图像核对专项](../build/pytest-library-image-recheck-20261010-1/report.xml)：请求第 2 页时，只向图像服务传该页的缓存和完整 OCR；图像缓存修改或缺失会停止核对，不调用模型冒充成功。图像服务采用记录输入的模拟客户端，不视为真实视觉理解评分。
- 导师分页逐字对照原来的整章字符串，覆盖中文、组合字符、Emoji、嵌入 NUL、空原文但有图像记录、跨页分隔、边界和末尾；下一段位置保持一致。指定页的检查确认其他页正文不进入处理回调。
- 人为延迟原文读取，验证事件循环继续响应；文件指纹、授权节点和未读限制继续检查。测试中无效的模型服务夹具已改为合法的内置服务标识，不冒充产品修复。

## 怎样验收

1. 使用已有书库，打开章节较多的书，观察目录切换和阅读状态刷新。
2. 在书架搜索正文或笔记末尾的独特术语；确认仍能命中，点击后定位原页。
3. 在学习对话引用一个已整理节点，要求导师回查该节点的具体 PDF 页，或分段读取长证明。核对它返回的页码、上下文和继续位置。
4. 同时进行另一项独立聊天或生成，检查本地回查时界面仍可操作。

这些改动主要降低数据库查询和原文回查的等待与内存。完整视频首次转录、十本扫描教材的长期理解准确率、真实云端生成总时间和整机多任务峰值仍须分别测量；不能用查询样例的提速比例替代它们。
