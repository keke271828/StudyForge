# 长文核查记录与总结衔接验收

日期：2026-10-14。本轮继续改善学习交付；**源码已更新，未重新打包。已发布的0.4.3安装包不包含本轮和此前“快速核查局部修订可靠性”改动。**

## 实际复现的问题

长讲解超出全文总结的辅助输入上限后，原程序会改用各部分的标题与小结。如果“待核实事项”位于小结之后，小结的提取范围会在该标题前结束，具体疑点没有进入总结，只剩目录中的标题。下一部分的衔接输入也有类似问题。

新增测试在旧程序上实际复现了“只保证n>N”的限定丢失。修复前20项新行为检查失败，不能把它说成20个相互独立的历史漏洞；其中一些检查是新记录字段和保护行为的验收。

## 已完成的改动

1. **全文总结保留核查记录。** 输入能完整放下时保留完整已写讲解，核查记录不重复。超限时，在原长度预算内单独保留能放下的整段核查记录，同时明确记录总段数、完整传入段数与省略段数。过长的记录注明省略，不把半个公式或半条疑点当完整记录。
2. **区分疑点与复核状态。** “待核实事项”、来源定位提示、有限代数提示属于待核对记录；“已局部修订，但未再次独立复核”单独作为核查状态，不自动当成已确认剩余错误。引文和代码内的同名标题不计入应用的核查记录。
3. **总结保留可见边界。** 正文仍有待核对记录时，在总结中保留对应阅读提示，即使模型未写，也不把总结当成疑点已获排除。复用已有总结不新增模型调用，重复整理不重复叠加同一提示；模型自写一个同名标签不能绕过这一保护。
4. **后续章节同样接收疑点。** 串行续写保留最近24部分中、1600字符预算内可完整放下的核查记录。原章节编号保留，更早部分和放不下的记录明确注明未列入，不声称已经读到。并行模式下需要等待前章的续接分支也保留相应记录；独立并行章节不假装知道其他尚未完成草稿。
5. **电脑和手机共用记录展示。** 成果“资料依据”显示全文总结实际使用的核查记录段数及省略。这里计的是记录段落，不是已确认错误数。旧成果没有这些记录时不使用当前资料补填。手机壳更新为v39，仍只缓存公开界面，不缓存学习数据。
6. **保留速度边界。** 沿用原来的总结请求和48000字符辅助输入上限，没有增加自动模型审查。复用已经准备好的同一份总结输入，避免服务器再组装一次；顺序出题的原有8000字符讲解衔接也使用同一保留机制。原文仍完整逐部分交给讲解模型，本次压缩只作用于辅助衔接与总结。

## 真实模型：5次短总结实验

模型为`deepseek-flash`、high、工具关闭、API直连，使用合成资料与隔离数据目录；没有改变用户模型设置，也没有使用真实聊天、画像或教材。5次均得到完整返回，原文、输入与人工评语保存。

- 数学：保留具体核查记录后，实际总结明确写出`n>100`及前100项不受该估计约束；缺少该记录时只能表达一般尾部关系和未知条件，没有编造门槛。两份都未把尾部估计扩大到所有项。
- 社会科学：核查细节帮助模型保留随机分配的是提醒、并非实际行为等限制，但第一次返回又写成“只能停留在关联”，可能把针对行为效应的疑点扩大到实验整体。
- 增加通用的“疑点只限制相应断言、待核实不等于已证错误”说明后单独补测一次：不再明确说只能得到关联，仍正确限制记笔记行为效应；但表达偏保守、存在重复，也没有展开在有效随机分配等条件下可估计提醒分配效应的区别。不据此认定模型的因果推理已经稳定改善。

前4次是输入记录消融：两臂使用同一当前总结指令，只有具体核查正文被替换成缺失占位。它不是旧版本软件的完整回放；消融臂保留相同的试验前计数，计数不能作为具体证据已传入的验收。第5次是发现过度保守后的单次补测。顺序、网络与缓存未随机控制，6.81—17.32秒的短总结耗时不能外推为完整书籍／视频提速或整体内存优化。
