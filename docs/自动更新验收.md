# 自动更新验收

本项完成更新设置与更新流程的源码实现，没有重新打包，也没有发布安装包。根据用户选择，更新源先预留，正式发布时接入；`desktop/release-config.json` 的更新目录与发布者签名名称目前均为空。

## 打开并验收

1. 先从托盘完全退出旧版，再双击项目根目录的 `验收最新版.vbs`。窗口标题应带「源码验收版」。
2. 进入「设置与联动 → 运行与更新」，找到「软件更新」。应显示当前版本及「源码验收版，改动尚未打包」。版本号仍是 0.3.4，不代表旧安装包包含本项改动。
3. 检查更新源目录、自动检测、自动下载和检查间隔。更新源可以暂时留空，默认开启自动检测、关闭自动下载，间隔为 24 小时；可调整为 1—168 小时。
4. 改动开关或间隔，点击「保存更新设置」。完全退出并重开，设置应保持；不需要向 AI 发送内容。
5. 源码模式的「立即检查」保持禁用，不下载安装包。清空更新源后保存，应提示尚未配置；填写 HTTP 地址或直接指向 EXE、`latest.yml` 的地址应提示无效。
6. 展开「更新恢复」，点击「打开备份目录」。目前没有真实更新备份和旧版本缓存时，目录可以为空，「暂无可回退版本」保持禁用。

不要填写虚构地址验收真实更新，也不要用 `start_studyforge.cmd` 打开旧安装包来验收源码改动。

## 新安装版中的运行流程

正式发布包含本功能的新安装版并配置有效更新目录后：

- 开启自动检测时，启动约 20 秒后检查一次，以后按照所设间隔检查；关闭自动检测则仅手动检查。
- 默认发现版本后等待用户下载；开启自动下载则在后台下载，界面显示进度、大小和版本说明。不会因为普通退出或关闭窗口自动安装。
- 点击「保存任务并重启更新」后，先保存当前任务的可恢复状态、停止后台记忆队列，创建数据库和设置快照，再停止本软件后台进程，复核安装包并启动 NSIS 更新安装。
- 没有备份确认、后台未停止、文件损坏或签名不符时取消安装。退出已开始而备份失败时，本次仍退出旧版；重新打开旧版后可查看日志并重试。
- 网络失败可重试。已完整下载的安装包保留到重开后，可复核后安装；未完整下载的文件不能成为可安装版本。
- 存在已缓存的旧版本时，可明确确认后回退软件版本。不会自动回退，也不会自动覆盖当前学习记录。

使用生产依赖 `electron-updater 6.8.9`，更新目标保持完整 NSIS 安装包，采用 generic HTTPS 更新目录。构建脚本只在用户要求打包时生成配置，使用 `--publish never`，不会自行上传发布。接口依据：[electron-builder 26 自动更新文档](https://www.electron.build/v26/docs/features/auto-update/)。

## 文件核验与数据范围

- 更新目录要求 HTTPS；拒绝嵌入密码、查询参数、片段及直接安装文件地址。下载文件可来自 HTTPS CDN。
- 只接受稳定版 `major.minor.patch`、一个完整 NSIS EXE，且文件名为 `StudyForge-Setup-版本.exe`。版本按数字比较，不把 0.3.10 当成小于 0.3.9。
- 下载后核对文件大小和 SHA-512。运行前核对构建时配置的发布者名称及 Windows Authenticode 签名，并再次核对本地文件；发布者名称不能在普通更新设置里更换。
- 尚未配置发布者签名时，安装版可以检查或下载，但不能自动运行安装包；源码版只保存设置。
- 发布说明按纯文本显示，不执行其中 HTML。更新 IPC 只接受本机主窗口的主框架。
- 更新前备份位于学习数据目录的 `update-backups/备份编号`，包含 SQLite 一致性快照、设置 JSON 和带校验值的清单。API 密钥继续使用原有凭据存储，不复制到快照。
- **备份不包含视频、原资料、成果文件和项目工作目录**，这些保留原位置。没有将数据库快照表述为完整文件备份，也不包含系统恢复功能。
- 回退旧软件不保证旧版能读取新数据库结构。没有自动还原数据库；快照用于后续有明确范围的人工恢复，恢复前应核对版本兼容性。

## 正式发布时接入

1. 将版本号提高到 0.3.4 之后的新版本，配置真实的 HTTPS 更新目录、发布者名称与签名证书。构建时配置 `desktop/release-config.json`，也可使用 `STUDYFORGE_UPDATE_URL` 和 JSON 数组形式的 `STUDYFORGE_UPDATE_PUBLISHERS`；签名凭据通过构建环境提供。
2. 用户明确要求打包后运行原有 Windows 构建流程。发布签名 EXE、`latest.yml` 及构建生成的关联文件到更新目录，不在日常启动时构建或发布。
3. 先在独立数据上实际验收两个签名版本的检查、下载、保存、安装、重开与兼容性，覆盖故障和旧版本回退，再对正式使用说明作相应更新。
4. **已有的 0.3.4 安装包没有这次更新代码，需要先安装一次含更新功能的新版本。** 此后更新才可走软件内的检查与安装入口。源码修改不能让旧 EXE 自行获得更新能力。
