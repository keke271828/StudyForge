# 教学条件保留与真实对照

这次集中改善导师与成果讲解的一个共同问题：讲解可以补充背景、例子和推导，但不能把原资料没有说的条件当成已知。

例如，原文只给了某组浓度，不能直接称为“初始浓度”；某天20名自愿填写问卷者的自报平均，不能改成全班或长期的平均。若需要假设一个情境帮助理解，应先说明是假设，再解释这个情境下能推出什么。

## 已实现

- 导师和文档撰写共用一条简短规则，保留数据的时间、状态和样本范围。
- 文档已有审查同步核对这些限定，仍允许明确标注的假设例子。没有增加审查轮次或另开一个教学代理。
- 规则更新后，下一轮请求会按现有机制重建模型私有会话状态，公开聊天和学习资料继续保留。
- 极速模式仍只在生成时自检，不冒称经过独立审查；快速模式仍使用原有一次核查与可定位的局部修正。

## 为什么没有采用另一条“只补卡点”的新规则

先用实际软件构造的输入做了4组、8份真实DeepSeek回答对照。新增限制在编程追问中更紧凑，但数学追问更长、更慢，完整讲解还出现原文未给的“初始浓度”。因此没有把这条限制加入全局提示词。

随后围绕数据条件再做2组、4份真实回答，范围限定得到保留，但不支持稳定提速或全面质量领先的结论。新旧规则在社会调查题中都能讲清关键限制；长化学讲解也仍有扩展偏多、补充条件在后文宜再次明确的问题。完整结果原样保存，没有修饰成“优秀样例”。

另有两轮各4次真实快速审查：两轮的新旧规则都发现了擅加的初始条件，并局部修正文中与总结的对应句；明确的假设例子均被保留。首次记录器只统计流式请求，漏计非流式审查，因此保留该次结果但不把其中的0当成没有请求；复测已记录完成调用、非流式POST调用、模型用量和指纹。内部连接重试次数没有单独测量。

## 程序验收与范围

255项相关Python回归与136项前端测试通过。新增完整生成任务使用实际软件处理流程和受控HTTP回复：一次撰写、一次快速审查，修正后的正文进入最终Word文件，原文引用、数值计算与假设例子保留；没有附加题单或额外交付Markdown、审查文件。

受控回复用于验证软件传递与交付，真实DeepSeek样例用于评阅教学内容，两类证据分开。Word检查重新读取了文件内容，本轮没有重新做Word外观排版验收、安卓实机、整本扫描书、长视频或整机内存峰值测试。没有改真实数据库、默认模型或已有成果。
