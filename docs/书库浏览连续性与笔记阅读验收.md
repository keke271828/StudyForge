# 书库浏览连续性与笔记阅读

日期：2026-10-11

## 修复的实际问题

1. 原来每次重新打开同一本书都会清空勾选，即使只是从学习工作台返回书库。现在同书刷新保留勾选、筛选和折叠；切换教材时，按书分别保存这些浏览草稿和目录滚动位置。删除或失效的节点从选择中移除。
2. 原来所有教材详情请求共用一次等待，快速切书时可能等待无关请求；只有书籍 ID 的检查也不足以区分“先看 A，再看 B，又看 A”的旧响应。现在以导航和书籍请求版本校验响应，不让较慢的旧操作覆盖当前教材；相同教材的进度轮询仍合并。
3. 手机阅读笔记原来把 `markdown(target, content)` 当成只接收文本、返回 HTML 的函数调用，导致渲染失败。现在电脑和手机共用 `renderLessonText`，显示 Markdown、公式和表格，并继续过滤不可信 HTML。

浏览草稿仅在当前页面／软件窗口运行期间保留，最多保留 32 本书，不保存正文或笔记副本。已有教材、阅读整理和对话引用继续由原来的数据库长期保存；此次没有增加跨设备的勾选同步，也没有把浏览草稿当作对话资料或画像证据。

## 笔记阅读窗口

- 独立窗口立即显示加载状态，并显示教材名称、章节路径和 PDF 页码。
- 长笔记在正文区域滚动，标题、关闭按钮和底部操作保持可见；长公式和表格横向滚动，不撑破窄屏。
- “查看起始原页”打开实际 PDF 页，采用只读预览，不调整节点范围。
- “引用到当前对话”加入现有书库引用，继续按对话保存；不会把笔记作为聊天消息插入。
- 加载失败时在原窗口提示，并提供重试。关闭时终止在途请求并释放正文；旧请求不能重新弹窗，也不能覆盖后来打开的节点笔记。
- 打开教材失败时显示重试入口；添加引用的等待期间重新检查当前教材和对话，防止使用过时的界面状态。

## 验收

使用独立测试数据目录、实际 Electron 窗口和经电脑批准配对的 HTTPS 手机页面。长笔记、公式和不同书籍为受控测试资料；不修改用户教材和学习数据库。

13 项新的实际界面检查全部通过：

1. 同书重开及切到工作台再返回时，勾选和筛选保留。
2. 不同教材分别恢复勾选、筛选和目录滚动，不串用节点。
3. 删除的节点从保留勾选中清理。
4. 慢响应的旧教材不能夺回当前选择。
5. 电脑公式、表格和长笔记显示，滚动正文时关闭／引用入口可用，HTML 脚本未执行。
6. 笔记可作为本对话引用，聊天消息数不增加。
7. 原页入口实际加载 PDF 页，并禁用编辑和保存。
8. 加载中关闭笔记后，窗口不会被旧结果重新打开。
9. 较慢的旧笔记不能覆盖最后选择的笔记。
10. 配对手机关闭、重开书库保留勾选。
11. 390 像素手机页面显示并滚动带公式长笔记，聊天不受影响。
12. 320 像素手机页面显示并滚动带公式长笔记，无横向布局溢出。
13. 手机也能打开实际原页，并保持只读。

## 打开验收

从 Windows 通知区托盘完全退出旧版，双击项目根目录 `验收最新版.vbs`。在全局书库中勾选几个章／节，切到另一本书后再返回；然后打开已整理节点的“阅读笔记”，试用滚动、公式、原页和引用。手机刷新当前电脑提供的工作台页面，再从“选项”打开全局书库。
