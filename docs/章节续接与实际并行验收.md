# 章节续接与实际并行验收

2026-10-26。源码更新，未重新打包；本轮聚焦生成讲解时的章节衔接。

## 缺陷与修复

1. 已生成成果作为参考资料时，每个分段附有版本化的资料身份信息。原依赖判断没有越过这一封装，因此看不到正文开头的“原文续接”，可能把后半推导当成独立章节并行写。
2. 身份信息中的文件名含“接上文的证明”等词时，原规则也会错误地把独立正文设为依赖。现只检查正文开头的实际续接标记／明确衔接语句，保留标题式及常见开头语；代码、引句、否定句和后文提及不自动产生依赖。
3. 独立并行章节尚无已完成草稿时，原输入仍带一个空的“已写内容衔接”标题，与并行草稿说明矛盾。现仅在确实有已完成片段时附上这个标题。

`source_origins.transport` 只识别完整、版本一致、结构符合既有约定的封装；未知或损坏封装不猜补、不裁掉。结构判断使用其正文，实际模型输入仍保留资料身份。AI成果不会因被重新引用而变成已核实的教材原文。

内部并行开启时，续接部分等待上一部分完成所选强度的核查，再收到其草稿；独立部分仍可重叠。关闭时全部依次完成。没有增加固定模型请求或核查轮数。已有交付不批量重写；旧未完成任务因新上下文而改变的第二部分需重新生成，可以复用的第一部分缓存仍可复用。

## 验收结果

- 修复前复现4项依赖判断失败，另复现1项空衔接失败；原始JUnit凭据保留。
- 最终304项关联回归全通过，0失败、0错误、0跳过；4个生产文件指纹前后一致。
- 27项专门检查，包含真实资料分段／身份、正文与文件名区别、空衔接、实际生成／快速核查顺序、关闭并行、Word正文及缓存恢复。
- 旧缓存测试先按错误的独立计划写完两部分，在总结前受控中断；修复后同任务续做，第一部分不重复请求，第二部分带前文重新生成，最终Word保留更新后的续接内容。
- 7组实际电脑／配对HTTPS手机检查：桌面按钮发起三项任务，分别验证续接等待、独立并行及关闭并行；两端公式显示、三份Word下载及完整哈希、390／320px、刷新保留结果。
- 三项任务每项2次撰写＋2次快速核查＋1次总结，共15次受控模型请求，0次外部模型请求；没有新增学习事件或掌握度记录。模型输出是人工流程夹具，不能用作真实教学质量、审核正确性或真实生成速度的证据。
- 三份手机实际下载的DOCX均与电脑文件哈希一致，ZIP完整，Word正文包含两部分及整体总结，含原生公式。没有在实体安卓或Microsoft Word应用中重复排版验收。

本轮测试过程保留：最初两个集成运行的独立资料夹具预期2段，实际因清单／身份开销变成4段，后按可变绝对路径长度动态安排测试预算；实际生产分段逻辑未修改。短模拟延迟与本地准备耗时曾使一次重叠断言失效，改用事件同步验证两请求可同时进入。第一轮实际UI进一步暴露空衔接标题问题；修复后重新完成最终测试。旧日志、截图没有混作最终通过。
