# 并行任务调度验收

2026-10-04。源码完成，未重新打包。实施范围是独立任务有限并行、可切换的讲解内部并行、上下文隔离、资源上限和实际运行记录。

## 打开最新版

1. 在 Windows 右下角托盘右键退出已经运行的旧 StudyForge。
2. 双击工程根目录 `验收最新版.vbs`。窗口标题应包含「源码验收版」，无需保持 CMD。
3. 在「设置与联动 → 生成偏好 → 任务调度」修改全局调度；顶部「模型请求」按钮也可直接进入这里。
4. 学习工作台生成按钮下方有「讲解内部并行」，为每次成果单独选择。任务保留启动时的选择，暂停后继续仍采用原设置。

旧安装程序不会因为源码修改而更新。本轮没有创建新的安装包。

## 两层控制

| 控制 | 默认值 | 实际行为 |
|---|---|---|
| 允许独立任务并行 | 开启 | 聊天、生成、通读、知识结构和不同题单共用有限并发，不再被整个页面的忙碌状态锁住 |
| 同时模型请求数 | 2，可设 1–8 | 控制正在运行的 DeepSeek 请求、Codex 回合和绘图模型请求总数；超出的排队 |
| 新任务默认开启讲解内部并行 | 关闭 | 设置工作台内部并行选项的默认值；已经手动选择的本次选项保留 |
| 讲解内部并行 | 默认关闭，可单次选择 | 同时控制长资料的独立部分和配套习题这两处 |

内部开关关闭时，逐部分撰写，再整理、总结、导出讲解，随后根据原资料和已完成讲解结构生成题单。开启时，题单与独立部分可重叠；识别为原文续接的证明、公式或段落等待前一部分，全文整理与总结等待全部部分。

全局关闭或并发上限为 1 时，模型请求实际依次执行，工作台会说明。只生成单个短篇讲解、没有配套习题时，内部开关没有可重叠的步骤。并行减少等待，不能保证所有资料都更快或章节衔接质量相同；连续证明优先采用顺序模式。依赖检测识别明确续接和切分标记，不等于自动证明所有章节在概念上互不依赖。

调低上限不打断已经发送的请求；之后的请求等运行数下降再开始。网页读取、媒体解析、图片生成和容器判题分别限为 4、1、2、1，避免所有任务同时争用本机资源。全局串行时各资源上限为 1。

## 可以同时做什么

| 场景 | 新行为 |
|---|---|
| 文档生成中继续聊天 | 允许；后续聊天不会暗中改写已启动的文档 |
| 同一对话再启动另一份独立成果 | 允许；各成果分别保留原指令、模型、资料与画像快照 |
| 切换到另一对话或项目聊天 | 允许；流式回复继续存入原对话，切回可看正在回复的内容 |
| 通读期间讨论无关问题 | 选择「本次对话资料 → 暂不引用资料」；保留原对话的资料选择，不声称已读完资料 |
| 依赖通读的文档 | 可以先发起，后台等待自己的通读；无关任务继续运行 |
| 不同题单的批改、编程判题 | 允许排入调度；容器测试仍按本机资源限制运行 |
| 后台画像整理 | 低优先级参加调度，保留空闲触发、间隔、每日次数和输入输出上限 |
| 讲解已交付，配套习题还在生成 | 可以提交理解问卷并让导师补讲，无需等独立习题完成 |

同一对话的连续导师回复、同一题单重复提交、成绩确认和依赖成绩的进阶保持顺序。解题与评分使用私有上下文，提交并批改前仍不公开答案。

## 上下文和暂停

导师和文档沿用同一学习对话的模型、教学规则和公共消息。生成启动时复制当前对话快照，工具缓存、工作目录和内部模型协议分别管理；完成的讲解和题单回到原对话和原项目。各生成分支不修改聊天的内部推理或工具协议。

后台画像仍是跨项目学习证据，其他项目的聊天原文不会因此进入当前对话。并行时保留题意核验、引用范围和原文件读取规则。

排队中的可暂停步骤尚未发送请求时可以直接停住，不消耗模型额度。已发送的模型请求、执行中的工具、判题和导出完成并保存后进入暂停；继续复用保存的步骤。暂停或删除一项任务不停止其他独立任务。Codex 执行嵌套模型工具时释放外层模型名额，完成工具后重新取得名额，避免上限为 1 时相互等待。

成果区任务卡显示模型运行数、排队数和内部执行模式。「任务调度 → 实际运行时间记录」显示步骤开始、结束及耗时，不显示原文或聊天内容。并发设置有保存顺序和过期响应保护，退出等待保存完成。

## 手动验收

1. 保持全局并行开启，上限 2。选择两份有足够篇幅的独立资料，在「生成内容」选择「讲解＋习题」。
2. 关闭内部并行，生成一次；查看实际运行记录，应先完成讲解，再运行题单步骤。
3. 用相同资料开启内部并行再生成；在存在独立部分时应看到重叠时间。不要用单段短文、没有习题的任务比较内部并行。
4. 文档运行中发送无关问题，再切换到另一项目聊天；原项目任务继续，回复和成果不应出现在错误项目。
5. 连续发起两份独立成果；暂停排队中的一份，等另一份完成，确认暂停项没有继续发出请求。恢复后应保留已经完成的步骤。
6. 全局关闭，或把模型上限改成 1；下一批请求应按顺序运行。打开全局并行并恢复上限 2，独立请求应有重叠。
7. 展开实际时间记录，核对开始/结束时间；习题文件中不应有答案。
8. 完全退出托盘后重开，检查聊天、成果和调度设置恢复。中断任务按原有恢复流程主动继续。
