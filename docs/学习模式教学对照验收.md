# 学习模式教学对照与质量验收

2026-10-08。本轮针对导师与生成文档的模式适配，完成源码修改、实际模型对照、功能回归与桌面验收；没有重新打包。

## 发现的问题与修改

1. 生成器将「未勾选同步出题」解释为「本次只需读懂并了解原文」，冲淡精学和研究目标。现在只据此决定不生成习题，深度继续由当前模式、学生要求与概括性档位决定。
2. 三种模式共用同一默认文档结构，生成入口还统一要求「教材式讲解」。现在入口使用中性要求，模式分别决定默认组织、讲解重点、方法处理和篇幅重心。
3. 通用教学规则和长原文之后的提醒容易恢复默认深度。现在在同一请求中追加当前模式的短提醒；它实际接入共享导师/文档路径，不增加固定模型请求。
4. 第一轮研究输出增加了边界段落，但主体仍重复证明。已明确研究的篇幅重心，要求核实路径说明具体检查对象、方法和局限；计划须标为尚未执行的教学建议。
5. 概览仍倾向额外展开配方，继续调整默认要求：覆盖主线、关键条件与结论，保留必要关键式，计算展开留给明确的逐步证明要求。
6. 真实样例出现单行来源定位误报：原文「行1-1」与引用「行1」位置相同，却被判不匹配。现在承认等价单行写法与连字符，错行、多行范围不一致、重名歧义和非逐字引用继续标记；匹配仍不代表内容正确。
7. 实际截图发现弹窗标题沿用白色渐变，在夜间产生浅字白底。通用弹窗标题现在跟随主题，文字保护覆盖标题与小标签；指南用圆角卡片和窄窗口单列。

## 三种模式的实际目标

| 模式 | 重心 | 对证明、方法和互动的取舍 |
|---|---|---|
| 概览 | 建立问题地图与主线 | 串联问题、概念、主要论据、结论及必要条件；保留核心转折，可邀请学生选择进一步深入处 |
| 精学 | 可复现、可迁移的理解 | 解释关键障碍、构造选择、步骤依据、使用线索与失效边界；围绕具体卡点补讲 |
| 研究 | 论证边界与可核实追问 | 凝练回顾已有结论，分析假设依赖、替代解释和证据强弱，提出具体核实路径及局限 |

研究数学时核对证明与可推广条件，不虚构争议；研究经验材料时区分观察与识别假设；研究哲学时辨析概念、前提与反驳，不统一改造成实验或物理模型。

模式控制目标，风格控制表达，概括性控制展开程度，是否同步出题独立决定。详细概览仍围绕主线，凝练精学仍保留关键理由。学生当前明确的结构、来源、语言、篇幅与逐步证明要求优先。针对一个追问先解释该卡点，不为了体现模式重讲整份资料。

工作台新增「模式指南」，从后端读取实际使用的定义，支持直接切换并保存到当前对话；已启动任务保持原模式。指南没有模型调用，支持明暗主题、圆角卡片及窄窗口单列。文字保护开启时，透明弹窗设置不会覆盖其可读性底板。

## 真实内容对照

使用已登录的实际 `gpt-6.1-sol`、中等推理强度，调用真正的 `/api/chat/stream` 和 `/api/generate`。资料、对话、模型工作区与成果均隔离于 `build`，未使用真实学习记录；各模式使用独立对话，未继承另一模式的回答。

两份原文分别是柯西不等式的有限维实数平方构造，以及自愿学习讨论与成绩的因果辨析。两条教学路径在三种模式下使用同样材料、中文通俗风格、约400—650汉字、只用资料且不出题的要求。文档均实际生成 DOCX 并重新读取，没有同步题单。

保留了过程记录，没有用最后成功替代最初结果：

- [修改前基线](../build/mode-quality-baseline-20261008/report.json)：数学文档三模式，3次请求；三者都主要重述同一证明，研究未展开核实路径。
- [首轮修改](../build/mode-quality-live-20261008/report.json)：两学科、三模式、导师与文档12组，12次请求；精学增加选择线索，研究仍过多重复推导。
- [调整重心后的12组](../build/mode-quality-final-20261008/report.json)：12次请求，逐份审读数学条件与社会科学证据边界。
- [概览最后四份复验](../build/mode-quality-overview-final-20261008/report.json)：4次请求，替代上述矩阵的概览输出。一次社会科学导师回复用了89.74秒，不能把短样例响应速度当作稳定承诺。

最后一份概览首次导出包含单行定位误报，原记录保留。修复后复用实际模型正文核对，2项警告变为0，原句逐字匹配；没有重新调用模型。[来源复验记录](../build/mode-quality-overview-final-20261008/citation-recheck.json)、[复验后的概览DOCX](../build/mode-quality-overview-final-20261008/data/artifacts/相关与因果-概览-来源定位复验.docx)。

本轮内容抽查共31次生成请求；这是开发验收消耗，正常使用不会因新增模式规则自动增加审查次数。最终对照矩阵为两学科×三模式×两路径12份；历史版本不相加为31份不同教学任务。

### 开发助手逐份审读的结论

| 材料 | 概览 | 精学 | 研究 |
|---|---|---|---|
| 柯西不等式 | 以目标、非负平方和、选参及等号连起主线；最后复验未额外展开配方步骤 | 解释目标差值怎样提示构造，通过配方或系数核对说明参数选择；正数乘除及零分母分支讲清 | 说明除法步骤在B=0时失效，而结论仍成立；解释实数、等号分支及复数推广需重新核对的依据 |
| 讨论与成绩 | 建立相关、共同原因、因果效果与推广范围之间的关系 | 解释自愿参加怎样影响比较条件，为什么增加样本不能代替因果识别，并提炼识别线索 | 提议检查讨论前的动机和成绩及比较条件，说明测量可靠性、遗漏共同原因和推广证据仍需核实；明确方案尚未执行 |

数学样例保留有限维实数条件、B=0分支和等号条件，不声称方法唯一。社会科学样例没有把可能的共同原因说成已证原因，也没有把证据不足说成讨论无效。没有编造人物、历史、数据或强套物理；文档保留系统性总结，没有未请求的习题。

短材料中必要定义和关键事实仍会相同；模式差异应体现讲解重心和方法处理。概览与精学的差异在单条短证明上有限；不能把不同标题或文字重合率当成教学适配的充分判断。

这是开发助手审读，不是独立教师盲评、统计重复试验或长期学习效果认证。没有在本轮真实调用 DeepSeek、Gemini 及每个第三方账号；共享路径回归不能代替其实际教学质量验收。

## 自己验收

1. 从 Windows 托盘彻底退出旧版，双击根目录 `验收最新版.vbs`。
2. 在工作台打开「模式指南」，查看并选择模式；切换到别的对话再返回，检查选择恢复。
3. 使用同一资料和同一问题比较：概览看主线，精学看构造/方法理由，研究看边界及具体核实办法。
4. 不勾选同步出题，检查精学/研究仍体现相应目标，且文档末尾没有新增习题。
5. 自定义背景并启用文字可读性保护，检查指南说明、卡片与按钮。

原安装包不会因源码修改自动更新。本轮未打包；真实服务的时延、额度与输出存在波动，提示词不构成任意资料绝对正确的保证。

开发复验：`python -m pytest tests/test_learning_modes.py tests/test_teaching.py tests/test_lesson_quality.py -q`；`./scripts/smoke_learning_goals.ps1`。真实抽样须明确指定 `python -m scripts.learning_mode_quality_eval --live --model gpt-6.1-sol --output build/mode-quality-new`，会消耗模型额度。
