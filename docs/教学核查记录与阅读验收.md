# 教学核查记录与阅读验收

2026-10-21；本轮源码实施，未打包。

## 解决的问题

此前生成任务已经保存逐轮核查意见、局部修订索引和应用定位记录，但成果卡片主要展示来源、格式和下载入口。学生难以直接看到究竟改了什么、哪些仍须核对；只看到通过或失败也容易误解其含义。

本轮在电脑“成果文档”和手机成果列表中加入共用的“教学核查记录”。只展示讲解成果；习题、编程作业、批改等成果不通过此入口展示私有审查数据或答案。

## 已实施

- 按讲解部分、阶段和轮次查看真实保存的意见，区分未执行独立核查、本轮未列疑点、历史疑点及已记录局部修订。
- 同一报告返回 `passed=true` 但仍有 `issues` 时，保留疑点，不据此认证通过。后续轮次通过也不自动标记先前的每条意见已经解决；历史疑点同样不冒充最终稿错误。
- 局部修订展开显示模型给出的原稿锚点、替换建议和定位记录数量；它们对应当时的核查。编号提议未保存原段全文时明确缺失，不从后来正文猜补。引用样式别名等锚点不冒称实际原句逐字相同。
- “依据”明确标成核查模型的理由，不冒充已确认的来源证据。模型建议和程序应用记录都不是正确性证明。
- 只在展开时构建内容，每页至多5条疑点，替换提议每批8条；长字段按需展开且保留全文。报告与疑点可输入编号跳转，非法编号不会跳到错误位置。
- 成果列表刷新保留面板展开、已展开的替换说明和内部滚动位置。修复实际界面测试中发现的“脱离DOM时恢复scrollTop无效”问题，延后到插入布局后恢复；旧卡片的延迟滚动事件不覆盖新位置。
- 手机320／390像素宽度可滚动阅读；深色主题沿用手机面板颜色，防止浅色底搭配白字。手机卡片缩减嵌套留白。
- 原有理解反馈入口保留；指南说明如何选择“讲解可能有误或依据不清”并定位原句。查看本面板不触发模型、习题、评分、画像写入或另行审查文档输出。
- 两端使用同一组件；手机仅更新公共应用壳到v59，核查记录等学习内容不进入service-worker缓存。

## 检验

1. **252项Python相关回归通过，47.38秒**。涉及核查、精确修订、原文生成、问卷、纯内容质疑与画像隔离、配对手机补讲、暂停续接和帮助；`build/teaching-review-final-regression-20261021.xml`。
2. **3项Node状态／隔离检查通过**：私有作业不创建检查器；通过标记和疑点冲突；局部修订与历史疑点不混同。
3. **原生两个完整DOCX任务**：隔离夹具中的快速和极速生成共3次受控模型请求、0次外部请求。快速报告两个疑点，一个局部修订实际写入，另一个试图改来源的替换被原有保护拒绝并保持待核对；极速没有独立审查。学习事件0条。这不是实际模型教学质量评测。
4. **7项实际Electron／配对HTTPS手机界面检查通过**：两端原生记录、按需展开、刷新后的滚动位置、53条合成疑点最后一页、跨报告查看与非法跳转、长证据原样文本／HTML不执行、习题私有解析排除、手机320／390宽度与深色前景／背景、真实生成DOCX可下载。浏览核查记录没有增加模型请求；界面控制台错误0项。见 `build/teaching-review-ui-20261021-1/teaching-review-ui-report.json`。
5. 实际查看电脑和手机深色截图，核对文字和边界。这里的手机验收是实际配对HTTPS服务与手机宽度Electron窗口，不是实体安卓设备人工验收；下载确认Word包签名，不代表Microsoft Word分页／排版视觉验收。

## 可打开的验收页

`build/teaching-review-acceptance-20261021/教学核查记录与阅读验收.html`。

其中4张卡片载入此前保存的真实DeepSeek核查，使用本轮同一显示组件。包括“返回通过但实际漏检”的被拒绝候选，保留其局限，不把它当当前默认方案。链接可打开相应核查当时交付的Word；这些是旧的真实结果复用，不是本轮新增模型评测。

软件使用 `验收最新版.vbs`。先在系统托盘彻底退出旧StudyForge，再启动源码；仅关闭窗口通常会继续后台运行。进入“成果文档”，找到一份生成的讲解，展开“教学核查记录”。旧成果没有逐项明细时明确说明缺失，不使用当前设置回填历史。

## 实际边界

本轮改善核查信息的可见性和阅读衔接，没有更换提示词、模型、推理强度、审查轮次或原文输入；也没有声称解决模型漏检、所有学科教学质量、长视频速度和全应用内存占用。记录用于回查，不能替代对原文件和推导的判断。
