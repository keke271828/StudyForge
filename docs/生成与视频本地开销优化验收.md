# 生成与视频本地开销优化验收

2026-10-11。源码交付：先从托盘完全退出旧版，再双击 [验收最新版.vbs](../验收最新版.vbs)。现有0.4.2安装包不包含本轮修改。验收在独立目录进行，没有修改真实学习数据库或原视频。

## 实际修复

1. **进度更新重复载入长对话。** 控制器初始化、进度、暂停、继续及检查点只取所需状态、进度和结果字段。启动意图仍完整保存，SQLite列读取权限检查确认这些控制操作不再读取`payload_json`。
2. **大份JSON临时副本。** 原文内容及保存步骤签名逐段编码计算SHA-256，不再生成整份JSON字符串和另一份UTF-8副本。转义、排序、间隔、数字表示及保存键保持一致；旧步骤仍能续用。步骤签名进入线程，准备完成后重新检查暂停和删除。临时开销仍受最大单段影响，任意长单段不是固定内存。
3. **大份图像校验挡住无关原文。** 缓存校验图片时不持有全局锁，其他已缓存资料可以同时读取。原文件及画面校验保持，缓存变化会重检。
4. **无用副本驻留。** 原文结果不携带旧预览JSON，生成末尾的原文件复核结果比较后立即释放。源数据库未删减，模型的正文范围保持。
5. **排版入口未共用限制。** 首次讲解、习题、视频原文档、作业解析、批改成果及导师成果进入既有单个本机排版队列；另存格式原来就使用此队列。模型资源仍可独立并行。首次讲解及习题排版接入保存步骤，暂停等待当前写入完成，继续不重复模型请求和同一文件的写入。
6. **视频自动使用硬件线程。** FFmpeg解码、过滤及输出编码限制为本机策略的1–4个线程。采样间隔、时间记录、缩放、PNG、音轨规格、Whisper模型及beam_size 5保持。音轨提取失败也清理临时WAV。

## 新增耗时详情

电脑“成果文档”、手机“任务”的任务卡提供“耗时详情”，按需查看原文核对、音轨、语音、抽帧、OCR、图片准备、模型、容器及排版记录，分别显示执行时间、并发等待与运行／排队段数。新的讲解请求进一步区分“讲解撰写”“讲解审查”和“全文总结”；旧记录不反推这些分类。点“刷新耗时”更新，不额外轮询或调用AI。

**各阶段可能并行或互相包含，不能相加当总时长。** 本机解析整体包含语音和OCR；模型段数可能包含同一请求的工具续接，不等于付费请求次数。模型占用不是纯推理时间，语音/OCR可能包含共享引擎等待。中断后的时间可能含停机，只能作不完整观察。

总时间从任务创建起算，包括暂停、审批和重试等待；目前没有进一步分解这些等待，也未按任务采集整机或云端模型内存。旧任务缺少阶段记录时明确提示，不补造。

记录不包含原文、答案、聊天或密钥。手机配对后才可读取；删除任务后不会由迟到计时恢复记录。实际手机检查还发现，复用已打开页面再次扫码可能只改变网址片段。现在响应`hashchange`填入有效新码，不退出已认证设备。

## 本地对照

两个独立Python进程都加载旧和当前模块，使用相同构造资料、长快照及数据库结构。计时先预热、重复3次取平均；另测`tracemalloc`临时分配，不含已构造输入、整个Electron工作集或模型内存。

| 操作 | 原平均耗时 | 新平均耗时 | 原临时Python峰值 | 新临时Python峰值 |
|---|---:|---:|---:|---:|
| 60段长原文校验 | 48.48 ms | 39.97 ms | 25,514,939 B | 430,853 B |
| 相同资料的保存步骤签名 | 49.06 ms | 40.80 ms | 25,514,885 B | 430,781 B |
| 长快照任务的30次进度更新 | 2,045.24 ms | 1,813.88 ms | 44,113,768 B | 13,939 B |

原文及步骤键完全相同，进度结果相同。两个校验样例临时峰值下降约98.3%。进度耗时只下降约11.3%，仍有SQLite更新与磁盘开销，临时分配降幅不能套用于整体生成速度。

### 实际视频原生处理

使用用户此前提供的本地LaTeX课程视频，只测前60秒音轨和原有10秒画面采样，没有重跑整段Whisper、OCR或云端理解。

- 六张PNG及时间戳逐项相同；16kHz单声道WAV的SHA-256相同；原视频SHA-256保持。
- 抽帧进程观察到的历史工作集峰值204,603,392 → 187,199,488 B，约195.1 → 178.5 MiB，下降约8.5%。每20ms读取Windows计数器，末次采样后的短峰值可能漏测。
- 抽帧3.32 → 3.25秒，音轨约0.20秒，耗时变化很小；单次局部测量不证明完整视频显著提速。
- 原视频未删除或覆盖，输出只在当前验收目录。这不是40分钟视频至讲解／习题的完整计时。

[视频对照记录](../build/generation-local-performance-20261011/decoder-comparison.json)，复现脚本`scripts/benchmark_video_decoder.py`。

## 尚未由本轮证明的事

未重新测量完整视频首次导入、整本扫描书、真实云端长文或多任务整机峰值，也未新增真实教学质量评分。语音/OCR、服务响应和长篇输出仍可能是主要耗时。下一步应按实际阶段定位；增加并发可能增加限流与内存压力。
