# 工作台刷新与任务数据优化验收

2026-10-11。本轮扩展到资料库、工作台、成果、作业和审批，源码更新，未重新打包。使用隔离数据和本机服务，不修改用户学习数据库，不调用收费外部模型。

## 实际修改

1. **资料列表不加载原文。** 文件名称、状态、分类、网址／图片解析策略只查询必要字段；不再先把每份资料的完整 `segments_json` 读入 Python，再丢弃正文。新成果加入资料快选的链接操作也不读取庞大的成果元数据。实际阅读与生成继续通过原有原文件读取链路。
2. **任务轮询使用轻量视图。** 新增 `/api/jobs/{id}?view=progress`，只提供状态、阶段、进度、必要标识、暂停能力、另存能力与重试状态。电脑任务监控、资料通读与知识结构等待、手机解析监控使用这个视图；需要完整结果的监控在结束／暂停时再读取原有详情。默认详情接口仍保留完整任务意图和结果，数据库中的原资料、对话快照及恢复步骤保持不变。
3. **任务列表不搬运整份快照。** SQLite 直接提取显示字段；Python 不再同时持有列表里所有任务的长对话、书库上下文或文档正文。模型运行／排队计数按任务批量查询。旧任务的暂停规则包括空值、空对象、空数组及字符串形式的值均有对照。
4. **重复请求合并。** 同一任务的重叠进度查询共用一次请求；手机同项目、同对话版本、同排序的重叠周期刷新共用一次加载。上传、生成、暂停等修改后的刷新仍安排新读取，避免把修改前正在返回的数据当作操作后的结果。项目、对话或排序改变时，旧响应不能覆盖当前界面。
5. **保留界面中的控件。** 手机资料、成果、题单、理解反馈列表未变化时不重建；任务逐条更新，未变化的任务保留原控件与焦点。正在等待暂停／继续响应时，刷新后的相关按钮也保持禁用。补讲状态变化会更新原有成果按钮，不因复用卡片而冻结“哪里没懂”的状态。
6. **修复审批归属与等待。** 旧对话审批的慢响应不能显示在新对话里；请求已处理后，旧响应不能重新把它显示出来。等待审批接口回应时允许和拒绝两个按钮都禁用，防止相互竞争或重复提交。切换只关闭旧界面，不替用户决定原请求；回到原对话仍可处理它。
7. **手机资源与指南同步。** 新公共脚本在手机服务的明确静态资源清单中提供，学习 API 仍需要配对。页面缓存升级至 v28，软件内指南说明刷新、作答和审批的行为。

这些修改改善界面与轮询的数据路径，不减少生成任务实际读取的原文或模型上下文，不更改评分规则，不提前公开习题答案。

## 性能测量与边界

受控前后对照使用同一隔离数据库，40份合成的长解析记录、真实 Word 文件和含长快照的任务。修改前源码保存为 `build/workspace-refresh-20261011/server.before.py`。分别在独立进程先执行未追踪的首次调用、再四轮计时，最后单独测 Python 分配峰值；同时读取 Windows 进程的工作集与历史峰值。两个进程都导入两套服务模块，避免仅基线多一个路由／模型注册表造成内存比较偏差。

| 本地操作 | 修改前平均耗时 | 修改后平均耗时 | Python分配峰值：前 → 后 |
|---|---:|---:|---:|
| 资料列表 | 109.16 ms | 41.48 ms | 21,430,128 → 53,372 字节 |
| 任务列表 | 131.93 ms | 86.40 ms | 6,311,815 → 15,557 字节 |
| 单项任务查询：详情 → 进度视图 | 31.16 ms | 29.39 ms | 4,206,804 → 9,510 字节 |

资料列表在此样例的耗时减少约62%，任务列表约35%。单项任务本地查询时间只小幅下降，仍有数据库／JSON提取等固定开销；它的主要收益是降低传输和反复复制长快照。Python峰值不包含 SQLite 原生分配。

在这组连续操作中，Windows观察到的基准进程历史工作集峰值为约 **86.8 MiB → 71.1 MiB**，初始工作集约60.9／61.2 MiB。历史峰值也包含服务模块导入，不将它当成某一步独占的内存，更不当成整个 StudyForge 的峰值。原有资料输出及任务显示字段的投影校验值匹配；列表新增项目／更新时间等字段，恢复与执行所需的原始任务快照没有改变。

结果文件：同目录 `polling-before.json`、`polling-current.json`、`polling-comparison.json`。测量脚本：`scripts/benchmark_workspace_polling.py`。旧显示字段的投影与校验值必须匹配，原任务意图仍在数据库保存。

这项测量是本地列表与任务轮询，不是全应用 RAM、扫描 OCR、视频转录、图片理解、模型响应或教学质量的评估。降低背景数据搬运不能证明长视频和文档生成总时间已经减少30%；这些部分仍需要各自计时与内容验收。

## 打开与验收

1. 从 Windows 托盘彻底退出旧版 StudyForge，双击根目录 `验收最新版.vbs`。当前0.4.2安装包不包含本轮源码改动。
2. 手机打开连接当前源码服务的页面并刷新。打开资料或成果，保持一个控件的焦点，等待刷新后它不应被重新建立；改变筛选、选材或排序仍应实际更新。
3. 作答框中输入文字并选择一段文字，等待刷新；作答、光标与未提交前的答案保护应保留。
4. 运行任务时点击暂停或继续，等待接口回应期间按钮保持禁用，完成后显示实际状态。
5. 在审批等待时切换到别的对话，旧审批不应进入新对话；回到原对话处理审批后，旧请求不应再次出现。

本轮无需更换模型、修改提示词或重新导入学习资料。真实手机键盘、长视频端到端速度、外部模型的教学表现仍需实际设备与材料验收。
