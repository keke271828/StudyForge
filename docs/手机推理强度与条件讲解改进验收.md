# 手机推理强度与条件讲解改进验收

2026-10-11，三轮完善中的第二轮。

## 修复了什么

手机之前只为 Codex 显示并发送推理强度，导致保存的 DeepSeek 选择在聊天和讲解生成请求中变成空值。现与电脑一致，DeepSeek 提供自动、关闭、低、高、最高；导师、文档生成和新建对话都使用实际选择。留空模型使用服务默认，并不会关闭推理选择。Codex 切换到不支持原档位的模型时清除无效档位；没有配置推理能力的第三方服务不强加这个参数。选择保存到当前对话，刷新和设备续接后恢复。

共同教学规则增加：判断某条条件是否必要时只改这一条，保留其他条件，先检验是否已经可以推出；一种失败例子不能证明所有条件独立必要。属于一次原有请求里的教学要求，没有新增多轮审查或要求输出内部思考。隐藏工具会话的规则签名同步改变，公开聊天保留，后续请求使用新规则。

## 实际验收

- 104 项相关回归通过：教学会话与设置、手机接口、模型参数、聊天和画像隔离。报告 `build/round-two-20261011-tests.xml`。
- 真正配对的 HTTPS 手机界面 **8 项检查通过**。分别发送低、高、关闭、最高四次聊天，检查实际 HTTP 模型请求；手机生成一份真实 DOCX，检查导师和文档请求的高档位。新对话、刷新、Codex 档位不兼容、第三方不支持推理参数也通过。响应为固定的离线测试内容，不是假称账号推理能力的验收。报告 `build/mobile-reasoning-20261011-2/reasoning-ui-report.json`，无控制台错误。
- 两个额外真实 DeepSeek `deepseek-flash` / high 的教学样本，分别约 **59 秒**和 **24 秒**。第一个正确指出含 1 与减法封闭已经推出含 0，并用推导和保留其他条件的反例区分条件；第二个讲清开邻域为何允许取半间距，三分之一同样有效、量词允许选定正数。原始最终答案见 `build/teaching-conditions-20261011-1/`，没有保存或评价私有思考过程。

这是两道小样本的内容抽查，不能证明任意教材或所有模型已经准确，也没有证明比网页端稳定更好。手机尺寸界面验收仍不能替代真实安卓硬件的键盘与系统行为验收。
