# 知识库混合检索与条件保留验收

2026-10-21。本轮为源码改进，未打包。全局书库已有关键词与本地语义混合检索，本轮修复其候选选择和原文摘录；没有新增固定云端模型轮次、改变默认模型或要求重读全书。

## 采用的方法与理由

参考两份一手技术材料：

- [Anthropic：Contextual Retrieval](https://www.anthropic.com/research/contextual-retrieval)：语义检索可能遗漏精确标识与术语，结合词面检索并融合、去重候选，同时关注片段的上下文。
- [Qdrant：Hybrid Queries](https://qdrant.tech/documentation/search/hybrid-queries/)：用结果排名融合不同检索通道，避免直接相加量纲不同的原始分数。

本软件原本就在节点级采用排名融合；发现页级选取仍优先塞满语义页，会丢掉精确条件。因此保留现有轻量本地模型、数据库和范围验证，将去重与互补选择落实到章节候选、原页和页内摘录。没有迁移到远程向量库，也没有自动为每页增加一次LLM补上下文、查询改写或重排调用。公开材料的实验收益不套用于本软件。

## 修复的学习问题

### 1. 同一章节的大量相似片段挤掉别的相关小节

旧语义检索对所有片段取全局前列。同一长页出现大量高相似度片段时，可能占满候选，另一个相关小节根本进不了节点排名。

新候选池按当前有效阅读记录分组，每组保留最多3个不同原页的最佳位置，先让保留组各贡献一个位置，再补其他原页。默认候选上限24时，最多保留24个已完成组及一个当前组，每组最多3页；原矩阵仍分批计算，不把全书向量或原文装入缓冲。输出候选数量上限、原模型、相似阈值和自动引用门槛保持原规则。

受控复现：一章一页有40个高相似片段，另一节有一个相关位置；旧结果6个命中来自同一页，新结果2个命中来自两个小节。这里是人为固定相似度的行为复现，不是模型准确率排行榜。

### 2. 语义页挤掉精确条件页

旧原文回查拿到3个语义页后，不再为词面匹配的页留位置。现在按词面与语义排名融合页候选，保留最强词面页和最强有效语义页；页数预算允许时，用邻页替代较弱候选以带入定义或证明条件。

受控复现：查询标识只在PDF第9页，定义在第8页，语义候选在第3、4、5页。旧参考提供3、4、5页，缺少关键条件；新参考提供3、8、9页，同时保留语义线索、定义和精确条件。页码与片段来源继续逐项记录；这不能保证任意证明所需的全部前提都在3页内。

### 3. 找到同一页，仍可能裁掉页尾条件

语义位置原先优先决定摘录起点。现在，同页存在真正的词面命中时，使用现有的有界词面窗口选择；没有词面命中的同义改写，继续使用经指纹验证的语义位置。

受控长页例：原查询的精确条件在约4700字符之后，旧摘要位置在页首；新摘录包含页尾条件并记录真实字符范围。英文按完整单词边界匹配，不把 `eat` 当成 `repeatedly` 的词面命中。后者在改进后的交叉检查中暴露，已增加测试并修复。

## 保留的边界

- 手动引用先限制允许节点，再检索；未读、未确认范围、过期阅读版本不作为正文证据。
- 仍需验证语义片段的阅读ID、页码、连续字符区间和文本指纹。伪造或范围外的命中被忽略，不能借排序扩大读取。
- 只处理已经授权、已经保存的阅读内容；不为搜索自动OCR或通读未选择章节。相关未读目录仍只提示位置。
- AI图像核对、AI导航笔记与原页提取文字继续分开标明；词面命中不等于原资料正确，OCR公式也不能因此被认证。
- 用作完整重点讲解的节点仍提供全部所选范围；本轮只改参考背景的候选和有长度上限的摘录，不用3页搜索结果替代整章。
- 全局共享书籍，聊天与对话引用选择仍按原规则隔离。索引不写聊天记忆或学习能力评分。
- 已有有效向量、阅读笔记和任务保留，无需重新下载语义模型、重建全部索引或重新通读。

## 具体检验

### 复现与原生请求

- 最初8项检索平衡场景在修复前为6失败／2通过；新增同页页尾条件场景另有1项修复前失败。原始XML和旧函数源码保留于 `build/knowledge-retrieval-20261021/`。
- 新增12项检查覆盖：章节候选被挤出、同页重复、候选上限和排序、小页数预算的精确条件、邻页定义、范围及指纹、长页尾、英文子串，以及实际导师与DOCX写作请求。
- 原生导师聊天与DOCX生成检查均走真实应用数据准备和HTTP请求编码，云端返回使用受控传输。两者的请求确实含“除数必须非零”的原文及相邻定义，手动范围外章节没有进入；生成了可读ZIP结构的DOCX，没有习题。它们验证资料进入请求，不作为真实模型教学能力证明。

### 真实本地模型与已读扫描教材

- 使用实际固定版本的 `Xenova/multilingual-e5-small` 本地ONNX模型，5个跨领域改写查询全部目标进入前三，其中4个第一、1个第二。数学一一映射和主动回忆两问在纯关键词模式下没有目标命中，混合模式能找到。语义开关关闭和不相关查询也检查通过。
- 这5份材料是合成的已保存文本，不是5本书实际通读，更不是新的云端回答质量测试。模型输入和详细结果见 `build/knowledge-retrieval-real-20261021-2/report.json`。
- 同一保存语料使用真实本地模型交替运行旧／新算法，共10次本地搜索；5题目标排名均保持一致，部分同页重复位置减少。这里没有实际排名提升，不将受控复现的改进冒称五题准确率提高。见 `build/knowledge-retrieval-real-comparison-20261021-1/report.json`。
- 复用了此前已获准阅读的真实《高等代数》扫描教材“数域”记录，在独立数据库中索引和查询。3个问题的参考仍限定在PDF第6、7页，没有新增OCR、云端理解调用或读取其他未选章节。见 `build/knowledge-retrieval-real-book-20261021-1/report.json`。
- 此进程加载本地模型后的工作集约446MiB，关闭释放后约81.6MiB；模型仍有明显内存成本。本轮没有降低模型体积，也没有证明全软件内存问题解决。

### 候选缓冲负载

默认24个候选，输入10,000组、120,000个合成片段：保留完成组不超过24，当前组不超过3页，总保留位置边界75；本机纯缓冲处理约0.142秒。清空Python自由列表后，追踪的Python分配峰值28,453字节。

这个数字只测候选缓冲，不含数据库矩阵、ONNX、分词器、OCR或整个应用RSS；不是端到端检索耗时或全应用内存降幅。保留旧函数的完整对照见 `build/knowledge-retrieval-balance-20261021-4/report.json`。首个对照脚本没有对旧函数注入相同受控编码器，导致该次实验无效；已修脚本，失败目录保留，不把它计入产品结果。

## 打开与使用

1. 托盘彻底退出旧StudyForge，打开工作区的 `验收最新版.vbs`；现有安装版EXE尚未替换。
2. 全局书库→智能检索→选择“关键词＋本地语义”。这台电脑已有本地模型，已有完成页可以继续使用；内存紧张时可保留“仅关键词”。
3. 输入概念或问题，点击结果定位章节；需要引用时使用当前对话的自动参考或手动引用。原页摘录、阅读疑点和省略提示继续可查。
4. 手机连接同一最新版后刷新，公共壳已更新v62。两端共用索引和检索开关；对话的引用模式仍各自保存。

本轮可打开：`build/knowledge-retrieval-acceptance-20261021/知识库混合检索与条件保留验收.html`。报告会显示三组实际本机旧／新结果、真实本地模型查询、原文片段及界面截图，方便下次开机验收。没有打包，也没有把模型“检索命中”当成“已学懂”。
