## 普通聊天也能明确指出卡在哪一句

已完成导师回答底部新增“针对这段追问”，与“保存为成果”放在一起。点击后查看已保存回答原文，支持翻段、跳到后半部分、选取具体原句；手机有同样的入口。

一次显示 4000 字符；最多选择 3000 字符的原句，另附前后各最多 700 字符。7000 字符以内的短回答可以整条引用，更长的回答需要明确选段。原文窗口保留公式记号，便于选中同一条实际记录；不是重新解析教材。

点击“使用选中原句”后，输入框上方显示引用，可以修改或取消。继续在原输入框写自己的疑问，发送后才启动导师回答。选句本身不请求模型、不自动出题或生成文档。引用会增加相应请求中的定位上下文，不能将“选句零模型请求”理解为后续回答零 token 成本。

引用草稿按项目和对话分别保存在当前设备，切换或重开可以继续。发送后，问题旁保留可展开的引用快照；已保存的引用可以随后续聊天和文档任务快照恢复。不需要再手动复制整篇回答。

## 内容与记忆边界

- 发送前核对原项目、原对话、回答身份、完整内容指纹及 Unicode 字符位置。重复句子靠位置区分；换行和补充字符不会使选句错位。目标回答变化时要求重新选择，不静默引用新版或其他对话。
- 学生的问题在消息表中保持原样，AI 原句与附近上下文另表保存。公开历史和冻结文档快照携带引用，提供给模型时明确标为历史 AI 内容，可能有错误。
- 引用不是学生作答、已掌握证据、教材原文或新的工具授权。原回答中的指令不随引用取得权限。
- 学习画像整理优先用明确引用的原句定位知识点，避免误用最近一条不相关的导师回答；证据原话仍仅来自学生自己的问题。引用和翻段本身不产生掌握分或学习判断，无关操作不进入画像。
- 历史快照保留当时的原句，不因以后修改或删除目标回答而假称已核对新版本。删除引用问题或清空历史时，数据库关联随消息清理。

## 修复聊天模型连接释放

复现了正常完成、模型报错、取消和准备失败时未主动关闭当前客户端的问题。修复后，公开聊天入口负责本次客户端的清理，完成或结束流时释放连接；准备失败也清理已经创建的客户端。清理异常不覆盖原输入错误或模型错误。

五项对应检查通过，包含实际 DeepSeek 客户端与受控 HTTP 传输，确认底层 HTTP 客户端关闭。其他正在运行的任务拥有自己的客户端；关闭本次连接不会删除公开聊天或按对话保存的内部状态。

这项修改解决已复现的资源生命周期缺口，没有测出整个软件 RAM 下降比例，也不代表所有长视频、扫描书籍或云模型任务已经提速。

## 真实回答观察

三道题在采样前固定，使用 DeepSeek Flash／high，工具与联网关闭。两道普通导师追问、一份文档实际输入构造各两版，共六次真实模型请求，每臂一次，没有重复抽样或盲评。模型、推理强度和教学规则相同，差别是是否附带用户明确选择的原句。

未附引用的问题本身可能有指代歧义，解释最近一步也可能合理，不能统一判成模型错误。引用版也没有普遍更短或更快。

残余问题原样保留：极限追问又重证了矛盾；Python 的“等号创建对象”最好明确为右边列表表达式创建对象；能量文档的“这些条件才保证”容易夸成每项都必要，转换为公式排版的原文引文不再逐字一致。本轮没有因此再次加长共同教学提示词，也没有把六份样例当作所有学科质量认证。

## 最终功能核验

两组最终相关程序检查共 **156 项去重通过**，分别为 **94 项**和 **62 项**。覆盖原句、坐标、内容变化、长窗口、对话／项目隔离、历史分页、冻结文档上下文、完整原文、学习画像证据、模型状态、答案隔离、项目清理、手机访问、指南与聊天连接释放。

原有一条冻结上下文测试依赖已经过时的提示标题“原资料全文”，改为通过实际原文内容找到撰写请求；完整历史、原文首尾、全文出现次数、任务配置与冻结快照校验全部保留。

最终 **5 项实际电脑端／配对 HTTPS 手机尺寸交互通过**：

1. 长回答后半段原句选择，Unicode 与 CRLF 坐标准确，选句零模型请求。
2. 引用草稿按对话隔离，切换与重开后恢复。
3. 引用进入真实聊天流程，学生问题保持原样，已存记录重开不重新请求。
4. 手机选择窗口、整条短回答引用、发送与历史显示，390 像素宽度无页面横向溢出。
5. 引用本身不建立掌握分或画像判断，控制台无错误。

界面检查使用真实应用页面、后端、数据库和 HTTPS 配对，但模型传输受控，共两次受控请求，没有外部 AI 调用。手机部分没有重新使用真实安卓设备验收，也未验证所有第三方模型账号。
