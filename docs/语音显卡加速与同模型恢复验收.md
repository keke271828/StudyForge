# 语音显卡加速与同模型恢复验收

2026-10-12。继续检查新视频首次处理；本轮直接测量本地真实课程音轨，没有调用收费云端模型。本轮源码完成，未重新打包。

## 实现

### 设备选择确实影响执行

在“设置与联动 → 模型与语音”新增“语音识别设备”：自动、CPU、优先 GPU。自动及优先 GPU 只有在显卡、运行库及隔离执行自检通过后才使用 CUDA；CPU 明确使用原 CPU 路径。

“检测语音识别设备”读取当前未保存的模型与设备选择，返回实际可用设备及回退理由，不偷偷保存配置。修复了异步设置刷新覆盖这些未保存选择的问题。保存后用于之后的识别；不声称已保存的旧转录随设置自动重做。

补齐界面中原本缺少的 medium、large-v3、large-v3-turbo 选项，和已有后端模型白名单一致。默认模型仍为 small，没有通过缩小模型获得提速。

### 本地缓存优先，同模型恢复

原加载器用模型名加载时可能再次访问 Hugging Face 查询，即使完整模型已在本机。新加载器先以 `local_files_only=True` 加载；只有明确缺少本地文件才下载所选模型。损坏、执行错误不被伪装成缓存缺失，也不换模型。

删除原来的隐式 tiny 降级：所选模型失败时给出所选模型与环境提示，保留原资料。GPU 加载或识别出错时，使用同一个模型在 CPU 完整重试；中途产生的部分 GPU 转录被丢弃，不混入完整 CPU 转录。没有改动语言、VAD、beam size 5、完整音轨或采样率。

GPU 使用 `int8_float32`，本机原 CPU `int8` 实际也采用 `int8_float32`。相同模型和参数仍不能保证不同设备转录逐字一致。

### 控制内存与自检生命周期

- GPU 自检在隐藏的短期子进程中运行，不把源音轨或聊天发给它。子进程只处理一秒静音，检测库、驱动和模型能否实际执行；失败或超时回 CPU，不能据此推断教学或转录质量。
- 自检不下载额外模型；缺少本地所选模型时，主任务仍按所选模型正常准备。本机 GPU 能力和模型／运行库条件参与缓存，自检结果与失败冷却有界，检查不会无限累积。
- 同一时间不启动多份 GPU 自检；模型设备改变或切换 ASR／OCR 时仍释放上一引擎。120 秒空闲释放策略及本机重计算限流保持。
- 没有开启大批量语音并行来占更多内存，也没有改变系统代理、驱动或注册表 PATH。CUDA 路径只加入应用进程及其自检子进程。

### 真实状态保存到两端

任务“耗时详情”显示实际模型、CPU／GPU、精度、完整音轨长度及恢复说明，将语音整体拆出本机识别引擎等待、模型加载／设备核验、完整音轨识别。整体包含分项，不可重复相加。

这些信息是来源正文以外的小执行记录，保存在任务计时表；工作流完成时覆盖普通结果不会丢失。多次音轨识别时显示最近一次，不冒充全任务的唯一识别。已删除任务不能因迟到记录重新出现。没有把音频内容、文件路径或答案写进这些记录。

## 本机实际环境与组件

实际检查：RTX 5060 Laptop GPU，8151 MiB 显存，约 16 GiB 系统内存；faster-whisper 1.2.1、CTranslate2 4.8.2。最初驱动可见，但 CUDA／cuDNN 运行库缺失，不能把“发现显卡”当作“加速已可用”。依照 [faster-whisper 官方 GPU 要求](https://github.com/SYSTRAN/faster-whisper#gpu) 配置 NVIDIA 运行库。

从 NVIDIA 在 PyPI 发布的 Windows wheel 准备 cuBLAS 12.9.2.10、cuDNN 9.27.0.42 和 CUDA runtime 12.9.79。大文件逐段验证范围及最终 PyPI SHA-256，证书校验保留；只针对这些固定公开依赖使用可用的直连下载，不修改全局代理。原来镜像／代理通道的超时没有被当成下载成功。

通过校验的组件和许可证在 `resources/asr-cuda`，合计约 1.93 GB，仅为应用私有运行库，没有全局安装或更新驱动。构建脚本在存在该可选组件时保留相对路径一并复制；本轮没有重新构建安装包。没有组件的环境仍用 CPU。开发准备脚本为 `scripts/prepare_asr_cuda.py`，组件二进制不纳入 Git。

## 实际音轨对照

取用户此前指定本地课程的三个完整 60 秒片段（开始于 0、300、900 秒），不是合成语音。分别在独立进程中测试 CPU 和 GPU；使用相同 WAV SHA-256、相同 small 模型文件 SHA-256、相同识别参数及 4 个 CPU 线程，没有同时运行另一个重计算实验。

| 实际识别 | CPU | GPU |
|---|---:|---:|
| 0 秒起的 60 秒片段 | 18.90 秒 | 19.38 秒 |
| 300 秒起的 60 秒片段 | 22.84 秒 | 3.64 秒 |
| 900 秒起的 60 秒片段 | 17.61 秒 | 3.25 秒 |
| 三段识别总计 | 59.35 秒 | 26.27 秒 |
| 模型加载 | 1.95 秒 | 4.58 秒 |
| 独立测试进程峰值工作集 | 732,078,080 B | 854,659,072 B |

三段识别总计减少约 55.7%，但首段 GPU 初始化并不更快。GPU 测试进程峰值工作集增加约 123 MB，因此没有称总 RAM 已下降；单次工作集测量也不包括整个 Electron 应用或所有并发任务。

记录：[CPU 实测](../build/asr-quality-performance-20261012/asr-cpu.json)、[GPU 实测](../build/asr-quality-performance-20261012/asr-cuda.json)。模型文件 SHA-256 为 `3e305921506d8872816023e4c273e75d2419fb89b24da97b4fe7bce14170d671`。所有对照均为本机识别，外部模型调用 0。

### 文字质量不能只看参数或相似度

逐段比较完整文字：分句边界和少量字词不同。忽略空白、部分标点后，三段文本相似度约 98.9%、97.8%、93.0%；这不是人工金标准准确率或词错率。

GPU 把 CPU 的“雷泰克斯”“带玩格”等改为 LaTeX／单元格，部分更好；首段 GPU 又将 CPU 识别为 caption 的词写成 Captain。两种设备都还存在“自动补给”“双数信心”等疑似识别错误。因此没有宣布 GPU 质量完全等同、必然更好或学习原文可免核对。应用保留原音画及既有画面核对，录音发送前可修正文字，CPU 仍可选择。

完整对照见 [转录文本](../build/asr-quality-performance-20261012/asr-text-comparison.md) 和 [逐段差异](../build/asr-quality-performance-20261012/asr-text-comparison.json)。没有用模糊匹配后的文本替换实际输出。

## 完整软件路径

同一份 300 秒起的 60 秒 WAV，又分别通过实际 `media.transcribe` 测量，包括音轨提取、排队、模型载入和设备检查。

| 一次完整转录调用 | CPU | 自动选择 GPU |
|---|---:|---:|
| 总耗时 | 32.43 秒 | 17.73 秒 |
| 实际模型 | small | small |
| 实际设备 | CPU | CUDA |
| beam size／完整音轨 | 5／60 秒 | 5／60 秒 |

这个应用路径样例约快 45.3%。GPU 自检与初次加载约占 12.56 秒，实际识别约 4 秒。记录：[完整 CPU 路径](../build/asr-quality-performance-20261012/pipeline-cpu.json)、[完整 GPU 路径](../build/asr-quality-performance-20261012/pipeline-cuda.json)。它们不是完整视频下载、全部 OCR、云端讲解或 DOCX 总时间。

## 当前边界

本轮改进语音部分，不宣布完整 40 分钟视频、所有书库扫描、云端长文生成、整机内存或所有教学质量全部通过。不同显卡、口音、噪声、学科术语和大模型尚未做完整金标准测试；设备自检只保证当时可执行。本机资源缺失或变化时明确回退同模型 CPU，避免将菜单中的 GPU 选择伪装成实际使用。
