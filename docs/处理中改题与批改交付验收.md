# 处理中改题与批改交付验收

2026-10-26，源码更新，未重新打包。

## 发现与修复

前一轮解决历史题单变更后的按题回看。这一轮继续核对任务运行过程中改题的情况：三个真实流程的受控复现均失败，分别为补讲时改题、排版时改题和代码审查时改题。原实现仍会交付批改文档或保存编程成绩。

新增共用的本机题单检查，比较题干、参考解（包括编程测试代码）、难度与项目归属；标题和正常流程状态不属于题目版本。客户端准备完成后、评分或补讲准备开始时，以及各自完成后重新核对；原题解析与最终批改排版后、登记成果前也核对。编程判题结束后先核对，再决定是否开始代码审查；成绩保存时在同一个BEGIN IMMEDIATE事务中再次检查，防止检查和保存之间被另一写入改变题目。编程结果另存紧凑的版本指纹，该指纹只记录输入身份，不证明评分正确。

普通习题评分原来已经有事务版本检查，本轮保留。已正确保存的原评分属于有效历史证据，不因之后补讲中断而删除或重复记录；尚未形成可靠成绩的阶段不写入成绩和画像。新版本检查失败使用ReviewVersionConflict，沿用既有非自动重试分类，不把改题问题当网络问题反复请求模型。

恢复历史原题的函数仍只用于阅读，不被拿来给当前变化后的题单继续批改。两端既有版本提示、旧问卷和后续行动限制继续生效；指南补充中途改题的处理说明，手机静态壳更新到v83。

## 打开方式与凭据

先从Windows托盘完全退出旧版，再双击项目根目录`验收最新版.vbs`，无需CMD。当前0.4.4安装包没有包含本轮修复。

可打开报告：`build/homework-inflight-acceptance-20261026/处理中改题与批改交付验收.html`。

- 最终回归与指纹：`build/homework-inflight-final-20261026/command.json`
- 实际两端操作：`build/homework-inflight-ui-20261026/ui-report.json`
- 处理中改题的提交/评分/交付凭据：`build/homework-inflight-ui-20261026/inflight-evidence.json`
- 汇总：`build/homework-inflight-acceptance-20261026/result.json`

脚本为`scripts/verify_homework_inflight.py`、`scripts/run_homework_inflight_ui.py`和`scripts/report_homework_inflight.py`。复跑请指定新的build目录，保留已有证据。
