# 讲解质量与视频提速验收

2026-10-10。当前源码已更新，本轮没有重新打包安装程序。任务范围是讲解质量、视频理解与生成效率及相关实际故障；全局电子书知识库按用户要求暂缓。

## 1. 如何打开与验收

1. 从 Windows 右下角托盘完全退出旧版 StudyForge。只关闭窗口会继续在后台运行。
2. 双击项目根目录的 [验收最新版.vbs](../验收最新版.vbs)。不需要留着 CMD 窗口。
3. 在工作台选择 DeepSeek、实际可用的模型，以及希望使用的推理强度。数学证明验收建议选“直观与专业并重”及“快速”，不勾选同步出题。
4. 比较构造之前是否讲清目标与障碍，是否解释选择的合法性、端点与量词、统一下标，以及替代构造。检查文档中的公式是否正常显示。
5. 对视频可以沿用已经成功解析的资料。新生成仍是新的模型请求；未重新转录的复用不等于首次导入时间。

## 2. 教学与格式改进

### “直观与专业并重”

导师对话、讲解生成及补讲共用规则，重点是：

- 先说明实际对象、目标与障碍，再解释为什么选这种方法。
- 在关键构造旁交代合法性及其作用，而不是先摆公式、最后笼统赞叹。
- 用直接的几何图景或完整例子帮助理解，再接上可复现的正式推导。
- 把量词、条件和范围放在对应步骤附近；不把方便的构造写成唯一方法。
- 例子、迁移线索和总结也保留条件，不在正文之外重新引入已纠正的错误。
- 长资料之后再加一段简短的本次风格提醒，不新增一次模型请求。

数学样例具体解释了为何可从“任意正容差”中选定特例、为何两个开邻域在半个间距时仍不相交、为何取最大下标门槛，以及取其他正容差或不等半径时如何改变边界位置。

没有照搬用户提供的网页回答中的误述：对于两个严格误差界，正容差之和不超过间距即可制造矛盾；这里的等号可以成立。较小的相同半径仍然对称，只是两个边界不再汇合成同一个中点。这些是对示例的数学核对，不是把网页回答当作绝对标准。

实际共享提示词见 [AI导师提示词](AI导师提示词.md)。提示词改善的是教学约束，并不保证模型每次都遵守或数学判断绝对正确。

### 快速核查

“快速”保持每个讲解部分一次综合核查。核查响应可以携带最多8处、具有唯一原文锚点的小范围修正，不另发全文重写请求；引用、标题与代码围栏受到保护。无法定位或尚有争议的修正不强行应用。

已局部修正的问题以简短核查说明呈现；未解决的问题继续标注。完整审查结果保留在任务记录中，不另行导出用户没有要求的审查成果文档。

“快速”不是三轮独立审查，也没有实现自动反复审查到绝对正确。数学验收中仍发现模型漏查的边界及量词问题，复核版对其做了额外的明确修订。

### 实际排版与总结故障

- 粗体中的 LaTeX 继续解析为原生 Word 公式，不再留下裸公式编码。
- 代码里的 `|` 以及后面的 `---` 不再误判成 Markdown 表格，也不会把正文吞进单列表格。
- Word 表格跨页重复表头，并防止表头孤立在上一页底部。
- 不同编号列表使用独立计数，保留起始编号；PDF 不再丢掉编号。
- 总结输入在篇幅允许时使用各部分完整讲解，不只使用可能有遗漏的小结；较长输入明确注明节选及遗漏范围。
- 总结内部使用同级标题时，软件保留所有小节并调整层级，不再只截取开头一段。
- 总结请求强调覆盖所有传入部分；不把最后一部分小结充当全文总结。此次视频的三个部分已在新总结中串联。

## 3. 视频处理为什么能提速

旧实现反复逐帧发送请求，画面分析还会重述已经识别的普通文本甚至提前长篇讲解。大量重复内容又被传到后续写作，增加等待时间与输出负担。

现在对支持多图的原生服务分批读取，每批最多4张，要求分别返回每张图的客观识别及重要纠错。原始 OCR 与语音转录另行完整保留；不让每帧识别变成一段教学文章。

处理过程使用少量工作协程和已有全局模型并发限制，不为所有页面提前建立携带 Base64 的并行请求。失败或遗漏图像单独重试，不重复全部画面；识别结果按图像、位置、模型、推理强度和策略版本校验后缓存，原画面变化会失效。

这个缓存复用的是客观资料识别，不是跨项目共享聊天历史。画面识别与后续生成都遵循实际选择的服务、模型和推理参数。

本轮没有减少同一视频样例的抽样画面，没有降低请求模型或其推理强度，也没有将完整转录替换为资料库预览。视频本来就使用抽样画面，并未实现逐帧观看所有视频帧。

924.55秒的冷缓存测试验证主要提速路径，发生在最终总结及排版小修之前。后面的验收没有重新跑完整冷缓存流程：

- 视频讲解改写复测使用已有识别缓存，且中断后恢复，记录中的148.5秒只属于恢复后的运行，不能当成新冷启动耗时。

- 额外成功生成全文总结用时24.08秒，单独记录。此前失败的范围检查也消耗了请求，不能把本轮所有验收的累计用量说成只有一次请求。

## 5. 教学验收与真实内容边界

数学样例的4个位置与4块原文引用均机械匹配；视频样例的56个位置均匹配，53块引用中50块匹配，其余3块仍显示“来源定位需核对”。位置和引句匹配只能验证来源关系，不证明讲解论断、推导和覆盖绝对正确。

另外查看了200、600、800秒附近原始视频画面，对照识别结果。主要代码及表格结构能对应；200秒附近识别对选中行的描述仍有偏差，所以不能声称所有视觉细节正确。

视频复核版纠正了竖线数量、注释行数、合并跨度与题注编号等技术细节。补充说明使用实际核对的原始项目源码：编号由普通 `\caption` 推进计数器，见 [LaTeX题注源码](https://raw.githubusercontent.com/latex3/latex2e/develop/base/ltfloat.dtx)；单元格中的 `\vline` 与 `\multicolumn` 的跨度，见 [LaTeX表格源码](https://raw.githubusercontent.com/latex3/latex2e/develop/base/lttab.dtx)；空白命令的实现，见 [LaTeX间距源码](https://raw.githubusercontent.com/latex3/latex2e/develop/base/ltspace.dtx)。这些是补充核验，未冒充视频原文。

两份最终 DOCX 均通过独立、只读的 Microsoft Word 进程实际打开并渲染：数学7页、视频37页。数学正文含202处原生公式，普通段落无残留的 `$` 或 `\varepsilon` 编码。整份PDF的文字边界检查无越出页面记录；另查看页面图，核对公式、引用样式、表格和最终总结。完整图片与记录保存在各自 `word-review` 或 `final-word-review` 目录。
