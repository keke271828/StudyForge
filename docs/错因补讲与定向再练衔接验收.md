# 错因补讲与定向再练衔接验收

2026-10-13。继续优先改善学习流程。本轮适用于普通习题，未重新打包；编程作业继续使用原有编程判题与费曼／进阶入口。

## 找到的实际缺口

原流程已将逐题错因和补讲保存到作业记录，并附入提交记录，但“同难度修复练习”仅取分数、简短反馈和暂定诊断，未完整接上逐题补讲与学生填写的错因。

另一个使用问题是：手机的再练入口按低分状态显示，总分较高但仍有错题时可能看不到入口。现在工作台作业反馈和手机详情均可主动请求再练，不以总分低于80为唯一条件。

## 新流程

1. 完整提交作答，先取得原题与参考解析；现有批改、问卷与错因补讲继续执行。
2. 错因不明时先填写问卷；新入口不跳过等待。选择原有费曼流程的题单先完成费曼环节。
3. 在电脑工作台作业反馈记录，或手机作业详情，点击 **按本次错因同难度再练**。
4. 每个失分项对应一道新题，保持原难度，要求写出关键理由或步骤；只错一道就针对这一道生成，不额外扩成默认四至六题。
5. 新题单在电脑、手机和 Word 中标明对应的原题。解析及私有的检查重点仍在完整提交后开放。

阅读、看完补讲、打开作业记录都不会自动出题。新成绩保存为新题单的作答，不覆盖原来的分数，也不直接替代学习路线中的完整三维检查。

## 教学依据与隔离

- 只采用同项目、同题单、同一份完整作答、同一题目版本、同一提交编号且已完成的错因分析。
- 将本次作答支持的暂定定位、学生自报、尚未确定的原因分别保留。历史画像的疑问不能单独变成“这次一定因为不懂某概念”。
- 传递对应失分项的原题、评分依据、有效证据、错因、补讲片段和自查方法。长补讲只传前4000字符并明确标记节选；不会假装看过剩余部分。
- 原因未明时按原题知识要求设计能展示推理的题目，不给学生定性。证据引句重新对照本次作答及本题问卷，其他题与其他项目的数据不可冒充。
- 继续读取可用原文件，不使用资料预览摘要替代。原文件不可用时明确限定为已提交的原题和参考解。
- 私有修复目标及解析独立保存；公开接口只给对应题号、知识点、依据类型与难度，不公开解题线索。

生成题目的目标编号、知识点、题数与私有检查重点有本机结构校验；不满足时不发布。它能防止漏题、错贴目标和完整原题复用，不能独立认证新题的语义质量或学生的迁移能力。出题要求优先选择最小充分情境，避免为了变化而堆积复杂条件。

## 持久化、复用与修订修复

参考记录包含原题版本哈希、作答哈希、提交编号及逐题目标。新建独立的修复上下文表，旧记录不清除。

同一依据下重复请求复用已完成题单，不重复付费出题。原题、评分或错因依据变化后不冒用旧对应关系；旧成果保留。旧版没有目标记录的通用修复题不会被直接贴上新的验证标签。任务步骤按参考签名区分，暂停恢复继续检查对应关系。

真实模型试验发现：专门修订题目时，原修订提示只要求基础字段，未携带新情境／错因修复的完整约束，可能在修正题意后丢失目标字段，直到完成后面的独立求解与核查才失败。

现在修订步骤本身接收完整约束并立即校验。题干未改动时，从原题恢复它自己的附加字段，避免不必要的模型格式修复；题干发生变化时，须提供与新题相符的字段，缺失就在此步骤修正，不再先支付后续复核。此修复同时覆盖新情境检查；不为重排后的题目凭位置猜测目标。

本轮没有增加固定审查轮数，仍使用设计、独立求解及现有核查。实质问题触发的有界修订和格式修复仍可能增加实际请求，不能把“通常四步”说成“永远四次模型调用”。

- **127 项相关回归通过**：修复练习、作业、批改质量、新情境、任务流程、项目彻底删除及指南。
- 修订流程修复后另有 **65 项关联回归通过**；最终 **6 项前移校验／指南检查**与 **1 项答案释放专项**通过。上述组有重叠，不累计成总数。最终专项覆盖未改题干直接恢复字段、改题干先修正字段再继续求解，两种情况分别应用于错因再练与新情境题。
- **5 项实际 Electron 桌面与配对 HTTPS 手机交互通过**，见 [结果](../build/repair-learning-ui-20261013-2/ui-report.json)。95分的合成作业也可从工作台主动再练；只生成对应一处失分的一题；保持难度与自报边界；手机复用同一成果、不额外调用模型；手机可下载实际 Word。
- 界面夹具使用4次模拟模型响应，外部模型调用为0；数据库、原生HTTP请求、排队、配对与导出实际执行。截图已实际查看：[电脑入口](../build/repair-learning-ui-20261013-2/desktop-repair-entry.png)、[手机题目与依据](../build/repair-learning-ui-20261013-2/phone-repair-reference.png)。
- 测试确认提交前没有新题解析或私有检查重点；新题完整作答后才开放它们，原题95分保持。Python编译与相关JavaScript语法检查通过。
- 测试全部使用独立数据目录；没有用合成成绩修改用户实际数据库或学习画像。新表沿用现有外键归属及项目删除流程。

## 真实模型试验：保留失败及限制

模型为实际 DeepSeek `deepseek-flash`，推理 `high`，素材为合成高斯定律材料及模拟95分作业；没有评估真实学生的能力。

1. 首次连接中断，约31.86秒，0份完成响应，见 [报告](../build/repair-learning-real-20261013-1/report.json)。
2. 第二次完整试验实际调用8次，约304.68秒。初稿参考解有实质问题被现有核查拦下，修订后的内容通过后续核查，但缺少目标字段导致未发布，见 [失败报告](../build/repair-learning-real-20261013-2/report.json)。这次失败用于定位上述修订约束遗漏。
3. 修复后，复用了这次失败试验的初稿与前四步检查响应，重新实际调用模型4次完成修订、独立求解及核查，约124.04秒，导出一题无答案 Word，见 [修订复测报告](../build/repair-learning-real-20261013-revision/report.json)。**这不是一份全新独立设计的成功试验，也不能据此声称整体提速。**

无答案原样样例：[高斯定律定向再练](../build/repair-learning-real-20261013-revision/高斯定律_定向再练_无答案样例.docx)。已重新读取 Word 内容，题干保留、私有字段隐藏；本轮未用 Microsoft Word 打开或渲染，结构检查不等于目标应用排版验收。

我实际读过最终题意、私有解答与核查。它能检查净通量与局部电场的区别，并要求说明理由；仍比均匀电场穿盒子的最小例子复杂。更严格的讲解应说明不讨论点电荷所在的奇点，不能仅由“外部贡献非零”直接断定总场非零；可补充内部点电荷附近的分析，区分某点抵消与整个区域处处抵消。原样实验文件没有被人工改写成“完全正确”的模型输出。

这轮实现了错因到再练的实际衔接，但模型核查通过并不等于全文无误。题目设计与少量作答仍不能证明长期保持、远迁移或整个知识点精通。
