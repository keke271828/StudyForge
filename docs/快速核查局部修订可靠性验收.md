# 快速核查：局部修订可靠性验收

日期：2026-10-14。此轮在 0.4.3 发布完成后继续改进教学交付。**本轮为源码更新，没有重新打包；原 0.4.3 安装包不包含以下改动。**

## 解决的实际问题

复现了快速审查的程序漏洞：同一条疑点涉及正文和总结多处时，只要一处替换成功，旧逻辑就可能隐藏整条疑点，留下未处理的错误。修复前新增的14项检查中10项失败；记录保存在 `build/review-corrections-before.xml`。

同时发现旧逻辑只防止修改包含“[来源”的片段，没有保护常见的 `[教材｜第3页]`。模型可以通过替换完整定位或其中的书名、页码，意外改写来源。不同问题的修订发生重叠时，原逻辑还会受返回顺序影响。

## 新行为

- 同一 `issue_index` 的全部替换整组应用。任一处原句不存在、含糊、越界或结构损坏，这一组不应用，疑点继续显示。
- 有重叠的修订两边都保留疑点，不以模型返回顺序决定采用哪一个。其他可独立应用的完整修订仍可生效。
- 超过8处的返回不截断成“部分修好”；不能归属到有效问题的替换也不被悄悄忽略后隐藏提示。
- 保护原文引用、章节标题、来源名和页码、英文定位、网页链接；即使替换只命中定位内部的一小段也要核对。包含未改变来源定位的段落可以修订其解释文字。
- 未配对的代码块、独立公式块及不可显示字符会阻止相应替换组应用；不把这些机械检查当成完整 LaTeX、论证或事实验证。
- 正文、保存的任务快照和最终 Word 的疑点状态一致。核查报告原样保留，应用替换不把原报告的 `passed=false` 改成已经复核通过。

以上在本机进行。正常快速核查仍只需原有一次综合核查，没有增加自动审查轮次或全文重写请求；极速、平衡和严谨的原有流程保留。软件内指南已解释“已局部修正”与再次独立复核的区别。

## 验证与真实模型结果

分轮回归去重为 **198项**，包括修订分组、来源保护、格式、Word完整生成、保存记录、其他格式、原有教学及批改相关流程。最终受影响范围又完成84项检查；各轮有重叠，不把运行次数相加当作新增用例。

| 范围 | 记录 |
|---|---|
| 第一轮169项关联回归 | `build/review-corrections-final.xml` |
| 指南2项 | `build/review-corrections-guide.xml` |
| 渲染与交付123项复测 | `build/review-corrections-render-final.xml` |
| 最终修订／公式／指南84项 | `build/review-corrections-last.xml` |
| 去重、最终源码指纹与6份真实返回回放 | `build/fast-review-20261014/最终核验记录.json` |

真实模型使用 `deepseek-flash`、high、API直连，工具关闭。复用上一轮保存的3份回答，修复前后各核查一次，共 **6次真实核查请求**，均取到完整返回。

1. 有错的高斯定律讲解：两轮都发现“净电荷零等于没有场源”和“必须有极强对称性”两处实质错误，并应用局部替换。
2. 人工检查未发现实质错误的物理回答、柯西不等式证明：两轮均保持原正文逐字不变。
3. 最终程序又回放以上6份真实JSON返回，输出与已保存核查结果一致，新增模型请求为0。

**这不是模型识错能力提高的证据。** 修复前也找出了上述两处错误。本轮解决的是程序可靠应用修订的问题；分组定位失败等漏洞通过受控样例复现，没有在这6次返回中自然出现。实际高斯讲解中账目比喻“每一笔都不是零”仍不精确，因为例子四个侧面通量是零，本次模型核查未列出这一处；人工评语明确保留该限制。

## 本机开销

候选实现的压力自检发现，修订结构检查不需要重复解析所有表格单元。为结构保护增加跳过表格单元解析的路径，正常导出仍使用原有默认路径。

在同类合成段落、8处修订的本机测量中，约7万字符的候选检查中位耗时从0.3871秒降至0.0884秒，约88万字符从5.8265秒降至1.1727秒。没有修订时直接返回原正文。这是本轮候选实现内部的局部测量，不是与已安装0.4.3的整软件对比，不代表模型生成、视频总耗时或整软件内存下降；Python临时分配也没有明显改善。记录见 `local-cost-initial.json` 和 `local-cost.json`。
