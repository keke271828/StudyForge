# DeepSeek 独立运行与空内容修复

日期：2026-10-02。本项仅修改源码，未打包；现有安装程序及旧 `.exe` 不包含本项修复。

## 排查结论

源码中的 DeepSeek 直接请求 `api.deepseek.com`，不经 Codex App Server；桌面应用启动自己的本地服务，退出监视器监视 StudyForge 桌面进程。没有发现 DeepSeek 生成必须保持 Codex 窗口开启的硬依赖。

发现并修正了两类问题：若接口漏传服务，部分入口会固定使用 Codex；流式输出也没有充分区分空正文、资源不足、中断、损坏的数据包及完整工具调用。非流式响应则只报告“模型返回了空内容”。本机当前任务记录没有对应的历史失败任务，因此不能证明用户所见那次失败的唯一原因，也不能仅凭关闭 Codex 后失败就断定因果。

## 修改

- 全部学习请求的默认服务、答题文件与代码提交、MCP 批改跟随已保存的服务选择；找不到 Codex CLI 时默认用 DeepSeek。显式选择 Codex 仍按该选择执行。
- 学习工具本身的默认服务也跟随设置，图片读取不再因工具默认值而误选 Codex。源码桌面后台监视 StudyForge 桌面进程，与安装版一致。
- DeepSeek 保持当前所选模型，通读也不再被旧的“质量优先”设置强制改成另一模型。
- 流式和非流式响应共同校验正文、结束原因和工具参数；兼容 `data:` 无空格、单独用量包和 JSON 响应。
- 空正文、输出中断或临时传输错误最多恢复一次；只重试当前请求，保留已完成的工具结果。未完整结束的工具请求不执行；长度上限、服务拒绝不重试。
- 保留服务要求的内部推理字段，但从不将思考记录替代最终讲解。失败不导出空白或截断文档。
- 界面标明 DeepSeek 无需打开 Codex；重试时显示状态并清除半截正文，完成后保留独立的工具状态。
- 生成和通读任务的重试状态也显示在进度卡与顶部状态中；保留原阶段、百分比和暂停状态，恢复后清除重试提示。
