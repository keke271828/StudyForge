# 新情境理解检查与证据分开验收

2026-10-13。本轮优先改善学习判断：原题做对可能包含记住题目或解析的作用，不能据此直接判定能在不同情境中重新论证。新增自愿发起的新情境检查，继续使用现有生成、审查、作业提交和批改流程。本轮未打包，也没有用测试成绩修改实际学习画像。

## 怎样使用

1. 从根目录 [验收最新版.vbs](../验收最新版.vbs) 打开源码；正在运行旧安装版时，先从托盘退出旧版。
2. 在“学习路线”为目标关联本项目原资料，按需发起“三题理解检查”。
3. 完整提交当前范围的一份检查并取得可用评分后，可主动点“新情境检查”。它不要求先通过所有题，也不强制等待三天；是否练习由学生决定。
4. 手机上打开“学习选项 → 自愿检查理解”，选择本项目目标和检查类型。目标在电脑的学习路线建立，手机不必打开完整编辑界面。
5. 在成果或作业区查看单独生成的无答案 DOCX。完整提交后，另行开放解析、批改，以及新题的情境变化说明。

阅读、打开目标记录、查看手机选项或生成讲解不会因此自动布置题目。手机选项按需加载目标，不持续轮询。启动任务保存当时的对话、服务、模型、推理强度、语言与讲解风格；之后切换对话清空旧控件，不把旧目标带入新对话。

## 实际改变了什么

### 1. 保持参考难度，改变题目任务

新任务选取同一目标、当前原文件与目标范围下，已经完整提交且评分不待核实的一份检查作为参考。以实际提交时间、提交顺序确定参考；不会把较晚创建但较早提交的题单误当成最新依据。

参考快照保存三道公开题干、设计维度、难度、原题单与提交编号、题干哈希。这个参考包不附带旧答案、旧作答或批改反馈。当前对话本身已有的学习历史仍按原方式供本对话使用，其他对话历史不引入。

新题保持参考难度，要求实质改变条件、表示、论证或应用任务；不因旧题做完就直接加难。三题依次观察概念与条件、方法与论证、迁移与边界。缺少必要前置时须在题面提供，不能把前置缺口误当作不会迁移。

每题保存私有的情境变化说明，供现有核查检查题意是否真的支持变化。它可能含解题线索，不能进入学生题面；完整提交后才随解析开放。新生成与核查仍走原有四步：设计、独立解题、题意与解法核查、最终发布核查。**没有因此再加一轮模型审查。**

本机拒绝原题完整复用和本题单重复题，保留数学关系符号避免把不同条件误判成同题。这个检查只排除明显重复，不能认证语义上的新颖性；模型的变化声明和审查通过也不是经过校准的迁移测量。

### 2. 分别记录原题记忆与新情境作答

学习路线把“理解检查”“原题复习”“新情境题”分别标注。复习同一份新情境题归为原题复习，不重复算成一次新的情境证据。已有新情境成绩不会被之后的原题复习简单抹掉，但后来的低分、辅助条件和待核实评分仍影响下一步建议。

延迟原题达到教学约定的分数后，若尚缺新情境记录，建议自愿检查变化后的情境，不直接跳到“能力已经掌握”。本轮沿用 80 分教学约定，不声称这是经校准的能力分界；自报未使用提示仍不证明实际无外部帮助。

同一时间的多次提交改用数据库真实提交顺序排序，避免随机编号导致旧分数成为“最新分数”。审查交换未改动题目的顺序时，恢复原题自己的维度，不能为了满足三项顺序把标签错误地重新分配。

### 3. 两类任务可独立进行

同一目标、同一对话、同一检查类型且同一参考的重复点击复用已有任务。普通检查与新情境检查不是同一任务，可以分别排队并使用现有模型并发上限。暂停、继续与成果归属沿用原流程，已完成模型步骤继续复用。

任务针对启动时冻结的资料、目标和参考生成；后来修改范围不能把旧检查成绩用于新范围。手机仅增加读取路线与启动检查的接口，未开放完整路线编辑或电脑设置权限。

## 实际 DeepSeek 抽样与人工判断

用合成的极限定义、唯一性与有限项修改资料及模拟 85 分参考进行抽样。模型是实际原生 DeepSeek `deepseek-flash`，推理 `high`；未调用外部搜索或 Agent 工具，也没有真实学生的能力成绩。

首次请求约 34.1 秒连接失败，0 份完成的模型响应；第二次完成三题设计与现有核查，**4 次模型请求，共约 146.1 秒**。结果见 [实际抽样报告](../build/learning-transfer-real-20261013-2/report.json)，无答案题面见 [Word 样例](../build/learning-transfer-real-20261013-2/isolated-data/artifacts/新情境理解检查_实际模型抽样.docx)。原答案与审查保留在隔离实验目录，不在此页提供直接答案链接。

实际样例已重新读取 Word 文件，三道题干均保留，私有解析与情境变化说明未进入题面。本轮没有用 Microsoft Word 打开或渲染该样例，不能把结构验证说成目标应用中的排版验收。验收页与 README 的本地链接已核对存在；指南入口、Python 编译及涉及的 JavaScript 语法检查通过，见 [交付核对记录](../build/learning-transfer-20261013/delivery-check.json)。

我逐题看过题意、解法与模型核查：

| 题目方向 | 实质变化与教学价值 | 局限 |
| --- | --- | --- |
| 收敛定义的另一种表示 | 在“有限例外”与“尾部全满足”之间转换，要求说明量词和门槛 | 仍属于较近的概念转换，不能外推到广泛应用 |
| 比较失败的半径选择与有效构造 | 解释过大的邻域为什么不能逼出矛盾，再说明统一门槛 | 与原证明仍比较接近；题面已给部分比较信息，独立性有限 |
| 修改有限个数列项 | 对一个具体新数列重新选择门槛，应用极限与唯一性 | 是近距离应用，未覆盖远迁移或长期保持 |

这比只把原题再做一遍提供了不同的证据，但三题设计通过不证明学生理解，题目之间也不是标准化量表。没有用一次抽样声称整体质量提高了某个百分比；146 秒也不是全软件提速或完整长视频性能证据。
