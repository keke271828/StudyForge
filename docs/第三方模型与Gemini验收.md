## 已实现的入口

| 接入方式 | 认证与配置 | 模型及回复 | 图片/视频画面 | 工具与审批 |
| --- | --- | --- | --- | --- |

接入的服务会出现在学习工作台“AI 服务”下拉框中，模型会出现在旁边的“模型”下拉框中。导师、资料通读、讲解、习题、批改和后台学习记忆使用所选服务；文档任务保留启动时的模型与资料范围。原有 Codex 和 DeepSeek 保留。

这三种入口有实际协议差异。某家服务仅提供自己的专有 API 时，不能靠填写一个地址就假定兼容。当前通用入口适用于支持 Chat Completions 的兼容服务；Gemini 另有原生适配。

## 添加第三方兼容服务

1. 点“＋ 兼容服务”。填写你能辨认的服务名称。
2. 填写服务的接口根地址，例如 `https://你的服务域名/v1`。不要填写完整的 `/chat/completions` 路径。远程地址使用 HTTPS；本机 `localhost` 或 `127.0.0.1` 服务可使用 HTTP。
3. 填写服务商提供的 API 密钥与默认模型调用名。模型名称应使用接口实际接受的标识。其他可选模型可每行填写一个。
4. 根据服务实际能力选择“工具调用”“图片读取”和“JSON 格式约束”。无密钥的本机模型可取消“需要 API 密钥”。
5. 点“保存服务”，再点“在工作台使用”。需要读取目录时，在工作台点击模型旁的刷新按钮。
6. 点服务卡片的“检测”，进行一次小量模型请求；它会显示实际请求的模型名称及返回内容。

读取模型目录不生成教学内容。目录失败时保留手动模型并提示原因，不把服务清空。连接检测会使用少量额度。

密钥不保存在 `model-services.json`，不由列表接口返回。编辑时密钥框保持空白，留空表示保留原密钥；勾选“清除已保存的密钥”才会删除。移除服务保留已有对话和成果，但该服务不能继续发起请求。服务有进行中的回复或未完成任务时，先结束或删除任务，再修改或移除配置。

## Gemini API 的使用方式

1. 在 Google AI Studio 获取 Gemini API 密钥。
2. 点“＋ Gemini API”，填写密钥。默认官方接口为 `https://generativelanguage.googleapis.com/v1beta`，默认模型使用 `gemini-flash-latest` 别名。
3. 保存后刷新模型目录，选择当前账号可以调用的型号，再检测连接。
4. 返回学习工作台选择该服务。聊天、通读原文件、生成文档和习题均采用当前选择。

API 密钥的申请与额度由 Google 管理，参见 [官方 Gemini API 密钥文档](https://ai.google.dev/gemini-api/docs/api-key)。模型目录中出现某型号，不等于当前密钥已经拥有调用权限。默认别名会跟随 Google 的服务调整；需要固定型号时请选择具体调用名，参见 [官方模型文档](https://ai.google.dev/gemini-api/docs/models)。

## 使用 Google 账号登录 Gemini

1. 点“＋ Gemini 账号”，先保存服务。
2. 点“安装官方 Gemini CLI”。如果已安装官方 CLI，软件会直接检测到；否则安装到软件资料目录，不要求全局安装。此路径需要本机 Node.js 20 或更新版本。
3. 点“登录 Google 账号”。软件会打开官方 CLI 终端及浏览器，按 Google 的提示完成登录。软件不要求填写 Google 密码。
4. 登录完成后关闭这个登录终端，回到软件点“刷新状态”及服务卡片的“检测”。“授权已缓存”只表示本地授权文件存在，检测连接才会验证请求是否有效。
5. 回到工作台选择该账号服务及模型。`auto`、`pro`、`flash` 是 CLI 调用别名，由官方 CLI 决定具体型号；也可填写实际可用型号。
6. 换账号时，在服务编辑区点“退出／重新登录”。清除该服务的本地授权与 CLI 缓存，学习对话和成果保留。随后重新登录。

账号授权使用官方 CLI 的登录流程，参见 [Gemini CLI 官方认证文档](https://geminicli.com/docs/get-started/authentication/)。是否可以使用某模型、是否需要额外 Cloud 项目及额度限制，以 Google 对该账号的规则为准。浏览器中已登录 Gemini 网页不会自动成为软件的 API 密钥或 CLI 授权。

## 实际行为与边界

- 自定义兼容 API、Gemini API 和 Gemini 账号任务都不需要启动 Codex。
- 软件的只读、需要审批、完全访问模式继续约束文件工具。审批时保持原任务等待，决定后继续；切换模型不会自动扩大文件权限。
- Gemini 原生接口保留函数调用签名，后续工具结果不会丢失必要的原生信息。
- Gemini 账号路径使用独立的授权目录与按对话区分的工作目录，关闭 CLI 自带文件、终端、MCP、扩展和记忆功能。它向软件请求工具，软件检查权限并执行。不会把普通登录账号的 Gemini CLI 全局工作区直接映射成学习项目。
- Gemini 账号采用私有结构化协议传回正文；逐步显示其中的公开正文，转义后的中文、公式和表情可跨片段解码。完整响应及最终结束标记通过校验后才处理工具调用。模型使用 Markdown 围栏包装协议时，仍可校验完整正文后交付，不把协议内容显示给学生。
- Gemini 账号暂不直接分析图片与视频帧；图片/视频学习需要选择 Gemini API，或有图片能力的兼容服务。读取网页视频仍受工作台的视频开关约束。
- 现有“推理强度”档位用于 Codex。切到其他服务时隐藏该选项，使用服务自身默认参数；没有伪造无效的通用推理强度开关。
- 有界并发、对话隔离、原文读取、提交前隐藏习题解析、任务暂停/继续及通知仍沿用共用流程。
