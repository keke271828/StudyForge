# 书库后台阅读安排：时段、每日额度与实际续接

2026-10-10，源码交付。现有 0.4.1 安装包没有更新。先从 Windows 托盘彻底退出旧软件，再双击根目录 [验收最新版.vbs](../验收最新版.vbs)；手机刷新这个源码版本提供的页面。

## 使用方法

1. 打开「全局书库」，展开书架中的「后台阅读安排」。电脑与已配对手机使用同一份设置。
2. 可勾选「限定自动阅读时段」，选择开始、结束与星期。默认不限制。
3. 可填写「每日 token 预算」。`0` 表示不限制；这是后台书库阅读的额度，不包含普通聊天、成果生成和目录识别。
4. 点击「保存阅读安排」。规则在下一步执行前生效；已经发送的模型请求完成并保存结果。
5. 确认目录范围、勾选需要的节点，再安排串行或并行阅读。时段或额度不允许时，任务显示「等待时段」或「等待额度」，保留已完成步骤。
6. 等待任务可直接点击「调整阅读安排」。提高额度或进入允许时段后自动继续，无需新建同一任务。

例如：选择周一、23:00—02:00，表示周一晚上 23:00 至周二凌晨 02:00，结束时间不包含在内。起止相同表示所选星期全天开放。时间与每日日期按电脑本地时间计算。

主动点击「暂停」的任务保持暂停，不因时间到了、额度恢复或重开软件而擅自恢复；需要点击「继续」。电脑关机不能执行任务，重新启动后恢复保存的队列和步骤。

## 限制确实作用于模型请求

- 每次请求在获得共享模型名额之后、实际发送之前检查时段与余额。
- 同时阅读不同章节时，事务内共同预留额度，不能各自花掉同一份剩余额度。
- 每次重试都重新检查和预留，失败不能成为绕过额度的入口。
- 额度不足会释放后台执行位置，等待结算、下一个本地日期，或用户提高额度。目录任务可以继续，不被等待的阅读任务堵住。
- 已完成的原页处理和模型结果保存到步骤记录。恢复后复用它们，只继续未完成步骤。
- 前台活动仍优先；阅读安排不改变原先选择的模型、推理强度、输出上限或原页范围。

## 用量如何计算

界面把以下数值分开显示，并可展开最近 12 次请求：

| 类型 | 含义 |
|---|---|
| 服务报告 | 原生响应提供的总 token 数，包含其报告范围内的输入与输出 |
| 保守估算 | 服务没有报告总量时，用请求前的估算量结算 |
| 请求中预留 | 已允许执行、尚未结算的请求所占额度 |
| 中断或未确认 | 无法确认实际用量的请求，仍按预留量计入，防止无限重试 |

DeepSeek 和兼容接口读取原生 `usage.total_tokens`；Gemini API 在转换响应之前读取 `usageMetadata.totalTokenCount`。不把已包含的缓存明细或推理明细再重复相加。协议参考：[DeepSeek 响应字段](https://api-docs.deepseek.com/api/create-chat-completion/)、[Gemini UsageMetadata](https://ai.google.dev/api/generate-content#UsageMetadata)。

当前 Codex App Server 和 Gemini 账号 CLI 阅读没有接入可靠的原生总量，使用明确标注的估算。估算不会把图片 Base64 长度当成实际视觉 token 数，也不会为计量另复制整份图片编码。账本不保存模型密钥或原文。

**这是请求准入的软预算，不是服务端账单的硬上限。** 推理长度、视觉计费和服务隐藏上下文可能超过预留量；软件记录服务报告的实际值，随后停止不满足余额的请求，不截断已开始的高质量回答。当前没有按各服务价格换算金额。

如果单次请求的预留量已经高于整天预算，等到第二天也不能解决：任务明确提示提高预算或缩小节点范围。未报告总量的请求采用保守结算，所以界面额度可能比真实账单更高。

已开始的请求跨午夜完成时，计入其开始的本地日期。删除书籍或任务不会抹去当天已发生的用量。重启时，尚未结算的在途记录标为未确认并保守计入，不假装免费释放。

- 使用隐藏 Electron 窗口执行了真实页面操作；模型传输使用模拟响应，局部语义检索使用已安装的真实本地模型。没有消费用户的云端额度，也没有改写正式学习数据。

这些证据验证调度和计量边界，不证明模型对教材的理解绝对正确。十本大型扫描教材的长期阅读负载、各学科内容覆盖和费用换算仍需另外验收。
