# 错题追问与批改衔接验收

日期：2026-10-15 完成收尾核验，试验于 2026-10-14 启动并保留原目录名。源码新增；未重新打包，原 0.4.3 安装包不包含本项。

## 解决的学习问题

作业流程已能输出原题解析，以及另一份批改与错因补讲文档。原对话中的完成通知只含下载链接，没有专门按题读取保存记录的工具。导师在后续追问中可能缺少原题、学生具体作答或已交付补讲；不能将链接本身当成已经读过文件。

本次加入 `sf_read_homework_feedback`：导师先得到当前对话的简短作业目录，必要时按“题单＋题号”读取。它返回保存的作业记录，使用与批改文档相同的排版内容构建方法；不宣称重新打开并核对了 Word 的每一页，也不把此前 AI 的反馈当作绝对正确的原资料。

## 实际使用

1. 在提交作业的原学习对话里继续提问，例如：“第2题为什么这样改？只补这一题。”
2. 如果同一对话有多份题单，说明题单名称。导师应先辨认对应哪份，不默认挑一份同题号作业。
3. 导师可按需读取该题原题、此次作答、已交付参考解析，以及已交付的评分、错因和补讲。
4. 电脑和已配对手机使用同一后端通道。回看不重新批改、不自动出题，也不自动给画像加分。

支持已有 `homework_attempts` 流程中绑定本对话、关联文档仍存在且元数据一致的作业。较早的独立批改若没有这种关联记录，不由本工具猜测恢复；学生自行选入的文档仍可按原资料阅读方式讨论。

## 范围与交付规则

- 只读当前项目、当前对话的作业。知道其他对话的 ID 也不能读取；跨项目画像不携带其他对话的作答原文。
- 私有评分／独立生成上下文不能借此读取作业历史。
- 完整提交及文档交付条件必须满足。等待错因问卷时，只能读取已经发布的参考解析及自己的作答，不提前发布私有诊断。
- 评分待核实时，保留“暂不定分、不据此判定学生错误”的原状态。
- 文档已删除、文件已丢失或关联元数据不匹配时，不冒充仍可读取已交付反馈。
- 题目或参考解版本改变时停止，避免混用旧作答与新参考解。
- 只读／关闭通用 AI 工具时，仍可读取本机学习画像和本对话已交付作业记录；不会开启联网、文件写入或修改权限。
- 诊断和补讲作为此前 AI 内容返回，仍可能有误；历史错因不证明学生现在仍不懂。

## 运行开销与上下文恢复

- 每轮只准备简短目录快照，默认最近 6 份，可分页继续查看，不将所有作答、诊断和画像正文塞入每次提问。
- 实际读取默认最多 12000 字符，上限 16000，带总长度、下一位置、记录与题目版本指纹；长反馈可以继续读，不能把截断公式当成完整内容。
- 目录和版本检查只读取必要字段；旧记录的变化也参与内部会话版本，避免目录第一页以外的已读反馈遗留。
- 本轮收到的目录版本固定；若批改在聊天过程中更新或被删除，下一轮重新核对，不将旧内部工具记录重新标成新版状态。
- 本功能不额外发起后台分析模型请求。需要原作答才能回答的追问，可能增加一次读取工具后的模型续答；这是获取实际依据的成本，不宣称每次追问更快。
- 未测量整应用总内存、长视频或完整文档生成速度。
