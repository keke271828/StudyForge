# 长讲解总结条件片段验收

日期：2026-10-16。接续教学质量改进；当前源码可验收，本轮未打包。

## 发现与实施

`summary_context` 在完整讲解超过辅助输入预算时，可能只保留章节结构与现有小结。此前已保护核查疑点，但正文中部未被标成疑点的适用条件仍可能完全不进入总结输入。原模型知道的内容因此少于已生成的正文；不能简单归结为模型能力或推理速度问题。

新增本机 `summary_evidence`，利用原输入剩余空间追加条件片段：

- 原结构、小结与核查记录原样保留，不挤占它们的预算；仅对已有章节均入选的节选计划补充。
- 最多追加3000字符、16段，单段最多1000字符；从已完成AI正文逐字提取，保留章节、从0开始且右端不包含的字符范围和SHA-256。
- 对适用条件、反例、限制、非零／退化情形等采用有限关键词匹配，不做真伪认证。按章节交错选段，重复原句去重；跳过已在输入中的文字、块引用、代码、小结和核查记录，超长段与未闭合公式不截断提取。
- 完整输入、没有余量或已有章节省略时沿用原方案。准备好的计划可复用，位置和指纹确定，不重复追加。
- 原文读取、模型、推理、风格、语言、审查档位及章节调度不变；总结仍使用原有一次请求。资料范围只来自当前传入章节，不读取其他项目或用户画像。
- 成果元数据新增 `lesson_quality.summary_body_evidence`，只保存数量、位置和指纹，不复制整段正文，不新增学习分数。

片段来自可能有误的AI讲解，不是原文件或新审核。没有把推断当作事实；输入中特别保留正文与小结冲突时需核对的不确定性。模型仍可能忽略或误述，不能视为总结准确性保证。

## 实际模型对照

DeepSeek Flash，服务返回 `deepseek-flash`，high；关闭联网、工具和历史聊天。相同总结系统提示，只比较旧输入与补入正文片段的输入。3组6次请求，每臂一次，没有重复或盲评；合成长讲解含重复占位段，辅助预算6000字符，不是实际电子书、视频或完整生成任务。

| 主题 | 旧输入耗时／字符 | 新输入耗时／字符 | 人工阅读 |
|---|---:|---:|---|
| 迭代的参数范围与任意初值 | 11.55秒／266 | 15.80秒／495 | 新版保留更新式、0<q<2与端点；“不能扩大为所有初值”需结合q的限定理解，措辞仍可更清楚 |
| 随机提醒与实际行为 | 14.98秒／267 | 11.83秒／509 | 新版保留假设实验、3分、随机干预对象与依从性／其他路径的限制 |
| 总压强、分压与惰性气体 | 9.68秒／268 | 10.59秒／509 | 新版保留恒温压缩、计量数差和恒温恒容加惰性气体不移动的边界 |

旧版多数明确说明输入缺少细节，没有普遍乱编；新输入帮助模型恢复已生成正文中的具体信息。因果新版仍说“原文未确认”，但这次提供的是AI讲解，不是原文件，来源措辞仍不准确；保留原回答及批评，不宣称完全通过。不能据单次结果声称准确率提升或普遍提速。数学本次约增加4.25秒，输入与回答变具体有开销。

原始条件片段与回答保存在 `build/summary-body-evidence-20261016-1`；没有润色后当作模型原回答。

- 完整受控生成：重新读取约7万字符原文件，忽略旧预览；2章撰写＋2次快速核查＋1次全文总结，共5次受控请求、0次外部请求。中部条件进入总结输入，位置与哈希随成果保存，实际只导出所选DOCX，没有题单或掌握分数。只核验文件容器和正文，未在Microsoft Word做视觉验收。
