# 错因依据与作答引用验收

2026-10-26，源码更新，未重新打包。

## 发现的问题

一是只给结果的作答可以通过包装绕过原有检查。原实现仅识别纯数字、少量选项和“不会”等短答，遇到“答案是4”“我选B”、带Markdown或数学定界符的最终答案时，模型可能把猜测的计算粗心或概念错误标为supported。另一处问题是报告中的多行证据只在首行加了引用标记，后续学生标题或笔记可以脱离引用，显示成导师自己的内容。修复前6种包装结果和1项多行引用共7个检查失败。

## 本轮修改

增加窄范围的本机结果识别：常见中英文答案前缀、数字／分数／单位、选项、简单变量最终值与明确的短结论。格式处理只发生在临时副本，不修改原作答或评分。明显只给结论时，不把模型猜测的原因当成作答证据；没有有效学生自报时，原因标为尚不能定位，进入既有错因问卷。有效问卷引句保留自报边界，不冒充独立验证。

明确步骤（如2+3=4）、推理语句和编程短代码保留原有分析路径。这是证据充分性的局部保护，不是新的数学评分器，也不能判断所有自然语言错因是否成立。

所有证据引句逐行加引用标记，包括空行和标题。电脑、手机回看中学生标题仍在引用框内，导师补讲在框外。实际DOCX导出检查确认学生多行引句保持Source Quote来源样式，导师解释使用Normal样式。

补讲复用规则升级为v2，导师回看协议升级为5；旧整阶段缓存也加入规则版本键。第一轮修复通过317项回归后，专门复现到旧的整阶段缓存仍能绕过新校验（1项失败），最终补齐阶段键后重新运行全部关联检查。已交付文档不自动改写，已有画像也未批量清理。未完成旧任务的补讲按新规则重新核对；原评分继续保留。

指南补充只给结果为何需要澄清、学生自报和来源引用的说明；手机静态壳更新到v85。

## 验收方式与凭据

先从Windows托盘完全退出旧版，再双击项目根目录的`验收最新版.vbs`，无需CMD。当前0.4.4安装包不包含本轮源码修复。

可打开报告：`build/homework-evidence-acceptance-20261026/错因依据与作答引用验收.html`。

- 最终回归及指纹：`build/homework-evidence-final-20261026-3/command.json`
- 两端操作：`build/homework-evidence-ui-20261026-3/ui-report.json`
- 问卷、文档与画像边界：`build/homework-evidence-ui-20261026-3/evidence-gate.json`
- 修复前7项失败：`build/homework-evidence-before-20261026.xml`
- 旧缓存复现：`build/homework-evidence-cache-before-20261026.xml`

复跑脚本：`scripts/verify_homework_evidence.py`、`scripts/run_homework_evidence_ui.py`和`scripts/report_homework_evidence.py`。使用新的验收目录，避免覆盖凭据。

## 范围

本轮防止部分明显无推理结果被诊断、改善来源边界；不能保证所有错因语义或教学解释正确。受控模型故意返回过度自信结果，用于验证保护，不代表真实模型整体质量。未认证实体安卓、Word实际分页、全软件速度或内存，也未批量修复历史已发布文档和旧画像。
