# 长对话增量刷新与并行显示验收

2026-10-11，三轮完善中的第三轮。保留历史消息和原功能，减少刷新时的重复渲染。

## 实施

1. 两端共享增量历史渲染：只创建新增或内容改变的消息，保留未变化的 Markdown、公式、代码与 DOM。首次恢复通过文档片段一次挂载，电脑不再逐条计算滚动高度。手机不再额外把全聊天序列化成一份大 JSON 字符串作为显示签名。
2. 同一消息 ID 的更正也会显示，解决旧版只比较 ID 列表时忽略内容修改的问题。删除或切换项目/对话会移除对应内容；缓存只保存当前阅读容器，不建立全会话常驻缓存。
3. 新消息出现时保留阅读位置、稳定文本选择和未提交问卷。旧消息不再因为后台成果完成就全部重建。
4. 取消“导师回复期间跳过历史刷新”的显示限制。桌面和手机可以在回复中显示独立任务的已保存结果，同时保留正在输出的原回复；最终回复保存后移除临时气泡，不制造重复。
5. 过期的异步历史响应不覆盖后来发起的刷新。手机在状态包之后紧接收到第一段文字时立即保存，避免因为节流窗口尚未结束而等到下一段才看见首句；正常后续文字仍合并保存，工具/结果状态及时更新。

## 局部性能对照

真实 Chromium 对 60 条公开测试消息及六次追加更新，按旧版/新版/新版/旧版顺序测量，保持渲染内容一致。

| 范围 | 原做法均值 | 新做法均值 |
|---|---:|---:|
| 首次恢复渲染 | 51.8 ms | 39.6 ms |
| 六次追加更新的累计渲染 | 344.95 ms | 3.45 ms |
| JavaScript 与渲染器堆峰值 | 49.46 MiB | 24.26 MiB |

追加渲染减少约 99%，此范围的堆峰值减少约 51%。测量报告：`build/history-performance-20261011-2/report.json`。还核验公式、渲染一致、稳定 DOM、选择保留、未提交问卷、同 ID 修订、删除与范围隔离。

这是聊天显示的局部改进，不能当成全应用 RAM、语音模型内存、视频转录耗时或 AI 生成提速比例。全部历史仍会从服务器取得，超长对话尚未采用历史分页；不能声称所有卡顿来源都已解决。
