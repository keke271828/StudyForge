# 多格式成果验收

这是逐项改进的第八项，源码已更新，未重新打包。重点是格式本身适合学习、公式可读、原文与讲解可区分，以及诚实显示代码验证状态。不能用文件能打开代替内容正确或学习效果验收。

## 打开与操作

退出旧窗口，双击根目录 **验收最新版.vbs**，确认标题含“源码验收版”。在原学习对话选择资料、提出要求，再选择输出格式。导师、学习模式、输出语言和学生要求沿用；默认中文，不自动增加练习。

1. 选择Word或PDF：检查行内／独立公式、分行推导、含绝对值的表格和引用公式。原文引用用灰色、宋体及背景框；讲解用蓝色、微软雅黑。Word公式仍是原生可编辑公式，函数名和单位保留正体。
2. 选择PPTX：按章节分页，文字多时继续分页；公式与含公式的句子用清晰图像排版，不将LaTeX命令直接显示为正文。原始表达式及对应文字保留在备注，公式图片本身不能作为原生公式编辑。表格当前按行呈现，复杂表格尚未转为精细的可编辑幻灯片表格。
3. 选择Anki：讲解完成后，由同一导师整理成明确的问题与简短答案，分别提取概念、方法动机和条件，不再把整章塞到背面。背面保留来源；定位或引句不匹配时，在对应卡片及成果记录中标为待核对。
4. 选择编程文件：只提取最终“可运行模型或示例”区，不把原文中的错误或演示代码混入最终脚本。注释说明参数、单位、依赖、运行方法、适用条件与示例；文件内写明未执行验证。
5. 选择Notebook：可运行区的多个Python代码块成为独立代码单元，讲解与总结保留为Markdown单元。原文中的示例仍是讲解内容，不自动变成需要执行的单元。代码单元没有执行次数和输出，不伪造运行结果。
6. 选择代码包：按用户与资料需要选语言，不默认只用Python。保留文件名、目录结构和说明，包内附 `StudyForge-validation.json`，标明实际语法检查及未执行状态。只接受文本文件，不支持二进制依赖打包；跨文件配合仍需实际验证。
7. 成果卡片展开 **格式与运行验证**，查看已做的检查、未验证的部分及格式整理增加的模型请求。讲解来源核对和转换后的卡片来源核对分开，不拿转换前的检查证明转换后的内容正确。

讲解仍只交付所选格式，不额外创建Markdown或审查成果。同步习题默认独立DOCX；显式选择习题APKG时，每张正面保留完整原题，背面仅提示回软件完整提交后查看解析，不加入私有参考解或评分标准。习题卡片允许较长题面，与讲解记忆卡的组织要求分开。

## MATLAB文件名的实际修复

实测发现，中文名称的 `.m` 文件通过MATLAB `run` 执行失败，同样内容换成合法英文脚本名后成功。现已修复：

- 中文成果标题保留，普通脚本文件名为可识别的 `studyforge_model_日期_时间.m`。
- 首个定义是函数或类时，文件名与函数／类名一致；脚本末尾的局部函数不会错误地决定文件名。
- 每个生成版本使用独立目录，同名函数的两个版本不会互相覆盖。内部路径可有中文，脚本基本名称采用合法标识符。
- 成果可用中文重命名；MATLAB实际下载名称保持可用，函数／类名称不会被标题修改破坏。浏览器再次下载自动添加括号序号时，应保存回合法名称；函数／类文件仍需与定义同名。
- 代码包中的MATLAB文件也检查名称及首个函数／类匹配；旧的命名不合规成果不会让整个成果列表报错。

其他成果继续使用原有可读的中文下载名称和重命名规则。

## 验证与费用边界

| 格式 | 本次验证 | 尚不能据此保证 |
| --- | --- | --- |
| DOCX | 真正用Word打开、导出PDF并看渲染图，检查普通公式、原文样式和表格 | 所有复杂TeX命令、所有Office版本与大型文件布局 |
| PDF | 重新读取并渲染页面，检查公式、字体、边距和引用 | 任意公式、超宽表格或任意字体环境都可排版 |
| PPTX | 真正用PowerPoint打开并导出六张幻灯片，查看公式和文字 | 转换为设计精细的演示、可编辑数学公式或完整复杂表格 |
| MM | 重新读取XML，核对标题层级、代码不误当标题和引用样式 | 已在FreeMind/XMind实际导入和交互验收 |
| APKG | 重新读取卡组数据库、正反面、来源、转义和卡片GUID | 已在Anki软件真实导入；模型问题完全原子、无错误或覆盖全部原文 |
| IPYNB | JSON结构、独立单元ID、Python语法、无伪执行记录 | 依赖存在或每个单元、执行顺序和数值结果已经验证 |
| PY / JS | Python AST／Node语法检查，不执行代码 | 逻辑、依赖、运行时行为或数值结果正确 |
| TS / C++ | 文件可读取、格式与未运行说明 | 已编译或执行 |
| M / WL | 自编函数模型在本机MATLAB与WolframScript实际执行成功，输出1 | 任意AI生成的模型已运行或适用于现实系统 |
| ZIP | 重新读取路径与文件、静态检查适用代码，验证状态写入包内 | 多文件协作、依赖和结果已经执行验证 |

目标应用没有做实际打开的项目如实标注，不用文件扩展名、模型口头声明或语法通过冒充验收。新编写的模型运行自检只接受逐字匹配本次自编常量的文件；AI或用户程序不会通过此脚本被执行，应用生成任务也不自动运行未知代码。

普通Word／PDF／PPT排版不增加格式整理的模型请求。Anki和代码包通常在讲解完成后多一次整理；长讲解分批时可能更多，成果记录如实显示。代码与Notebook维持原有的一次代码实现请求。只有主动勾选的习题才会另行调用出题和审查；不能将“没有额外格式请求”理解为整个任务没有模型用量。

输入超过长度、重复卡片题面、路径冲突、非法MATLAB名称、语法错误或无法排版的公式会明确失败，不静默剪掉正文、代码或原题。当前公式图像引擎支持常见标准表达式及分行公式，特殊宏、复杂矩阵等仍可能需要选择Word或调整表达；发现缺失字符时停止导出，不交付黑方框。
