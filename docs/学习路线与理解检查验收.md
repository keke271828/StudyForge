# 学习路线与理解检查验收

2026-10-08，当前源码。本次没有重新打包，也没有把验收用的目标、题目和成绩写入实际学习数据库。

## 设计目的

广泛阅读、读懂一份讲解、独立完成论证和长期掌握需要不同的学习活动。软件应帮助选择投入方向、暴露理解缺口、安排可执行的下一步，并保留实际依据。文档长度、回答流畅度、一次高分均不足以证明学透。

本轮增加项目内的学习路线，与已有的导师、完整原资料读取、生成任务、理解问卷、私有答案、错因补讲、画像和复习相接。

回忆和重建知识的设计参考了 Karpicke 与 Blunt 的科学文本学习实验。研究对象、材料和测验条件有边界，不能把研究结果直接当成这个软件有效的证据，因此检查是学生主动选择的活动，不强迫所有概览学习参加测验。[原始论文](https://learninglab.psych.purdue.edu/downloads/2011/2011_Karpicke_Blunt_Science.pdf)

## 已实现的功能

### 1. 项目学习路线

左侧新增「学习路线」，工作台学习模式旁也有入口。目标包含名称、领域、学习方向、可观察的学习标准、项目资料和建议前置；可以编辑、搜索、按领域或方向筛选、暂缓、恢复和移除。

| 方向 | 主要用途 | 软件行为 |
|---|---|---|
| 广泛了解 | 了解核心问题、必要概念和边界，决定是否继续投入 | 默认不强制检查；准备学习时使用概览模式 |
| 重点精学 | 理解关键方法、推理理由、适用条件和迁移 | 准备学习时使用精学模式；可主动检查三类理解 |
| 独立探究 | 重建论证、分析假设和反例、识别待验证问题 | 准备学习时使用研究模式；不因选择此方向就认定具备研究能力 |

手动创建目标默认广泛了解；同一项目可以保留多领域兴趣，也可以只选一部分重点投入。重点超过三个时仅提示可以集中精力，没有硬性限制。

目标创建、修改、筛选、暂缓和移除没有模型调用。引入已有知识结构也没有额外模型调用；首次整理知识结构仍按原流程调用模型。

### 2. 从知识结构加入路线

知识结构工具栏和知识点详情都有加入路线入口。保留原资料关联、概念领域、知识结构标识和前置关系的依据。相同结构中重复加入同一知识点会复用已有目标，不自动合并不同领域的同名概念。

建议前置是学习顺序建议，不推定学生尚未掌握。手动前置关系拒绝循环，编辑失败不会写入一半的修改；只更改目标方向或暂缓状态时保留原前置依据。原资料变更后，旧知识结构不能直接用于导入。

### 3. 目标影响实际导师与文档请求

点击「准备学习」为当前对话选择目标和目标的可用资料，切换相应学习模式，准备一份可编辑的学习要求。不会自动发送对话消息。目标资料尚未通读时，原有自动通读流程可能调用模型；有效阅读缓存仍可复用。

导师请求和文档生成请求会实际加入目标、领域、学习标准、近期检查摘要与建议下一步。原资料仍通过原有完整读取流程传入，目标或阅读预览不能代替原文。学生当前问题、模式和补充要求优先，不强行把其他学科转换成物理问题，不因选择目标就自动出题。

对话分别保存自己的目标和资料选择。其他对话的原始聊天不会因为学习路线而导入；同项目目标和明确关联的检查证据作为共享规划。跨项目画像继续只提供知识学习证据，不能把画像等同原始聊天历史。

生成任务保存启动时的目标范围、要求和对话快照。后来更改目标、切换对话或继续聊天，不会偷偷改写已启动任务。

### 4. 主动发起三题理解检查

「三题理解检查」只出题，单独生成无答案 DOCX，不同步生成讲解。

| 题目维度 | 检查内容 |
|---|---|
| 概念与条件 | 用自己的话解释概念、对象和关键条件 |
| 方法与论证 | 说明一处方法选择或推理成立的理由 |
| 迁移与边界 | 在改变的情境或条件中使用知识并指出推广限制 |

设计按目标所属领域调整：哲学可考查隐含前提，社会科学可考查证据与推广，数学物理可考查构造和条件，编程可考查算法理由、边界或短代码。维度是题目设计意图，不是经过校准的能力测量。

目标需关联可读取的原资料才能检查。模型返回必须有完整三题及对应维度、私有解析、评分标准和带领域的知识点名称；格式有误时只进行一次有界修复。不能确认题目安全发布时停止任务，不用未经核实的占位题冒充成功。

私有参考解经过现有独立求解及解析、成品核查流程。学生 API、题干、DOCX 和生成完成消息不包含私有答案。完整提交后，现有作业入口立即开放解析，并单独输出批改与错因补讲；错因不确定时仍先询问学生。任务支持暂停和继续；已经在途的模型请求先完成保存，再停在安全边界，不在暂停时继续导出。

### 5. 成绩证据和下一步

路线分别显示三类理解的近期逐题成绩、待核实状态、辅助条件和延迟记录，保留带时间、状态的原题及作答入口。导师摘要也包含作答日期，提醒不能把旧分数当作当前能力的定论。

- 79 分与 80 分的判断有实际区别；低分时指出需要补强的维度，建议先定位卡点。
- 评分待核实不显示最终分，不用于能力判断。
- 提示、笔记或未说明辅助条件会显示在证据中。「提交作业」入口也可填写这些作答条件并保留当前草稿选择。
- 自报未参考笔记或解析，仍不证明没有外部帮助。
- 单次三类达标后可主动加入延迟复习；复习基线使用当前范围内已经完整提交并确认的检查，新建但未提交的题单不阻止安排先前检查的复习。
- 实际间隔至少 24 小时的复习才计为延迟记录；提前作答如实记录间隔。
- 延迟检查未达标、仍待核实或使用了辅助，不被当作近期独立达标依据。
- 目标标准、名称、领域、所选资料或原文件内容变化后，旧成绩保留在原记录里，不混入当前范围。只更改学习方向、暂缓或恢复不会改变同一范围的证据。
- 已从画像移出的对应学习事件不重新进入路线能力摘要。
- 同项目以外的复习不会自动回流为该路线的进度。

80 分沿用现有教学约定；三题不能代表整个领域。当前复习复用原题，成绩可能包含对题目或解析的记忆。后续仍需要新情境、独立论证或实际项目，不能把这些记录宣布为全面精通。

### 6. 页面与数据收尾

轮询只在路线页运行，数据未变化时不重建卡片；变化时保留已展开记录、焦点和操作位置。删除计划需要二次确认，确认状态不会被轮询重置。暂缓目标不偷偷删去不可用资料；删除计划保留原资料、题单、成绩和成果。

切换或回收项目会清理旧项目路线和对话目标。新表纳入项目彻底删除的外键清理范围。多个窗口同时编辑同一目标使用版本检查，旧窗口不能覆盖较新修改。

路线页适配明暗主题和窄窗口，沿用自定义背景的文字可读性保护。修复新增导航图标缺失产生的浏览器错误。

### 真实模型抽查

使用隔离原文《描述与规范》，由实际 `gpt-6.1-sol`、中等推理强度生成并核查三题，**4 次模型请求，98.46 秒**。学生版 DOCX 实际写出并重新读取。

开发助手逐题核对题干、私有解和评分点：区分事实与评价；第二题解释补足前提与证明评价原则合理的区别；第三题提供评价原则后判断具体阅览室情境，并限制推广。没有强套物理、编造首创者或提前展示完整答案。评分标准允许等价表达和论证。

## 打开与验收

1. 从 Windows 右下角托盘完全退出正在运行的旧版。
2. 双击项目根目录 `验收最新版.vbs`，启动当前源码。
3. 在自己的项目中打开「学习路线」，创建一个广泛了解目标和一个重点精学目标。
4. 点击「准备学习」，修改准备好的要求后发给导师，观察讲解是否围绕目标展开；切到另一对话检查目标与选材独立。
5. 主动发起三题理解检查，在「成果文档」查看无答案 DOCX，完整提交后分别查看解析及批改。
6. 回到路线查看三类证据、辅助条件和建议下一步；重启检查是否恢复。

已有安装包不会随源码变动更新。本轮没有重新打包。

开发复验命令：`python -m pytest tests/test_learning_goals.py -q`；`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/smoke_learning_goals.ps1`。真实模型抽样必须显式传入 `--live`，会消耗实际模型额度；不要把模型响应时间当成固定承诺。
