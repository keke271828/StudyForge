# Windows 桌面通知验收

日期：2026-10-07。实现已加入源码，尚未重新打包；现有 0.3.5 安装包保持原来的功能。

## 打开与验收

1. 在 Windows 右下角托盘右键旧版 StudyForge，选择“退出 StudyForge”。仅关闭窗口会继续在后台运行。
2. 双击项目根目录的 `验收最新版.vbs`，直接打开最新源码桌面版，无需 CMD。
3. 打开“设置与联动 → 桌面通知”，启用通知并保存，点击“发送测试通知”。
4. 生成成果后隐藏窗口到托盘；任务完成后应收到原生提醒。点击提醒应打开对应项目的成果文档，并定位到该成果。
5. 在“需要审批”模式请求一项需要授权的文件操作。收到通知后点击进入原对话：任务应仍等待，文件仍未修改；只在点击“批准这一次”后执行。
6. 点击顶部铃铛查看最近通知。通知包含项目、对话、发生时间；待审批和待填写问卷排在前面。

如果系统横幅没有出现，请检查 Windows 的应用通知、横幅开关和勿扰设置，以及通知中心。软件不会修改或绕过系统通知设置。源码模式会建立专用开始菜单快捷方式，以提供 Windows 通知身份；安装版沿用安装程序建立的应用身份。[Electron Windows 通知说明](https://www.electronjs.org/docs/latest/tutorial/notifications#platform-considerations)

## 通知范围

| 情况 | 提醒与点击结果 |
| --- | --- |
| 讲解、习题、答案解析、批改或其他成果完成 | 返回成果所属项目、来源对话，定位成果；解析交付无需等后续批改全部完成 |
| 导入本地文件、网址或视频完成 | 返回对应项目资料库 |
| 资料通读、知识结构整理完成 | 返回对应学习工作台 |
| AI 等待文件操作审批 | 返回原项目和对话，显示审批卡片；点击通知不会授权操作 |
| 批改需补充错因问卷 | 返回原对话并显示问卷，保留批改暂停状态 |
| 后台任务或导师回复失败 | 回到对应任务或对话查看错误和重试入口；通知不暴露答案或完整错误堆栈 |
| 本机服务意外停止 | 提醒重新打开软件，定位运行设置 |
| 切到其他应用后导师回复完成 | 返回原对话；软件有焦点时不为普通回复反复弹通知 |
| 发现新版本、下载更新完成 | 返回运行与更新设置；安装仍由用户发起 |

后台学习记忆整理、每个流式片段、进度百分比和用户主动暂停/取消均不触发系统通知。

## 设置与实现

- 分类开关、通知声音、前台提醒开关保存于本机，关闭通知后仍保留软件内的通知记录。
- 主进程每 1.5 秒检查全项目事件，不依赖当前项目或当前界面，也不受隐藏窗口的渲染计时限制影响。
- 通知事件与回执持久保存于本机 SQLite。重试和重复轮询不会重复发送；升级时不回放已完成的历史任务，超过一天的旧完成提醒也不集中弹出。
- 审批与错因问卷优先发送；同一个任务一次交付多个成果时合为一条横幅。每次检查最多发送四条横幅，其余排队交付。
- 审批等待和问卷提醒采用持久显示；已处理的等待提醒会主动撤下。通知只提供定位，不调用模型，不产生额外模型 token。
- 桌面接口只允许同源主窗口调用；全项目事件接口需要启动本服务的桌面令牌。通知内容不包含聊天全文、习题答案、文件内容或授权凭据。
- 修正了设置读取请求晚到时覆盖未保存开关的问题；测试按钮会读取刚保存的通知配置。
