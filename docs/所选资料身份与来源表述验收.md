# 所选资料身份与来源表述验收

日期：2026-10-16。继续改进学习质量；本轮为源码验收，未打包。

## 为什么改

上一轮的真实总结把已生成的讲解称作“原文未确认”。另查到：成果虽然在资料快选里分类正确，读取时主要说明从文件读到内容；模型、MCP或缓存工具结果并不总能获知其AI成果身份。文件读取成功不能证明内容正确，更不能表明重新读过它引用的教材。

这类混淆会让学生误以为旧AI内容得到新的独立支持。本轮修复来源身份传递，不增加教学模板或固定审核轮次。

## 实施范围

- 新增 `source_origins`：按本机已有的成果／资料关联识别已知AI成果。普通导入文件记为提供的材料，作者和内容未被认证；不信任文件名或文件里自称的身份。
- 并非所有成果都是AI讲解：视频原文档记为整理的来源记录，保留自动识别误差限制；MCP或其他入口附加的外部成果、未知类型保留作者与真实性未认证的状态，不能一律认定AI创作。
- 选段沿已有范围关系追溯身份，只查询ID和归属等窄字段，不自动读取未选父资料的正文、路径或其他聊天。父资料删除、关系缺失或超出有限追溯深度时保留来源关系不完整的状态；不升格为可信原文。
- 发现源资料、其上级范围或成果跨项目归属冲突时，在读取内容前停止。查询按每批300份、追溯最多16层限量进行。
- 讲解、通读、导师当前引用和工具读取传递已知身份。正文、选定范围、页码与既有字节／内容指纹保持；长资料每个相关分段保留身份，不能只让第一段看见。
- 同名文件使用现有资料ID区分；每段只附适用的身份。原来的文件名与来源位置保持，普通导入且没有已知AI成果时不添加整份身份表。
- 导师明确指定PDF页码，以及Agent按页和从缓存读取时也传递身份，不因此扩大阅读范围。MCP读取结果的 `read_manifest.content_origin` 同样保留已知身份。
- 讲解生成与通读的现有系统提示明确区分文件读取方式与来源身份；导师在选中已知AI成果时使用同一说明。全文总结明确本次输入是已生成的AI讲解、小结及核查意见，不能声称做了新的来源查证。
- 成果“资料依据”在电脑与手机共用的组件中显示已知AI成果／普通导入／关系不完整选段的身份。原“条原文记录”改为“条提取记录”，避免界面本身造成误解。
- 不新增模型调用、习题或掌握分数，不自动打开成果背后的未选教材；既有任务的模型、推理、审查档位与文件权限保持。

用户自行下载并重新上传的文件如果没有本软件关联，仍只能记作身份未认证的导入资料；软件无法凭文本断定它由人还是AI创作。旧导出文档不会被自动改写。已知AI成果仍可正常解释和核对，不因其作者身份一概否定。

## 真实模型对照

DeepSeek Flash，服务返回 `deepseek-flash`，high；无联网、工具、学习画像或其他聊天。4组8次实际请求，每臂1次，没有重复和盲评。全部最终回答原样保存，没有复制私有推理过程。

总结组沿用上一轮实际旧系统提示和完全相同的用户输入；其他三组由当前讲解入口捕获提示，移除本轮来源规则、身份表与相应措辞来构造对照，未运行整个旧安装包。当前其余教学规则、语言、模式、详略与问题保持。

因此采纳身份传递与准确归因，不认定教学质量全面胜出，也不以此作为提速方案。尤其单份成果题本次慢了约30秒；输入长度、推理、输出与服务波动均可能影响耗时，不能归因于单一句子。未据此降低模型、推理强度或审查档位。

输入、公开用量和原样回答保存在 `build/source-origin-real-20261016-1`。这里只是合成短文本和总结，不测长书、扫描OCR或视频。

- 实际写出唯一所选DOCX，无题单或掌握分数；来源表不泄漏进交付正文。核对了容器与文字，未在Microsoft Word作视觉验收。此样例是受控教学正文，不冒充真实模型成品。
- 对照页直接嵌入八份实际回答、公开请求、用量、指纹及人工批评；电脑与手机宽度检查公式、切换、链接和横向溢出。页面中另嵌入实际共用的“资料依据”组件，检查生成成果与导入资料身份的显示，不触发模型请求。
- 检查中更新了几处陈旧测试：区分任务时不再查旧提示词措辞；审核输入按现有JSON结构解码后逐字核对原文；导师提示检查使用当前共享规则，避免把已经替换的旧形容词当作功能门槛。没有为满足旧字符串断言修改教学行为。

本轮没有测整个软件总内存、长视频整体速度或真实安卓设备；不能据此宣布这些历史问题均已解决。
