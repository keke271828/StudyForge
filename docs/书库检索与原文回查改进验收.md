# 书库检索与原文回查：改进与验收

2026-10-10。接续 [全局书库核心验收](全局书库验收.md)，本轮完善检索、原文回查和目录操作。当前交付为源码，0.4.1 安装包未更新。正式学习数据未用于写入试验；模型调用次数为零，真实教材检查复用了上一轮已保存的阅读结果。

后续已交付可主动开启的本地语义索引与混合检索，见 [书库本地语义检索验收](书库本地语义检索验收.md)。本页保留此前关键词检索阶段的测试与能力边界，“尚未采用语义向量”不再代表当前源码。

## 1. 打开和使用

1. 从 Windows 托盘完全退出旧版 StudyForge；只关闭窗口会让旧程序继续运行。
2. 双击根目录 [验收最新版.vbs](../验收最新版.vbs)。这是当前源码的入口，无需保持 CMD 窗口。
3. 电脑侧边栏进入“全局书库”。手机连接这个电脑服务后，在学习选项中进入书库；已经打开的手机网页请刷新。
4. 左侧搜索框可以搜索书名、章节标题、术语和已读页中的内容。结果注明书名、状态、匹配的 PDF 页以及原文文字/AI 图像记录等匹配类型。
5. 点击搜索结果只定位目录节点。未读节点仍需确认范围并由你主动安排阅读，搜索不会启动通读。
6. 打开一本书后，用“本书目录定位”和“整理状态”缩小目录；章节左侧箭头可折叠/展开子节。筛选时保留上级路径，方便判断小节属于哪一章。
7. 筛选或折叠不取消已有勾选，已选数量会注明被隐藏的目标；“清空勾选”明确清除选择，“清除筛选”恢复目录。点击外部搜索结果会清除遮挡目标的局部筛选并展开上级章节。
8. 已读节点可直接引用到当前对话。工作台会显示实际使用的书库来源；点击可以回到对应节点，不需要下载再重新导入。

电脑和手机现在使用同一份书库界面定义。本轮实际发现并修复了电脑端缺少新搜索容器的问题，避免两端分别维护时漏加控件。

## 2. 修复了哪些检索问题

- **后面的页面可能查不到。** 去掉“只检查前 120 个匹配页”的截断；扫描全部有效已读页并持续保留最相关的少量结果。强匹配在最后一本书的最后一页也可以排到前面。
- **中文问句容易漏掉短概念。** 调整中文概念片段和英文关键词的组合，不再只保留最长的少数片段。仍属于词面检索，不能承诺所有同义改写都能命中。
- **图片核对中的术语无法检索。** 已保存的 AI 图像核对记录纳入搜索，同时标明它是 AI 记录。不能把模型补写的图像描述冒充原文引语。
- **手动范围可能被其他书挤出结果。** 先限定允许的节点，再排名；不再先选全库前六名然后过滤，以免指定节点明明有答案却返回空列表。
- **无效的新阅读覆盖旧的有效阅读。** 选择与当前书籍版本和节点范围相符的最新完成记录；不混入旧范围正文。
- **长页只截取开头，漏掉问题所在段落。** 改为围绕查询词取得连续片段，保留原文字符位置与省略标记，并优先保留相邻定义或证明上下文。
- **大量页一次载入 Python。** 页面流式评分、分批加载，只在内存保留少量候选。回查时原文、来源标签、视觉记录、笔记和疑点共同计入总长度上限。

这轮优化没有增加后台阅读或回答前的模型请求，也没有让未选择的教材正文自动进入上下文。

## 3. 原文和 AI 笔记的界线

导师收到的参考依次区分：教材原页提取文字、AI 原页图像核对记录、未解决疑点、AI 导航笔记。OCR 和视觉记录仍可能存在错误，疑点会随参考一同传递。

原文件校验、节点范围版本和所用原页缓存校验继续生效。范围改变后不引用失效正文；未读章节只传目录位置。摘录变短或部分参考未能容纳时显式标注，不能把没提供的内容当成已经核对。

“参考背景”的回查是有长度上限的相关片段；你主动设为“重点讲解对象”的节点仍以全部所选范围作为文档输入，不能用几页搜索结果代替整章。

## 5. 检索负载实测

使用 10 本合成 PDF、每本 400 页的已保存文本，共 4,000 页，单页基础文字约 2,560 字符。这不是十本扫描教材的 OCR 或模型理解测评；没有模型调用。

| 项目 | 实测 |
| --- | --- |
| 英文关键词检索，5 次中位值 | 0.135 秒 |
| 中文完整问句检索，3 次中位值 | 0.304 秒 |
| 两类检索的最强命中位置 | 最后一本书的第 400 页 |
| 旧的一次性载入页面，Python 分配峰值 | 2,374,684 字节 |
| 新的流式页面选择，Python 分配峰值 | 221,997 字节 |
| 该检索操作的分配峰值下降 | 90.65% |

中文查询为“**一致收敛时为什么仍要检查极限与积分交换的条件**”。页面选择结果保留相关页附近的第 399 页，而不是用不相关的早期页面填满三个名额。

内存数字来自 `tracemalloc`，只覆盖该页面检索操作的 Python 分配；不包括原生库 RSS、OCR、模型图像缓冲或文档生成。页面加载耗时由约 0.021 秒变为 0.022 秒，不能据此声称这一步速度提高。整款软件的峰值内存和 AI 生成总时长没有在本轮重新测量。

记录：[负载 report.json](../build/library-retrieval-load-20261010-2/report.json)。可用 [smoke_library_retrieval.py](../scripts/smoke_library_retrieval.py) 加一个新的输出目录名复现；脚本拒绝复用已存在的书库，以免污染计时。

## 7. 仍需继续完善的部分

检索目前基于关键词和中文概念片段，尚未采用语义向量。完全改写术语、跨章多步关联或不同教材的同义定义仍可能漏检。搜索无结果时，应指定书名和章节回查，不能据此推断教材没有该知识。

语义检索、聊天 `@节点`、拖动重建目录层级、后台时间段和每日 token 预算仍属于设计中尚未交付的部分。复杂推导的真实教学质量需要独立评估；“工作器完成”和“命中相关页”都不等于模型已经理解正确。
