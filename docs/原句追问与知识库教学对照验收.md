# 原句追问与知识库教学对照验收

2026-10-21。继续学习链路改进，修复所选AI原句没有参与知识库检索的问题，并检查它对实际讲解的影响。源码交付，未重新打包。

## 一、可复现的问题

用户引用导师已保存的原句，再问“这里为什么不成立”时：

- 原句已传给导师，但书库只按简短问题检索。自动模式可能漏掉相关原文，手动模式可能选不到相关的后半部分页码。
- 直接生成讲解时，检索主要使用学生历史文字，没有把最后一次明确引用的概念作为线索。
- 多部分文档重新整理有限书库参考时，若只用普通生成说明，可能再次丢失这个检索焦点。

修复前11项针对性检查中 **7项失败、4项通过**。其中4项失败覆盖DeepSeek／Codex、自动／手动组合；其余包括未读目录线索、旧AI指令边界和缺失检索辅助函数。记录：`build/library-followup-20261021/baseline.xml`。

## 二、修改

### 原句是检索线索，不是来源权威

`studyforge/message_focus.py::retrieval_query` 使用当前学生问题和已验证的明确引用。选中了具体原句时，不使用未选中的邻近旁支、消息ID或内容指纹作为搜索词；没有引用时，当前问题保持原样。

`studyforge/library.py::reference_snapshot` 将检索文字与权限判断分开。是否只依据所选原资料，仍按学生自己当前的文字判断；旧AI引用中的“只依据原文”等句子不能成为新的范围指令。

`studyforge/server.py` 的公共聊天入口把同一检索线索交给节点检索和原页窗口选择，DeepSeek与Codex、电脑和手机共用。学生原话逐字保存，历史检索仍以本条问题作为标题，不将AI原句伪装成学生作答。

关闭书库、不引用资料、手动节点和未读范围的原有约束保留；本轮没有增加固定模型调用、重新OCR、通读未选正文或将检索结果计入画像分数。

### 生成与续接

没有填写新的生成说明时，生成任务沿用最后一条学生原句追问的检索焦点；另填新说明时使用新说明，不自动带回旧原句。

任务保存 `library_retrieval_query`，多部分讲解按较小背景预算整理书库参考时继续使用固定线索。旧任务缺失该字段时走原有回退，不重写已经完成的步骤。

补充检查覆盖原生完整多部分DOCX生成：第9页的目标条件进入有限背景并保留到最终成果来源记录，不被第1页泛论替换。

操作指南同步，手机公共壳为 **v64**。

## 三、六次真实模型对照

先通过软件原生聊天准备链路，在同一份独立受控语料及聊天快照上保存旧／新请求；再用真实DeepSeek服务重放三组、六次请求。模型请求名 `deepseek-flash`、推理强度 `high`，精学模式、直观与专业并重风格。重放未执行Agent工具或联网，不是自主检索工具能力测试。保存的是最终回答，没有保存或展示内部推理正文。

书库是受控保存文本，包含数学、物理、因果推断三项知识，不是三本实际教材的完整通读。

| 场景 | 原文输入结果 | 对教学的判断 |
| --- | --- | --- |
| 极限唯一性，能否取距离的1/3 | 旧／新均收到目标原文，实际请求体逐字相同 | 两份都正确解释半径并非唯一。回答与耗时差异属重复采样波动，不能算代码收益 |
| 高斯定律，净电荷零能否推出内部场零 | 旧版缺少目标高斯原文；新版提供该原文并排在前面 | 旧版本来也能给出有效反例；新版按原文立方体逐面计算，更直接对应卡点，仍有术语和散度前提说明问题 |
| 大样本显著能否证明记笔记的因果作用 | 旧／新均有目标原文，新版将其排在前面 | 两份都给出12分混杂反例；新版更短。额外标准误的方差口径与分组条件仍需讲清，未视为严格统计验证 |

### 保留的不足

- 原文进入输入，不保证模型准确使用、给出明确来源标注或把动机解释到位。
- 两版物理回答把被积函数简写作电场E不够严格；闭合面积分的标量被积量实际涉及E与外法向的点积。新版末尾的散度零也应明确额外局部条件，不能从总净电荷零直接推出。
- 统计例子的组内标准差含义、是否条件于固定分组构成，没有交代清楚，不能将其数值计算当作已验证的统计结论。
- “成立”等通用措辞仍可能命中其他无关背景。新版重点节点更靠前，并未彻底解决自动背景噪声。
- 本轮没有因此再添加一层固定教学提示词或默认审查。避免用额外要求掩盖实际检索／上下文设计问题。

真实请求体、服务token记录及六份原样最终回答：`build/library-followup-live-20261021-1/`。数学两份请求体SHA-256完全相同，可作为重复采样对照。完整人工评价保存在验收页的 `manual-review.json`。

### 两端实际操作

通过实际Electron电脑页及设备审批后的HTTPS手机页完成6项检查：

1. 点击“针对这段追问”选原句，不调用模型。
2. 电脑发送简短问题，原样保留学生文字，同时模型实际收到由PDF提取的目标书库内容。
3. 原对话依据随项目切换、返回和整页刷新恢复，不重复请求模型。
4. 手机原生选句／发送走同一链路，实际收到同一原页内容。
5. 手机真正打开学习选项的来源详情，390／320像素可见且无横向溢出。
6. 手机整页刷新仍保留两次原句追问，没有额外模型请求。

受控模型请求2次、外部模型请求0次；控制台错误0项。此界面测试和前述六次真实模型请求是两种不同证据。手机为真实浏览器引擎与HTTPS配对窗口，不是实体安卓触摸和跨网稳定性验收。
