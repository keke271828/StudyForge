# 补讲后单题理解检查验收

2026-10-15。本轮连接“发现具体卡点—补讲—自愿检查—依据真实作答再教学”。入口是可选项，不将所有阅读都变成作业。源码验收入口为工作区根目录的 `验收最新版.vbs`，已有安装版与源码入口是不同的交付版本。

## 实际操作

1. 在一份讲解的“理解反馈／哪里没懂”中选择困难，也可定位到章节或原句。
2. 提交并完成导师补讲。只保存反馈时不会生成检查题。
3. 在这份反馈卡片点击 **针对本次补讲检查 1 题**。电脑和手机均有入口。
4. 后台按该对话当前服务、模型和推理强度生成独立 Word 题单。可继续聊天，或到任务区暂停、继续、取消、删除任务。重复请求复用同一依据下的任务或已完成题单。
5. 完成后点 **查看这道检查题**，直接打开对应题单作答。完整提交才开放参考解析；参考文档在本机先导出，批改与错因补讲另走原有流程。原因无法确定时先询问学生，不提前定性。

新检查默认采用“先诊断修复”的低分流程，仍可在题单中选择原有费曼流程。参考难度 2/5 是软件约定，不是经过校准的题目难度；一次作答不能证明整章熟练、独立迁移或长期保持。

## 资料、对话与答案边界

- 从问卷恢复其所属的原项目、原对话、具体学生疑问、固定原句和已完成补讲；不是自动使用该对话最近的另一篇讲解。
- 当前资料勾选不会被小检查修改，题目沿用问卷的原资料 ID；原文件在实际生成时仍须可读并通过现有输入校验。
- 原讲解当时的书库输入、阅读版本和引用用途随检查恢复；后来关闭引用、更换节点或出现新的阅读版本，不会静默改用那些内容。旧依据已删除或原文件变化时按现有校验提示，不能冒称已读取旧版本。
- 检查目标由服务端重建，不能通过伪造客户端 JSON 改成其他项目、对话或资料。
- 正常查看反馈、跳过检查、点击已完成题单不调用模型。生成任务使用原有出题、独立解题及两项核查，不给每次聊天或讲解增加调用。
- 参考解、评分点、独立解题、审查记录和 `lesson_check_focus` 保留私有；未完整提交时，即使请求 `reveal=true` 或含解析的学生文档也不会释放。
- 学生版只有原题、来源及公开提示。完整提交后解析文档才增加本题与补讲的关系。
- 历史 AI 原句与补讲可能有误，只作待核对的教学参考，不是原资料、学生作答或掌握证据。保存反馈仍属于自报；阅读、补讲和生成检查不新增测验分数。
- 长定位包与补讲有明确截取数量和完整内容指纹；截取不能表述为已在目标包提供全文。

## 真实试验后的改进

第一轮使用相同两份合成资料，实际运行 DeepSeek Flash / high 的完整出题流程，工具关闭，模型请求直接记录最终返回，不读取或公开隐藏推理。历史讲解与补讲为测试构造，不能当成用户真实学习记录。

第一轮两份题单均经过一次修订后完成，各有 8 次组件请求。数学首稿的题面预告了另一个判断的结论，现有审查发现后进行了修订；社会科学首稿的术语分类引起一份审查异议，也发生修订。人工继续核对最终私有参考，仍发现数学分项评分存在覆盖冲突，社会科学解析加入了题面没有保证的抽样前提等多余论断。独立解题文本自身也可能出错，不能把多次通过当成真理认证。

据此仅收紧这项新检查的任务约束，不替换全软件导师人设：

- 一个关键理解、一个必要的条件变化或对照，至多两个紧密相关的小问；不额外要求研究方案或枚举方法。
- 去掉通用出题对“覆盖核心概念、论证与迁移”的额外要求，避免一题承载整套测验。
- 私有解析只解释该题必要的判断、理由与条件，不为了显得专业而添加未使用的公式或术语。
- 新任务的评分标准为 `criterion` 和正数 `points` 的分项数组，合计 100；已正确分项独立计分。格式和分数总和由程序校验，内容正确与公平仍须核查。
- 旧版本任务快照仍支持原格式，暂停恢复不强制将旧评分文本改成新数组。

第一轮记录保留在 `build/lesson-check-real-20261015-2`，不是被删除的失败样本。首个目录 `lesson-check-real-20261015-1` 的夹具初始化失败，尚未发送真实模型请求；不计为一次模型失败。收紧后的第二轮保留在 `build/lesson-check-real-20261015-3`。完整学生题面可通过对照页查看；私有答案不放进学生对照页。

## 工程验收

- 专项检查：精确补讲定位、完成状态与归属、长内容截取、实际 SQLite 并发去重、暂停／失败／取消、重复请求、原书库版本、当前资料选择保持、客户端伪造、分项评分校验与旧格式兼容。
- 答案隔离：真实 Word 排版与读取，未提交公开 API 无私有内容；空白提交被拒绝；完整提交在批改模型尚未启动时先生成参考文档。仅完整作答形成答案释放记录，仍不产生测验分数。
- 原生链路：受控 HTTP 响应走实际模型客户端、出题、独立解题、两项核查、保存和 Word 导出。阶段重放不重复模型请求。
- 桌面与手机：完整页面、配对 HTTPS、实际任务暂停／继续、刷新恢复、精确打开题单、Word 下载、当前资料选择和画像边界。手机为 390×844 尺寸 Electron 运行，不冒称真实安卓设备已验收。手机静态壳 v42。
- 本轮只改变源码；不操作用户生产数据库。回归中的旧修复练习夹具补齐了既有目标字段，没有削弱生产验证。

最终测试数量、第二轮实际请求和耗时、页面核验及源码指纹见 `build/lesson-check-review-20261015/最终核验记录.json`。

最终去重 **261 项**相关程序检查通过（专项 25、关联回归 258、指南 2，重叠不累计）；**6 项**完整桌面／配对 HTTPS 手机交互通过，交互测试使用 8 次受控响应、0 次外部模型请求。真实模型另行运行 **4 份完整流程、共 24 次组件请求**，不与受控请求混为一谈。对照页四份题面逐字核对，Word 链接可用，电脑与手机宽度无横向溢出，零外网依赖。最终真实试验启动时记录的任务源码指纹与交付源码一致。

|---|---:|---:|---|
| 数学 | 8 次请求，259.81 秒 | 4 次请求，223.38 秒 | 分项评分更清楚，任务更聚焦；一般区间条件推导仍有认知负担 |

## 仍需保留的判断边界

两种学科各两次试验属于小样本人工检查，未做盲评、重复统计或长期学习成效评估。改进是否让任意题目都更好，需要继续采样；格式可验证不等于参考答案必然正确。现有程序不校准单题难度、能力分或保留时间。

生成涉及真实服务等待和可能的格式修复、内容修订；4 次正常组件调用并非固定完成时间。此轮不能证明长视频／整本书提速、总内存下降或全软件教学质量已经达标。自动更新源尚未发布，旧安装版也不会因源码变化自动更新。
