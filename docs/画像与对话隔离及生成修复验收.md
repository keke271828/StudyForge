## 画像的范围

| 内容 | 使用范围 | 实际行为 |
|---|---|---|
| 学过或接触过的知识、理解困难、教学偏好、实际评估、自评 | 跨对话与项目 | 向导师提供摘要，也可用 `sf_read_learning_profile` 查询、检索与分页 |
| 原始聊天消息与内部模型协议 | 当前对话 | 按对话读取；缓存必须同时匹配项目、对话和资料/权限范围 |
| AI 工作文件与自动恢复的生成图片 | 当前对话 | 每个对话独立工作目录；图片按真实来源恢复，不按项目整体放开 |
| 同一项目的资料与成果 | 项目资料库 | 只有明确选入当前对话的资料可由资料工具读取；引用成果不开放其来源聊天 |

画像会分别提供做题评分、费曼讲解评分、自评熟悉度及主观难度，不把自评当作客观成绩。提问、通读和接触记录不证明已经掌握。用户纠正和移出记录继续生效。

以前「我的画像是什么」可能匹配不到具体话题，从而不给导师任何记录。现在这一问法提供画像概览，工具可以继续查询全部有效记录。没有相关领域记录、画像完全为空和候选学习证据尚待整理，会明确区分。

自动提供给导师的画像不含其他对话的证据引句、消息 ID、聊天原文和内部路径。画像页面仍允许用户查看自己的原始证据、纠正判断、移出和恢复记录。

## 只记录学习证据

普通聊天先经过低开销筛选，再由原有有额度上限的后台整理器核查。选取关于知识的疑问、学生自己的推理与理解、前置缺口、方法选择、迁移、表达和实现困难，以及明确教学偏好。软件按钮、报错、项目管理、文件格式、模型选择、任务进度和一般闲聊不作为学习画像。

一条消息同时含操作反馈与知识疑问时，只将符合条件的学习部分放入候选证据。问卷的自由补充采用同样筛选；原问卷仍保存用户填写内容，画像只保留知识相关部分。六类理解困难继续作为自报证据保存。

仅导入文件不再根据文件名自动生成「学过这个知识点」的判断；通读范围仍明确标作接触范围。旧的无关聊天和仅导入的记录自动移出有效画像，原证据保留，用户可在「已移出画像」恢复。即使重新启动，已筛除的旧事件也不再进入模型整理队列。

候选筛选与模型判断仍可能漏掉表述不明确的学习问题，或形成不准确的暂定判断。画像页面的证据查看和用户纠正用于检验这一点，不能把自动整理当成经校准的能力测验。

## 两层对话隔离

软件层面：独立工作目录、图片归属、缓存范围检查和文件工具权限同时限制访问。即使用户授权了较大的父目录，也不能直接读取软件内部数据库、设置文件、其他对话目录或未选的内部资料。用户明确授权的软件外公共目录仍用于文件操作。

连接层面：本机实际检查发现 Codex 原生 `memories` 已启用。仅使用临时线程不足以证明原生记忆不会被注入。因此学习软件在启动自己的 Codex App Server 子进程时，以及创建学习线程时，均关闭原生记忆、已有记忆注入、原生记忆生成、外部记忆导入和全局钩子。软件继续使用自己的学习画像；这些参数只作用于软件创建的服务进程。

设置依据为 [OpenAI 官方配置说明](https://learn.chatgpt.com/docs/config-file/config-reference)。本机已真实初始化该服务并通过 `config/read` 核对有效值，未启动模型回合。可运行 `python -m scripts.check_codex_learning_scope` 再次只读检查。

旧的无归属模型缓存停止复用，公开聊天仍保存。过去同项目共用的工作文件保留原位置，无法确认属于哪个对话的文件或图片不会自动塞进所有新对话；有需要可明确导入、选择引用。

导师口头声称「能读取其他对话」不能证明实际权限。软件会明确告知范围；验收应检查实际读取是否被拒绝、请求中是否出现其他对话内容。

## 讲解与习题恢复

讲解审查、习题生成与审查、Anki 和代码包整理采用统一结构验证。返回空 JSON、非 JSON 或缺少必要字段时，最多请求一次格式修复。仍未成功时给出可读错误，不直接显示底层 `JSONDecodeError`，不发布空文档或虚假通过记录。

习题原流程即使修订了题目，也会因第一版失败记录拒绝发布。现在保留旧记录，在有实质问题时修订整套题目，再重新独立求解和核查修订版；最终版本通过才保存题单。修订次数有上限，评分问题未解决时停止发布，并说明相关题号与问题类别。

审查失败说明可能包含答案，故公开任务错误只显示题号和类别，私有解析不进入任务卡片或聊天。学生版仍隐藏解析，整套提交并批改后才按原流程开放。同步出题后续失败时，已经导出的讲解继续保留。

## 手动验收

1. 打开上述源码入口，在「学习画像」确认已有记录；可用真实评估记录或填写自评，自评须单独标注。
2. 在一个对话里询问具体知识的理解问题；再发送一句软件操作反馈。后台整理完成后，检查知识证据与判断，操作反馈不应成为能力评估。
3. 新建同项目的另一个对话，再到另一个项目，问「我的用户画像是什么」。相关画像可见，原对话聊天不应出现在新对话记录里。
4. 尝试要求读取其他对话的内部工作文件。实际工具应拒绝；引用本项目成果应先明确选中该成果。
5. 选择资料，分别试「只生成习题」和「讲解＋习题」。最终任务正常完成后，下载并打开所选文档；DOCX 习题不应附参考答案。
6. 退出托盘并重新打开，检查原对话记录、来源归属和有效画像仍在，其他对话的原文没有被混入。
