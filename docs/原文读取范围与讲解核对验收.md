## 发现的实际缺陷

理解反馈会自动带上旧讲解标题、章节路径与问题。旧流程对整段格式化反馈判断原文件读取范围，因而旧AI讲解标题中的“第2章”可让原PDF等待选段，“第2页”可让原PDF只读取第2页，遗漏第1页的定义域或研究设计。对于仅上传、尚未解析的PDF，旧标题还可能导致未经真实页码请求就开始读取。

此问题已通过5对原生HTTP请求复现；不是只根据源码推断：

| 场景 | 旧输入 | 修复后 |
| --- | --- | --- |
| 已解析PDF，选旧AI“第2章” | 两页均未读，等待选段 | 原PDF两页均进入输入 |
| 已解析PDF，选旧AI“第2页” | 只读原PDF第2页 | 两页均进入输入 |
| 未解析PDF，选旧AI“第2页” | 自动读取原PDF第2页 | 等待明确原文件范围 |
| 旧AI“第1章”，用户明确仅核对原PDF第2页 | 被标题干扰而等选段 | 仅第2页进入输入 |
| 用户明确只看选中文字、稍后提供原文 | 等待选段 | 继续等待，未擅自扩读 |

学生公开提问逐字不变，修复的是资料范围识别输入。5对复现共10次受控请求，0次外部请求，原始请求和结果均保留于 `build/lesson-source-request-20261021/`。

## 实施

- `lesson_feedback.source_request` 只取学生自己的补充作为原文读取范围指令；旧AI标题、章节、原句仍保留为核对目标，通过原有历史AI片段输入提供。学生疑问不被删掉。
- 原PDF页码解析、选段判断、多文件名称定位及Agent原文读取指令都使用这份补充，DeepSeek和Codex入口一致。普通聊天仍按实际用户消息读取。
- Agent分支继承父任务的 `source_read_request`，保留已有工具权限及独立缓存，不能因分支忘记页码限制而扩大读取。
- 当页码、选段请求或全文授权改变，内部状态标识随之变化：DeepSeek不重挂不兼容的隐藏工具结果，Codex不复用不兼容的原生线程。保留同一对话的公开历史，同一页码的普通改问法仍可复用。没有资料的普通对话不新增这个范围标识。
- 手机公共壳v61与软件内指南同步。没有新增数据表、改写用户文件、变更默认模型或固定提示词叠加。

### 实际模型发现的伪工具正文

一次真实模型回答在最终正文中打印了DSML工具标签，未实际执行读取，却被原程序保存为完成。已在DeepSeek兼容响应校验中识别本轮观测到的裸DSML块，不解析执行这段文本。重试只针对未完成响应；持续失败会报错，内容核对状态失败、原问题和位置保留，不保存伪完成回复，也不写画像或自动出题。

已检查协议代码围栏、行内代码及引用日志的正常讲解；不因教学需要展示这些标签而拒绝。这个检测针对已观测协议文本，不代表能自动识别所有形式的假操作或保证模型真的完成所有声称的工作。流式生成尚未校验结束时可能短暂显示待完成文字；不能称为所有原始片段在屏幕上都不可见。
