# 大资料准备与界面响应优化验收

2026-10-13，源码更新，未重新打包。先在 Windows 通知区托盘完全退出旧版，再双击根目录 [验收最新版.vbs](../验收最新版.vbs)。现有 0.4.2 安装包不包含这轮源码修改。

## 找到的问题及修改

本轮检查长资料启动、生成准备和进度响应，发现了三处实际开销：

1. **不需要正文的校验也加载正文。** 讲解、通读、题单的启动校验，以及部分生成、聊天、续做准备，会读取并解码资料的完整 `segments_json`。非媒体资料马上又从原文件重新读取，刚加载的大预览并没有参与讲解。
2. **同步准备占用服务主线程。** 资料记录的读取、深复制、逐项图片路径检查、完整原文组装在异步请求中同步执行。执行这些操作时，其他进度、暂停、切换请求也需要等待这个线程。
3. **长段落反复复制剩余全文。** 旧分段器每切一段，再复制并拼接剩下的整个正文。特别长的单段文字会产生随长度快速增长的重复复制开销。最终组装又先做一份完整正文，再复制一遍加上标题。

已实施：

- 启动校验只读取资料的状态和项目归属等必要字段；真实生成、聊天、习题和续做按原文件准备输入。原始视频／音频仍保留完整转录、时间戳和画面位置，自包含的视频识别记录重新读取保存的原记录。
- 深复制、图片路径检查和原文分段、组装移到本机工作线程。该准备阶段同时只启动一项，避免并行任务同时扩大临时内存；模型请求和独立任务继续遵守原并发设置及前台优先规则。
- 取消等待不会提前释放尚未停止的真实线程名额。只读准备不把原文件路径登记为任务输出，进度和画面回调仍在服务线程处理。
- 分段使用位置偏移读取，并一次连接现有正文片段。保留字序、公式、来源和续接标记，避免为了提速缩短原文或替换为预览摘要。
- 桌面调度详情和两端“耗时详情”显示原文准备阶段，便于区分本机准备、排队、模型请求和导出。

这轮没有改变导师提示词、教学模式、语言、审查强度或模型参数；没有操作用户的学习数据库和原资料。

## 修改前后的可复现对照

对照运行修改前的函数快照和当前实现，使用独立 Python 进程、真实 SQLite 和合成完整正文。每种布局 **5,280,022 字符**；分为单个长正文和 2,201 条页位置记录两种。计时重复三次取中位值，内存另外测量；夹具建立和输出哈希检查不计入计时。没有外部模型、OCR 或语音调用。

完整正文和分段数组的 SHA-256 在两版一致，末尾条件保留；单段输出 442 段，页记录输出 452 段。这也保护原有分段内容参与的恢复／复用键。

上述心跳按 10 ms 间隔安排，反映被主线程挡住的时间；Windows 调度、线程竞争和 Python GIL 仍可能产生短延迟，不能理解为永远无卡顿。内存是该操作期间的 **Python 分配**，不包含已有资料、全部桌面窗口、模型引擎或整机 RAM。资料校验的小峰值也不能代替生成所需的完整上下文。

这些是本机准备阶段的改善，**不能换算为整份讲解或整段视频提速相同百分比**。长视频的完整语音识别、视觉请求、模型推理和 Word 排版仍需分别计时。

## 功能核验

专项检查覆盖：

- 使用 SQLite 读取权限检查，确保必要字段校验、非媒体原文件准备不访问大预览列；默认同步读取接口仍返回完整原记录。
- 保留媒体转录的原文件绑定、时间戳及画面位置，拒绝跨项目、不存在和未就绪的资料；保留成果引用身份。
- 对多种分段大小、多个资料、中文、Unicode 和公式比较完整旧分段输出；来源标签超过可用分段长度时明确报错，不无限重复切片。
- 验证复制、实际图片路径检查及组装在工作线程执行，回调在服务线程；图片分析与保存原文分开，选定范围不冒充全文。
- 取消时保留真实准备占位，下一项准备等待，独立模型请求仍可运行；原文件不变且不登记为可删除任务输出。
- 完整讲解在准备中暂停，尚未发出模型请求；继续后只请求一次并实际导出、重新打开 DOCX。

最终 **371 项相关回归全部通过**，其中新增 **14 项**准备、完整性、线程、隔离和任务控制检查；内置指南另有 **2 项**访问检查通过。Python 编译与本轮修改的 JavaScript 语法检查通过。

## 实际电脑和配对手机交互

通过 **7 项**真实 Electron 桌面及配对 HTTPS 手机检查。原文件、SQLite、后台线程、暂停／继续、原生模型请求协议、DOCX 导出、页面和下载通道参与；模型回答使用模拟传输，没有调用真实账号。

特意悬置原文组装线程，期间完成进度查询、调度查询、桌面对话切换和恢复、手机项目切换和恢复，以及暂停。释放线程后保持暂停，确认模型尚未请求；继续后产出一份 DOCX。实际请求包含原文件末尾条件，未包含旧预览；手机正常下载该文件。

本次受控等待期间，进度查询约 77 ms、暂停约 160 ms；桌面对话切换／恢复约 1.20／1.55 秒，手机项目切换／恢复约 0.95／1.13 秒。**这些是交互边界检查，不是整个软件流畅度已经达标的证据**；切换仍有可继续减少的串行请求和刷新开销。

## 如何验收

1. 从托盘完全退出运行中的旧版，双击 [验收最新版.vbs](../验收最新版.vbs)。这次无需修改模型、审查或并行选项。
2. 在自己的项目选择已解析的较长资料，启动讲解；同时切换到其他对话或项目，查询任务进度，尝试暂停再继续。
3. 在任务卡打开“耗时详情”，核对原文准备、原文件读取、模型请求和排版分别用时。不同阶段可能重叠，不应直接相加推算总耗时。
4. 打开实际成果，重点核对原资料末尾条件、公式和来源，确认输入完整性仍满足需求。

下一项优先建议：继续测量项目／对话切换中每个接口和渲染步骤，减少重复请求及互不依赖的串行等待。真实长视频与讲解总时长另做完整测量；不以本轮本机准备数字替代。
