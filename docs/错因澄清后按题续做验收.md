# 错因澄清后按题续做验收

2026-10-22。继续改进错题补讲的针对性、一致性和等待时间。源码交付，未重新打包。

## 一、实际问题

原先每次填写错因问卷，整个失分题集合都会再次进入诊断与补讲。虽然评分步骤已有持久化缓存，但补讲阶段的键包含整份问卷，所以澄清一题也会重写其他已完成题目。

这样既重复输出，也可能让有本次作答依据的已完成诊断发生变化。当前改动保留已验证输入／证据边界的结果，只更新自身问卷或共同依据发生变化的部分。

## 二、实现与保留的边界

新增 `studyforge/homework_analysis.py`，由 `homework.analyze` 调用：

- 共同指纹绑定尝试ID、题单、项目、对话、题目及参考解版本、完整作答、实际评分、教学设置、相关画像快照、所选及实际模型／推理强度、教学规则。
- 分题指纹绑定该题当前自报及对应的已交付诊断文字；内容改变、损坏、重复索引、记录版本不识别或缺少旧记录时重新核对。
- 更新第1题时，第2、3题的错因、证据、讲解和核对方法原样保留；更新结果按原题顺序合并。
- 模型仍收到完整题目、参考解析、作答和评分作为上下文，保留跨题依赖。只限定本轮要输出的题号，没有缩短原资料或丢掉其他题的条件。
- 在既有任务进度中显示保留多少题、正在处理哪些题，不增加需要手动开启的新模式。
- 同样输入且已有匹配结果时，可直接返回，不新增模型请求；不确定原因仍标为不确定，不绕过对应问卷。

原有评分、独立复核、解答释放时间、暂停、问卷、用户画像、成绩写入和题单隔离规则保持。新记录不是一次新的测验或重新评分，不因此增加证据分数。

已确认的题意、参考解、作答、评分、教学设置或实际服务变化时，旧结果不会冒用。历史任务没有新记录时回退完整核对，不从缺失资料中推断已验证。

这是输入与已保存结果的一致性校验，不是对AI内容的真实性认证。复用会同时保留原内容的优点和问题；需要纠正时仍可在原对话按题追问核对。

## 三、真实模型对照

独立合成三题：一元一次方程、加法、高斯定律。评分是试验给定输入，本轮不测试评分模型是否准确。第2、3题先有学生自报，第1题只写结果4，后来澄清“先算7减3得到4，忘记再除以2”。

请求名 `deepseek-flash`，`high`，精学、直观与专业并重。初次一次请求，随后旧／新各一次请求，共3次真实调用，无额外格式修复；没有联网或文件Agent操作。

这是单工作表、单次配对，缓存和模型波动没有完全排除，不能承诺稳定快38.8%，也不能推广为出题、初次评分、文档生成及导出的总任务提速。全软件RAM本轮未测。

### 人工阅读判断

- 初次回答能区分“只有结果4”与实际可定位步骤，第1题保持原因不确定，未仅凭答案编造心理原因。
- 两版数学补讲都解释为何先减3再除以2，强调4是2x的值而非x，给出代回／逆运算。不能说旧版原本不会教或新版内容必然更好。
- 新版其他两题与初次返回逐字相同，确保不会因为别题澄清而无故改写。
- 原先高斯补讲主线和立方体通量正确，但“积分核”称谓可更精确；复用并不自动纠错。
- 新数学返回的clarification仍重复询问已自报的步骤；该字段没有变成新强制问卷，原返回保留。
- 自报继续标明未独立验证，历史画像仅作为线索；没有把本轮补讲当作学生已经掌握。

所有原始消息、JSON返回、用量、耗时和合并结果在 `build/homework-analysis-reuse-live-20261022-1/`。没有保存隐藏推理文本或凭据。

## 四、持久化与实际交付

使用三个独立Python进程保存初次结果、回放旧流程、回放新流程。三者读取同一份状态文件，指纹一致；新版在新进程只请求第1题，其他两题逐字保留。

三个受控响应分别重放保存的真实模型返回，0次新云请求。新程序准备的初次／续做提示逐字对应上述真实调用，避免实验和交付代码不一致。

旧、新两份完整批改文档由应用原有的 `homework.report_document` 与Word输出器生成，均包含全部原题、作答、评分、错因、讲解、核对方法和参考解析。Word包、普通正文和原生公式结构已检查；没有渲染认证分页布局。

回放证据：`build/homework-analysis-reuse-replay-20261022-2/`。这验证独立进程读取保存分析的能力，不冒称已经在真实用户安装包上完成完整关机／开机验收。

另有完整原生提交流程检查：先交付解析，错因不确定时暂停，提交后只更新一题，不重复评分记录，最终Word仍含全部题目。受信手机API也完成两题提交、单题澄清与完整Word下载；不是实体安卓触控或新版业务UI整体验收。
