# 评分保存与中断续做验收

2026-10-26，源码更新，未重新打包。

## 问题与实现

普通习题与JavaScript作业在成绩已经提交、外层评分阶段缓存尚未保存时模拟异常，恢复均失败：评分入口认为原作答已经批改，任务无法接着补讲。修复前2个失败用例保留在`build/homework-checkpoint-before-20261026.xml`。

本轮把成绩、详细提交关联、掌握度与测评证据放到同一个数据库事务中保存。评分结果中明确保存提交记录ID与作业尝试ID，作业尝试同时保存该结果。学习证据写入失败时整项回滚，避免成绩或掌握度只完成一半。掌握度原有权重和自评规则保持；新增的事务参数仅用于一致提交，不把恢复算成一次新测验。

当评分阶段缓存缺失时，恢复只接受能够对应原题版本、原答案、原提交ID、评分内容与数值的保存结果，不搜索“最近一次成绩”来代替。恢复后只做缺失的错因补讲和导出，不重复更新评分或掌握度。编程结果也有明确提交ID；旧结果缺少提交ID时不再将补讲写给最新一条提交。

如果中断发生在评分事务完成前，整个事务回滚，原作答仍保留，重试可从原任务继续。若中断发生在成绩与学习证据提交后、阶段缓存保存前，已提交结果可供新进程恢复。原有复习完成收尾按需继续；已有阶段缓存仍沿用。

“重新复核原作答”是主动要求重新判断，相关入口会清除本次恢复用的旧评分结果，保留原作答和原有条件，再进行复核。不会错误地把恢复逻辑套到主动复核上。没有可核实关联的旧记录或损坏记录明确拒绝，不进行推测修补。

指南增加异常中断后的操作说明；手机静态壳更新到v84。

## 最终验证

- 427项关联回归全通过，0失败、0错误、0跳过；9个生产文件指纹前后相同。
- 15项专门检查：普通／编程恢复各1项，学习证据失败时整体回滚各1项，10种缺失／不一致依据，以及1项真实新Python进程恢复。
- 普通与编程作业恢复后均只补做缺失讲解，没有再次评分；原提交始终1条，掌握度计数不变。
- 新进程恢复使用中断后的同一份隔离数据库，原提交和掌握度保留，模型只调用1次补讲，评分调用0次。不是只依赖旧进程内的对象或缓存。
- 13组实际电脑与配对HTTPS手机操作通过：从失败作业历史点击重试、按题查看补讲、草稿／原对话返回、320px深色与手机实际下载DOCX。
- UI场景评分准备2次受控请求；异常后恢复1次受控补讲请求，云调用0次。原提交ID、测评证据数与掌握度完全保留；恢复后新增的正常错因补讲不是新评分。
- 截图已查看，报告显示恢复后具体错题的针对性讲解。

全部使用合成题目、受控模型及隔离数据，没有修改真实用户资料、成绩或画像。

## 打开方式与凭据

先从Windows托盘完全退出旧版，再双击根目录的`验收最新版.vbs`，无需CMD。0.4.4安装包没有包含本轮修复。

可打开报告：`build/homework-checkpoint-acceptance-20261026/评分保存与中断续做验收.html`。

- 最终回归与源码指纹：`build/homework-checkpoint-final-20261026/command.json`
- 两端操作：`build/homework-checkpoint-ui-20261026-2/ui-report.json`
- 中断前已保存状态：`build/homework-checkpoint-ui-20261026-2/seed-evidence.json`
- 恢复后的状态：`build/homework-checkpoint-ui-20261026-2/checkpoint-evidence.json`
- 汇总：`build/homework-checkpoint-acceptance-20261026/result.json`

复跑脚本为`scripts/verify_homework_checkpoint.py`、`scripts/run_homework_checkpoint_ui.py`和`scripts/report_homework_checkpoint.py`；新进程检查使用`scripts/resume_homework_checkpoint.py`。复跑请指定新目录，保留已有证据。

## 范围

这次验证模拟异常后的持久化恢复、事务回滚及实际两端入口，不是实际断电／损坏磁盘测试。没有认证任意旧记录均可恢复、真实模型教学能力、实体安卓或全软件性能。恢复仅复用已经保存且能严格对应的成绩，不将旧画像写入时间改成恢复时间，也不据一次成绩宣称已经掌握。
