# 项目与多对话验收

2026-10-04。本项源码实施完成，未重新打包。使用项目根目录的 `验收最新版.vbs` 打开最新源码。

## 本项解决的问题

原实现已将部分聊天保存在数据库，但前端缺少项目内对话列表及完整恢复流程；更改选材时会清空当前对话标识。界面状态还依赖浏览器地址的本地存储，而桌面启动端口可能变化。因此，保存过的历史记录不一定能重新显示，原有阅读记录和知识结构也可能不能自动找到。

本项补齐数据库中的工作台状态、对话管理 API、界面恢复与资料缓存查找。这里说明的是代码中确认的问题；没有检查或改写用户的实际学习数据库。

## 已落实的行为

| 内容 | 当前行为 |
|---|---|
| 项目与资料 | 同项目对话共享项目资料库；每个对话独立保存所选资料 |
| 新对话 | 默认不选资料，不继承其他对话的选材 |
| 对话列表 | 显示自动标题、最近消息和时间；支持手动重命名 |
| 聊天与草稿 | 保存到本机数据库，切换工作区、对话和重启后恢复 |
| 模型与学习方式 | AI 服务、模型选择、推理强度和学习模式按对话恢复 |
| 启动恢复 | 恢复上次项目及该项目上次使用的对话，不依赖启动端口 |
| 更改选材 | 保留当前聊天；以当前选中的资料作为原文依据，重新验证阅读记录 |
| 阅读与知识结构 | 原文件及模型参数未变且已有有效记录时复用，不再重复调用模型 |
| 成果归属 | 成果列表和快选只显示所属项目的生成文件 |
| 成果引用 | 自动出现于“本项目成果”，手动勾选；直接解析完整生成文件 |
| 成果管理 | 重命名同步引用名称；删除同步移除引用；原学习资料和作答保留 |
| 异步归属 | 旧项目的迟到响应不会填入新项目；导入完成不改动已切换到的另一对话 |

采用的问卷回答：新对话默认不选资料；成果自动出现但手动选择引用；自动标题、可重命名。

跨项目学习画像仍按原要求共用。对话之间共享的是有依据的学习记忆，不是其他对话的聊天正文、资料勾选或当前生成要求。

## 保存、迁移与引用方式

- 新增工作台状态与成果引用表，保留原 `conversations` 表结构及已有消息。已保存的旧对话补入列表；自动标题从第一条用户消息生成，不额外调用 AI。
- 每个项目保存上次对话，全局保存上次项目；对话分别保存草稿、资料 ID、阅读 ID 和模型等设置。
- 阅读复用仍校验完整原文件及关联资源的指纹。原文件、选材、服务或模型参数变化，失效的缓存不继续作为当前阅读依据。
- 成果资料引用指向同一导出文件，不复制一份，也不要求下载后重新上传。首次使用时解析完整文件，保留来源位置。
- 多文件代码包可按 ZIP 内文件和 Notebook 单元读取；读取不执行代码，不解压到任意路径，并限制数量和大小。
- 导师仍需区分原资料与 AI 生成的成果；成果能引用不等于内容已经被事实验证。

## 如何打开并自行验收

1. 若旧版正在运行，在 Windows 右下角托盘右键 StudyForge，选择“退出 StudyForge”。直接关闭窗口会隐藏到托盘。
2. 双击项目根目录的 **`验收最新版.vbs`**，确认窗口标题带“源码验收版”。它会启动最新源码，不需要保持 CMD 窗口。
3. 在一个项目导入 A、B、C 三份资料。新建对话时确认没有默认选材；第一个对话选 A+B，发消息并留草稿，另建一个对话选 B+C。
4. 切换工作区、项目和对话，核对选材、聊天、标题、模型及草稿；将一个对话重命名。
5. 完全退出应用后重新打开，确认恢复上次项目和对话。已有有效通读/知识结构应能直接恢复；没有记录或内容已变的资料仍需重新处理。
6. 生成一份讲解，回到工作台，在“本项目成果”手动勾选它并询问文件内容；无需下载重导。
7. 切到另一个项目，确认其成果列表与快选看不到前一个项目的成果。返回原项目重命名或删除成果，再核对快选同步变化。

## 实际边界与后续

- 能恢复的是本机数据库中已经保存的内容；未保存或已删除的历史无法凭空找回。故障修复没有检查用户原库的数据是否完整。
- 本机完整聊天保存与模型实际输入长度是不同问题。超长历史仍受模型上下文额度限制，不能声称每次请求都携带无限历史。
- “独立对话”不改变项目共享原文件的事实；原文件修改会使所有使用它的缓存按校验结果失效。
- 本项没有完成阅读笔记独立展示、通俗讲解标准调整、全部成果暂停与继续、自定义背景或并行调度；它们列在 [后续体验改造清单](后续体验改造清单.md)。
- 并行问卷及统一“讲解内部并行”开关要求已记录，尚未改变执行机制。后续需验证实际步骤重叠与串联顺序，不能仅以按钮变化判定完成。
- 没有重新生成安装包。当前 `dist/StudyForge-Setup-0.3.4.exe` 仍为旧包，验收本项须打开源码入口。
