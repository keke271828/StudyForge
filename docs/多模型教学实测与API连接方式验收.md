# 多模型教学实测与 API 连接方式验收

2026-10-14。针对“多测试一些模型，看看生成质量哪些最好”，完成实际服务调用和逐份正文评阅。没有把网页宣传、模型名称或自动测试通过数当教学质量排名。

## 实际测试范围

- 七个可调用的服务组合：DeepSeek V4.1 Flash、DeepSeek V4 Pro；Codex 的 GPT-6.1 Sol、GPT-6 Astra、GPT-6 Sol、GPT-6 Luna；已配置接口的 Kimi K2.6。
- 所有候选先做相同的三项初筛：柯西不等式的构造动机、事实与评价的哲学概览、高斯定律的概念纠错。Kimi 的证明题两次真实连接尝试均未取得完整正文，不能按题目失败评价其数学能力。
- GPT-6.1 Sol、GPT-6 Astra、GPT-6 Sol 与 DeepSeek Pro 再做相同两项追加题：随机鼓励是否识别行为本身的因果作用；列表原地排序、返回值与保留原列表需求。
- 同模型概览组织试验另有四次调用：Flash 与 6.1 Sol 各做原规则和缩短规则；Flash 在这组比较中都使用显式 API 直连，避免把环境代理超时当成提示词收益。
- 共 **32 份完整回答、5 条未取得完整回答的真实调用记录**。另有 **9 条测试记录器参数不兼容错误**，发生在发出模型请求前，保留记录但不计模型表现。不能把这 14 条记录统称为 14 次模型请求失败。

使用软件真实的讲解提示构造器、导师共同规则、现有模型客户端与配置凭据；同一任务的基础输入先冻结，原回答和 SHA256 保存。仅使用合成短资料和隔离数据目录，没有发送用户原聊天、个人画像或书库。真实调用会产生相应服务用量。

这些是**初次文字讲解／导师回答**，不是完整视频转录、扫描书阅读、习题独立求解、批改或 DOCX 排版的耗时测试；没有后续审查轮次。Codex 还有原生代理系统指令，Kimi 使用服务默认推理，其余用 high，不能认为计算预算和完整系统指令等价。这里比较用户实际能选的服务组合，不能据此给模型本体作严格能力排名。

## 评阅与选型结论

检查是否回应真实卡点、解释构造动机、算完例子、保留条件与来源边界、有无实质错误、重复程度以及实际等待。没有用回答长短代替质量，也没有把流畅语言当正确性证据。人工评阅未盲评，未经校准；只代表这批任务的判断，不是学生长期学习成效证据。

| 服务组合 | 本轮较突出的方面 | 实际缺点与建议 |
|---|---|---|
| GPT-6 Astra / Codex | 证明的构造、参数选择与边界说明完整；因果对象、对象引用讲得细 | 本轮复杂证明的优先候选之一。部分回答重复，等待较长，不能默认所有问题都用它 |
| GPT-6.1 Sol / Codex | 具体例子与专业推导衔接较好；追加题解释充分 | 与 Astra 都适合重点精学，本轮没有足够证据分出稳定总冠军。因果题一次约279秒，额外文字未必值得所有任务等待 |
| GPT-6 Sol / Codex | 概览、因果与简短编程纠错较紧凑，覆盖当前核心问题 | 本轮日常学习的效率候选。证明开头有一次项2B与2Bt的措辞不准，不能因为简洁就跳过核对 |
| DeepSeek V4 Pro | 证明动机、配方和通量计算可复核，独立 API 可用 | 不经 Codex 的重点讲解优先候选。因果题对有限样本不确定性的限定不够，编程输出状态标记不统一 |
| DeepSeek V4.1 Flash | 部分证明和物理纠错相当完整，连接正常时较快 | 概览冗余仍明显；缩短规则试验出现桥接原则与结论不相配。适合一般阅读，关键结论继续对照原文及审查 |
| GPT-6 Luna / Codex | 能给出较短的主线讲解 | 证明回答出现缺失行内公式闭合标记；物理回答短却等约173秒。不因名称或篇幅默认是最快方案 |
| Kimi K2.6 / 配置接口 | 两份已完成回答可读，通量算例本身正确 | 物理回答把净电荷零误写成无场源，又把强对称性误写成必要条件，本份不能原样推荐。证明未取得正文，不据此判断其数学能力 |

## 概览提示试验的处理

试验缩短规则强调一个贯穿例子、减少重复和旁支，实际发生：

- Flash：同为直连，原规则1477字符／37.46秒，试验规则1192字符／35.96秒。正文缩短约19%，却把支持相反结论、或缺少额外事实前提的原则也列作原结论的桥，教学逻辑变差。
- 6.1 Sol：原规则1634字符／71.74秒，试验规则1652字符／70.77秒，内容质量接近，没有明显篇幅或时间收益。

**撤回试验教学规则。** 已核对五类实际请求恢复后与初始冻结输入完全一致，记录在 `build/model-teaching-20261014/prompt-restore-check.json`。试验失败正文原样保留，不删除不佳样例，也不追加长提示词追着单题修补。现有精学、概览、研究和风格选择继续工作。

## API 连接线路修复

实际带认证的模型目录探测中，沿用环境代理时 DeepSeek 与 Kimi 分别在约8.50秒与6.45秒连接超时；关闭环境代理发现、仍保留 HTTPS 证书校验后，分别 HTTP200、约0.51秒与0.94秒。这只是本机当时的目录连接证据，不代表几十页讲解能在一秒生成，或整体任务已提速30%。

“设置与联动 → 模型与语音 → AI 服务 → API 连接方式”新增：

1. **沿用环境配置（默认）**：保留现有环境代理、证书等配置。
2. **直接连接（跳过环境代理）**：跳过环境代理，保留证书验证及显式 CA 文件／目录；不静默切换。

选择立即保存。DeepSeek、兼容 API 和 Gemini API 的普通／流式调用、模型目录读取使用该选择；配对手机通过同一电脑后端使用。Codex、Gemini 账号入口继续沿用各自运行环境网络。已建立连接不在任务中途改线，新连接使用当前选择。需要代理的服务可随时改回默认；没有擅自修改用户真实设置。

同时修复连接诊断结束后未关闭 DeepSeek HTTP 客户端的问题；刷新较早的设置响应不覆盖较新的线路选择，保存失败恢复原选择，重启后恢复已保存值。软件内零基础指南增加使用说明。
