# 讲解原句精准补讲与候选审查验收

2026-10-15。目标是让补讲准确对准学生不懂的具体原句，并继续核验例子是否回答了问题。此次没有更换模型、默认学习模式或审查强度，没有打包。

## 可以直接使用的改动

在电脑或手机打开一份讲解的“理解反馈／哪里没懂”，展开 **卡在哪一节或哪句话？（可选）**。

1. 选择这份讲解的实际章节。电脑尚未列出时点“列出这份讲解的章节”。
2. 点 **查看本节原句 · 可选段**。每次最多查看 4000 个 Unicode 字符，可上一段、下一段，也可指定本节的字符位置。
3. 在只读文字框中拖选或长按选中具体原句，点 **使用选中原句**，最多 3000 字符。
4. 勾选理解困难或填写自己的具体疑问。可“仅保存反馈”，也可“提交并请导师补讲”。

查看、翻段、选句和保存不调用模型，也不重新解析原文件。选句不等于报告理解困难，仍需学生表达困难。没有选句时保留原来的按章节定位方式，不强迫每次选句。

原来的定位辅助包对长章节只给开头 7000 字符，新方式将所选句子及前后各最多 700 字符用于定位。这里说的是补讲定位包；公开聊天或 Codex 路径可能仍包含整份历史讲解，不能误称模型原来完全看不到后半部分，也不能把选段等同于限制模型全部上下文。

## 定位、版本和画像

- 按当前问卷对应的交付记录读取历史 AI 讲解，不用最新的另一份成果代替它。
- 章节 ID 绑定内容指纹；选句的文本与 Unicode 起止位置逐字核对。相同句子出现多次时用位置区分，不猜其中一次。
- 内容变化、其他讲解的章节或错误坐标不能静默替代选段，返回明确提示，问卷和画像不作部分写入。
- 提交后保存固定选句与上下文。重复提交同一数据不重复记画像；后来正文变化也不重新计算已提交的选句。
- 历史 AI 原句可能有错，明确标为旧教学内容，不是原文件、学生作答或理解证据；原句正文不进入学习事件、画像洞见或公开学生消息。画像只保留学生自报及章节、字符范围、指纹。
- 补讲定位包中原句只放一次，不再同时复制一份完整选句和含同一选句的上下文。公开旧聊天本身继续保留。
- 设备草稿保留选句、困难和问题；换章节清空旧选句，保留学生问题。旧请求晚返回不能覆盖新的章节或对话。提交后才同步到电脑，未提交草稿仍只在当前设备。
- 支持 Windows CRLF 换行与 emoji／非 BMP 字符；界面的 UTF-16 选择位置转换回原保存文本的 Unicode 字符位置，不改写原文。
- 字符位置输入框按 Enter 只跳转查看，不会误提交整份理解问卷。

手机使用同一只读接口与选择控件，公开静态壳更新为 v41；学习内容和已认证接口响应不进入 service worker 缓存。安装资源自检也加入新控件文件，但这次没有制作或安装新包。

## 审查试验：两版候选均未采用

实际运行 DeepSeek Flash / high 的 12 次快速审查组件调用，工具关闭、模型并发最多 2。四份冻结讲解分别测试现有审查、全文主题与例子对齐候选、例子结论与理由配对候选。没有新生成长文或重放网页端；每格一次，未盲评。

| 样例 | 实际结果与决定 |
|---|---|
| 社会科学：问为什么迟到，却用制度解释担心迟到 | 两版仍未指出这部分示范衔接不足。原稿后面确实区分两种问题，也用孩子生病与地铁故障解释同一个迟到事件，因此不能把整篇理论说明一概定性为错误。 |
| 编程：去空格冒充忽略大小写 | 三臂都检出并修正正文和总结；现有审查已经能检出。第二候选修订又用了过强的“必须在 strip 后统一大小写”；实现顺序并非唯一，不能称为整段完全正确。 |
| 数学：形式系数反驳“单点非负足够” | 三臂均保留有效对照，没有误称它是真实向量违反柯西，也没有因对象不同而误判。 |
| 电场：收支抵消类比和匀强场立方体 | 第一候选保持原文；第二候选要求再明确写出高斯定律等式才算完成，补充本身正确，但对这个简明解释作实质缺口定性偏严。 |

不采用这两版候选，不继续累积全局教师规则或新增默认审查轮次。生产 `review.py` 与上轮验收的指纹保持相同；教师共同规则、风格与模式也没有因这次试验改写。

所有请求、公开返回和原样交付正文保存在 `build/teaching-alignment-real-20261015-1` 与 `build/teaching-alignment-pairs-real-20261015-1`。可打开的四组十二份对照为 [例子核查候选实际对照](../build/teaching-alignment-20261015/例子核查候选实际对照.html)。不包含私有思考、密钥或真实学习记录。
