# 讲解新疑问与连续核对验收

2026-10-21；本轮源码实施，未打包。

## 完成的改进

此前每份讲解只有一份理解问卷。提交或跳过后，问卷不可再次编辑，这原本是为了保留已提交证据，但也使新发现的讲解疑问只能回聊天框手动拼接资料。

现在，电脑反馈卡片和手机反馈详情提供“核对讲解新疑问”。它创建独立的内容核对记录，原问卷、以前的核对和回复保留；继续使用原讲解任务、原项目、原对话和原资料。每份讲解只有一个尚未提交的新核对草稿，重复点击或同时打开复用它；完成或跳过后可以再开下一次。

### 教学与画像边界

- 此入口只核对讲解，不把质疑或被选中的旧AI原句当作学生作答、知识薄弱或能力评分。
- 可以选原讲解章节／逐字原句，填写问题。“仅保存反馈”不请求模型；“提交并请导师回应”才发起核对。没有问题也没选位置时先提示补充，避免空调用。
- 核对时仍区分旧AI讲解与原资料；旧“核查通过”不是证据，不预设学生或旧讲解一定正确。现有补讲策略保留，未扩大成自动多轮审核。
- 内容核对不写学习画像、不扣分、不自动出题；对应界面没有理解检查题按钮，接口也拒绝将这种核对当作理解测验。原理解问卷的自报困难和主动单题检查保留原有行为。
- 同时修复原问卷六种困难加内容核对共7项选择被API上限6拒绝的问题；纯内容质疑仍不进入画像，混合选择只记录六类明确自报。

### 原范围与状态恢复

- 核对使用原对话当前模型及原讲解的教学设置，沿用既有同一导师对话流程。
- 修复旧流程重新检索当前聊天书库选择的问题：改用原生成任务保存的书库选择，仍执行书库版本／原文件检查；已知版本变化时明确拒绝，不混入后来新选的节点。此处是恢复保存的选择，不代表逐字重放当时所有模型输入，也不补认旧记录未保存的信息。
- 不改写工作台后来选择的普通资料；旧讲解另存格式后，可找到同一生成任务的现有讲解成果；全部成果或原对话正文缺失时不冒用其他文档。
- 失败可重试且复用原提问消息；重启将运行中的核对标为未完成。跨项目／对话请求、回收站项目和不匹配原句拒绝。
- 新内容核对使用新增表 `lesson_content_checks`，不重建、覆盖或改变旧问卷及其测验关联。删除原对话／原问卷时级联清理，项目彻底删除也纳入原有归属遍历。
- 手机接口只增加这个具体路由的放行，保留原有配对和设置／文件权限限制。公共应用壳更新到v60，反馈内容不进入静态缓存。
