# 作业原题版本与历史反馈验收

2026-10-26，源码更新，未重新打包。当前安装包仍为此前的0.4.4，不包含本轮修复。

## 本轮问题与修改

旧错因问卷从当前题单取题干，与历史提交中的作答组合。题干修改后可能错配；题数减少时，直接使用历史题号索引会触发IndexError，影响作业详情或列表读取。历史按题阅读原来则直接拒绝有变化的题单，即使提交时的原题内容其实已经完整保存在source_version中。

现在只读回看使用已保存的原题、参考解和难度，保留原JSON字符串，核对结构、题号和完整性，不通过新题猜补旧题。原题版本不同会同时在阅读器和工具返回中说明，题数和话题也沿用原版。缓存版本更新为4，当前题单首次发生变化时使旧内部上下文失效；公开聊天和已有成绩保留。

当前题单变更时，旧问卷、重试批改、再练和进阶按钮停用。电脑习题页不会把新版题干和旧批改并排显示，工作台作业历史和结果刷新也显示明确提示。配对手机使用同样的原题回看和限制；手机静态壳更新到v82。

原题缺失、损坏或不能核实的旧记录明确提示无法按题读取，仍保留原先已发布文档的入口。原题或原对话删除后不会借保存版本恢复读取权限。尚未完整提交的记录不能读取解析，没有交付的诊断仍不公开。只读恢复函数不参与评分或问卷写入，相关操作继续核对当前版本。

## 实际验证

- 修复前两个专门用例失败：没有版本隔离信息；题数缩短后出现IndexError。
- 最终281项关联回归全部通过，0失败、0错误、0跳过，8个生产文件指纹前后相同。
- 新增22项专门检查，包括原题数量、解析、历史评分、缓存变化、跨窗口版本、损坏保存数据、答案保护、问卷写入拒绝、编程题元数据和已删除原题。
- 5个生产前端脚本通过Node语法检查。
- 最终17组实际电脑和配对HTTPS手机操作通过，包含390/320px、深色显示、按题切换、独立草稿、旧问卷停用和损坏版本提示。实际截图已查看。
- 受控及真实云模型调用均为0；没有接触真实学习数据，没有因回看新增作答、知识评分或学习画像。

首次扩展单元测试中两项夹具不正确：把正常工具审计记录当成数据污染；模拟旧数据库缺失题单时被外键保护拦住。夹具修正后22项通过。第二轮界面脚本误等已提交题单进入“待提交”的下拉框，已改为通过真实历史入口与结果刷新验证；该轮失败记录保留，没有当作生产通过依据。

## 验收入口

先从Windows托盘完全退出旧版，再双击项目根目录的“验收最新版.vbs”，无需CMD。打开已提交作业的“按题回看”，可选原题号后回原对话继续问。若手头没有变更题单，可先看验收页中的合成案例截图。

可打开报告：`build/homework-version-acceptance-20261026/作业原题版本与历史反馈验收.html`。

验证凭据：

- 最终回归与生产指纹：`build/homework-version-final-20261026/command.json`
- 两端操作：`build/homework-version-ui-20261026-3/ui-report.json`
- 前端语法：`build/homework-version-ui-20261026-3/syntax-check.json`
- 汇总：`build/homework-version-acceptance-20261026/result.json`

复跑脚本：`scripts/verify_homework_versions.py`、`scripts/run_homework_versions_ui.py`和`scripts/report_homework_versions.py`。UI复跑必须使用新的build直接子目录名，避免覆盖旧凭据；最终回归目录也需改为新目录。

## 验收范围

这次主要保证历史回看和题单版本对应，不是模型整体教学能力评测，也没有认证实体安卓触控或全软件速度、内存。验证内容为合成题目与人工指定的既有评分。运行到一半时外部修改题单的全部并发时序未全面覆盖；不据本次结果宣称整个评分流程完全无误。
